# 模块 11 — 堵转协议通路（0x5A/0x5B/0x5C/0x7C/0x1B — 不实现检测算法）

> **范围**：主控侧堵转通信协议 + 通路保留，但**不实现**实际检测算法
> **关联文件**：
> - `UserApp/protocols/can_protocol.cpp` (回包处理：0x5A/0x5C/0x7C)
> - `Robot/instances/dummy_robot.h/cpp` (历史含 `SetStallMode/BroadcastUnlock/QueryStallStatus`)
> - `UserApp/protocols/ascii_protocol.cpp` (历史含 `!STALL_*`)
> - `Robot/actuators/ctrl_step/ctrl_step.hpp/cpp` (历史含 STALL 类状态)

## 模块概述

**重要决策背景**：电机固件 stall v3 已删除（`!STALL_*` 入口、0x5A/0x5B/0x5C/0x7C 主控侧处理、`isStalled` 字段已全部清除），参见 [`firmware_new主控固件修复—阻塞回OK与OLED同步—2026-09-24.md §七`](./firmware_new主控固件修复—阻塞回OK与OLED同步—2026-09-24.md) 的 stall v3 删除记录。

**当前保留的堵转相关通路**（仅最小集）：

| 通路 | 状态 | 用途 |
|---|---|---|
| `CAN 0x1B SetEnableStallProtect` | **保留** | 电机端独立开关堵转保护；OLD 也有此命令（`ctrl_step.hpp:52`） |
| `CAN 0x5A/0x5B/0x5C/0x7C` 主控处理 | **已删除**（§七） | — |
| `!STALL_*` ASCII 命令 | **已删除** | — |
| `isStalled` 字段 + `IsStalled()` 方法 | **已删除** | — |
| `PollStallStatus`/`[STALL]` OLED 探针 | **已删除** | — |

**通过保留 0x1B 的 `SetEnableStallProtect`**，电机端可在不修改主控的情况下独立启用/禁用堵转检测。电机端做了 stall 检测后由电机端决定后续行为（抱闸/上报/重启），主控不参与。

## 决策

| # | 决策 | 理由 | 风险 |
|---|---|---|---|
| 1 | **不实现 stall v3 检测算法**（决策 §0.1 #1） | 沿用电机固件决策：电机端无 LOCKED/RETREATING 状态机 | 无 |
| 2 | **保留 `SetEnableStallProtect`**（决策 §0.1 #5） | 是独立的"开关堵转保护"命令，与检测算法无关 | 无 |
| 3 | **主控侧 0x5A/0x5B/0x5C/0x7C 处理已删除** | 决策 §0.1 #1 不实现算法→主控不识别这些命令 | 电机端启用堵转后主控无响应（符合预期） |
| 4 | **`!STALL_*` 命令已删除**（决策 §0.2 §七） | 主控侧无接口 | 与 §七 stall v3 删除记录一致 |
| 5 | **`isStalled`/`IsStalled()` 已删除** | 不实现字段 | 运动指令入口不再有 IsStalled 拦截 |
