## 阶段 0：准备

**目标**：确认 `firmware_old/` 基线可用，建立新工程目录。

**大致步骤**：

1. 确认 `firmware_old/dummy-35motor-fw/`、`dummy-42motor-fw/`、`dummy-ref-core-fw/` 均能 `ninja` 编译通过。
2. 把 `firmware_old/` 复制一份作为新基线。
3. 验证烧录工具链（stlink / openocd / 串口助手）。

**达成**：每个工程能独立编译，烧录到对应硬件能跑通基础 Enable / Disable / SetPosition。

---

## 阶段 1：地基（build 系统 + CAN ID + 单位）

**目标**：先把所有"数据"层迁移到位（无算法改动），后续阶段在此基础上叠加。

**大致步骤**：

1. **建立单一电机 build 系统**（`motor_fw_f103/`）：一套源码，通过 `MOTOR_TYPE` 宏区分 35 / 42 / 57 / gripper，CMake 生成 **4 套产物**（每个 ELF + 同名 .hex + 同名 .bin，共 12 个文件）。`configurations.h` **按 `MOTOR_TYPE` 切出 4 套独立的默认参数块**（即使数值相同也分开定义）。
2. 主控侧扩展 `motorJ[]` 为 8-slot，加 `motorJ[7]`（地轨）和 `hand`（夹爪）。
3. 电机侧硬编码 CAN ID：在 `configurations.h` 内根据 `MOTOR_TYPE` 设置 `RAIL_FIXED_NODE_ID=7`（57）或 `GRIPPER_FIXED_NODE_ID=8`（gripper），35 / 42 仍由拨码开关决定 1~6。
4. 主控侧单位统一：定义 `RAIL_STEPS_PER_MM` / `SLIDER_TO_RPS` / `AXIS_MAX_RPS[8]` / `MOTOR_REDUCTION[8]` 等常量。
5. **57 算法与 35/42/gripper 完全一致**：直接复制 35 的 `motion_planner.cpp/h`、`motor.cpp`（仅 `RAIL_FIXED_NODE_ID` 不同），**不要复制 `CalcSoftGoalWithRealPos` 这个反闭环函数**。PID 通过 `MOTOR_TYPE_57` 默认块覆盖。
6. 主控与电机联调：上电后 `#GETJPOS` 能返回 7 值（含地轨 mm）。

**达成**：

- 一套 `motor_fw_f103/` 源码可编译出 **4 套产物**（每个 ELF + 同名 .hex + 同名 .bin，共 12 个文件）。
- 主控 `motorJ[0..7] + hand` 9 个节点表完整。
- 速度 / 加速度接口单位统一为 r/s、r/s²。
- 电流限幅按型号分档（35/42/gripper = 2.0A、57 = 2.5A，详见重构需求 §1.1.1）。
- 地轨 CAN ID = 7、夹爪 CAN ID = 8（CAN 抓包验证）。

---

## 阶段 2：电机固件扩展（CAN cmd + 参数查询 / 设置）

**目标**：在阶段 1 的基础上，给电机固件加上参数远程读写能力。

**大致步骤**：

1. 电机固件 `interface_can.cpp` 实现 CAN 写入类 cmd（带 EEPROM 持久化）：电流限幅、加速度、DCE PID。
2. 实现 CAN 查询类 cmd：返回加速度、电流限幅、PID。
3. 主控侧 `#ACC_J` / `#SPEED_J` / `#I_LIMIT_J` / `#GETJACC` / `#GETI` / `#SET_PID` / `#GET_PID` 接入 CAN 收发。
4. 联调：主控读 → 改 → 读回 → 验证。

**达成**：

- 通过主控能远程查询 / 设置任意电机的加速度、电流、PID。
- 写入后重启电机仍保持（验证 EEPROM 持久化）。
- 查询响应格式稳定，串口助手能解析。

---

## 阶段 3：协议层（ASCII + CAN 回包）

**目标**：把 ASCII 命令集扩展为完整指令集。

**大致步骤**：

1. ASCII 基础命令：`!START` / `!DISABLE` / `!HOME` / `!RESET` / `!STOP`。
2. **EmergencyStop 修复**：`!STOP` 发 CAN `0x09 BroadcastEStop`（不是旧版错误的 0x89）。
3. 夹爪命令：`!HAND_*`。
4. 编码器归零：`#OFFSET_J`（替代 `!CALIBRATION`，顺带删除 `!CALIBRATION`）。
5. 调参命令（依赖阶段 2）。
6. RGB 命令（依赖阶段 5 的 RGB 实现）。
7. 主控 CAN 回包路由扩展，匹配电机新增 cmd。

**达成**：

- 串口助手能完整解析所有 ASCII 响应。
- `!STOP` 在电机运行中能立刻停转 + 抱闸。

---

## 阶段 4：控制算法（MoveJ / MoveL / 7 轴 / SERVO / TORQUE / TUNING）

**目标**：实现 6 种 CommandMode 的完整控制算法。

**大致步骤**：

1. MoveJ 阻塞（`>`）+ 非阻塞（`&`），入参 8 字段（含地轨 mm）。
2. 7 轴同步抵达（`ComputeSyncSpeeds`）—— 让 MoveJ 各轴同时抵达。
3. **MoveL（`@`）加入地轨算法**（具体策略实施时由 agent 再设计）。
4. SERVO_J（5kHz 实时环随动）。
5. TORQUE_CONTROL（`$` 透传 7 通道电流）。
6. TUNING（扫频正弦）。
7. 5kHz 实时环（TIM7 + ControlLoopFixUpdateTask）。

**达成**：

- 6 种 CommandMode 都能跑通。
- 5kHz 中断抖动 < 5%（示波器测）。
- MoveJ 7 轴同时抵达（finish 时间差 < 5ms）。
- SERVO_J 能透传 1kHz+ 位置流。
- MoveL 在含地轨的目标下能正确插补。

---

## 阶段 5：辅助功能（RGB / 夹爪 / !BACKHOME）

**目标**：把独立子系统都迁移到位。

**大致步骤**：

1. RGB 10 灯效 + 静态色 + 亮度查询 / 设置 / 持久化 + 渐变 + DMA。
2. **`!BACKHOME` 统一回位**：先 `!HAND_C` 再 `!HOME`，**借鉴堵转检测的状态机思路**处理异常（机械臂卡阻时回退 → 锁定 → 解锁）。
3. Homing / Resting 30s 超时兜底。

**达成**：

- RGB 10 种模式都能正确显示，亮度调节无闪烁。
- 地轨受外力偏位后能自动追回。
- `!BACKHOME` 一键完成"夹爪闭合 + 机械臂归位"，卡阻时能优雅处理。

---

## 阶段 6：联调与验收

**目标**：8 节点全联调通过，性能 + 边界测试达标。

**大致步骤**：

1. 8 节点全连接：主控 + 6 关节 + 地轨 + 夹爪。
2. 串口助手全命令回归测试。
3. 性能测试：5kHz 实时环抖动、SERVO_J 透传延迟、MoveJ 同步抵达时间差、MoveL 含地轨的插补精度。
4. 边界测试：电机掉线恢复、CAN 总线错误、EStop 响应时间、`!BACKHOME` 在异常下的行为。
5. 长时间运行稳定性测试（≥ 1 小时）。
6. 与 `firmware/` 旧版本功能对照测试，确保所有新功能可用。

**达成**：

- 8 节点同时在线 1 小时无崩溃。
- 所有 ASCII 命令响应符合 [`对比清单`](./新功能清单—firmware与firmware_old对比—2026-09-18.md) 中的预期。
- EStop 响应时间 < 50ms。
