## 阶段 0 — 信号量泄漏修复（独立，最先）

### 问题描述

`CanSendMessage` 在 `HAL_CAN_AddTxMessage` 返回 `HAL_ERROR`（mailbox 满）时不释放信号量，导致永久泄漏。`!START` 时 8 次循环，每次可能泄漏一个信号量，最终死锁。

### 改动文件

`firmware/ref_core_f405/Bsp/communication/interface_can.cpp`

### 改动内容

**当前代码**（有信号量泄漏风险）：

```cpp
void CanSendMessage(CAN_context* canCtx, uint8_t* txData, CAN_TxHeaderTypeDef* txHeader)
{
    osStatus semaphore_status;
    if (canCtx->handle->Instance == CAN1)
        semaphore_status = osSemaphoreAcquire(sem_can1_tx, osWaitForever);
    else if (canCtx->handle->Instance == CAN2)
        semaphore_status = osSemaphoreAcquire(sem_can2_tx, osWaitForever);
    else
        return;

    if (semaphore_status == osOK)
        HAL_CAN_AddTxMessage(canCtx->handle, txHeader, txData, &canCtx->last_heartbeat_mailbox);
}
```

**改动后**（加失败释放 + 10ms 超时）：

```cpp
void CanSendMessage(CAN_context* canCtx, uint8_t* txData, CAN_TxHeaderTypeDef* txHeader)
{
    osStatus semaphore_status;
    // 加固：10ms 超时替代 osWaitForever，避免永久阻塞
    if (canCtx->handle->Instance == CAN1)
        semaphore_status = osSemaphoreAcquire(sem_can1_tx, 10);
    else if (canCtx->handle->Instance == CAN2)
        semaphore_status = osSemaphoreAcquire(sem_can2_tx, 10);
    else
        return;

    if (semaphore_status == osOK) {
        HAL_StatusTypeDef ret = HAL_CAN_AddTxMessage(
            canCtx->handle, txHeader, txData, &canCtx->last_heartbeat_mailbox);
        // 加固：发送失败时释放信号量，防止泄漏导致死锁
        if (ret != HAL_OK) {
            if (canCtx->handle->Instance == CAN1)
                osSemaphoreRelease(sem_can1_tx);
            else if (canCtx->handle->Instance == CAN2)
                osSemaphoreRelease(sem_can2_tx);
        }
    }
    // semaphore_status != osOK（超时）时放弃本次发送，下一循环重试
}
```

### 验证

- 编译：`ninja`（主控固件），0 errors
- 功能：反复 `!START`/`!DISABLE` 不再死锁

## 阶段 1 — 电机端 Rx 路由恢复 `id==0` 特判

### 问题描述

当前电机端 Rx 路由：
- `cmd >= 0x50 && cmd != 0x5C` → 广播
- `id == nodeID` → 单播

**问题**：`id=0` 帧（ALL 代理）落入 `else if (id == nodeID)` 分支，但 `id=0 != nodeID(1~9)`，所以 **0 个电机响应**。

### 改动文件（3个电机固件同构）

- `firmware/motor_fw_f103_35/Core/Src/can.c`
- `firmware/motor_fw_f103_42/Core/Src/can.c`
- `firmware/motor_fw_f103_57/Core/Src/can.c`

> 夹爪固件 `motor_fw_f103_gripper` 不参与 ALL 代理，不需要改。

### 改动内容

**当前代码**（`can.c` 中的 `HAL_CAN_RxFifo0MsgPendingCallback`）：

```c
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef* CanHandle)
{
    if (HAL_CAN_GetRxMessage(CanHandle, CAN_RX_FIFO0, &RxHeader, RxData) != HAL_OK)
    {
        Error_Handler();
    }

    uint8_t id  = (RxHeader.StdId >> 7);
    uint8_t cmd = (RxHeader.StdId & 0x7F);

    // ── 广播命令 (cmd 0x50~0x7F): 所有节点无条件响应 ──
    if (cmd >= 0x50 && cmd != 0x5C) {
        OnCanCmd(cmd, RxData, RxHeader.DLC);
    }
    // ── 普通命令 / 0x5C 单播: 仅目标节点响应 ──
    else if (id == boardConfig.canNodeId) {
        OnCanCmd(cmd, RxData, RxHeader.DLC);
    }
}
```

**改动后**（恢复 `id==0` 特判）：

```c
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef* CanHandle)
{
    if (HAL_CAN_GetRxMessage(CanHandle, CAN_RX_FIFO0, &RxHeader, RxData) != HAL_OK)
    {
        Error_Handler();
    }

    uint8_t id  = (RxHeader.StdId >> 7);   // 7Bits ID (0~127)
    uint8_t cmd = (RxHeader.StdId & 0x7F); // 7Bits CMD

    // [v3.1 修复] 恢复 id==0 特判，支持 ALL 代理广播
    // id==0: 任何 cmd 群发（广播代理），但排除 0x5C（单播查询）
    if (id == 0 && cmd != 0x5C) {
        OnCanCmd(cmd, RxData, RxHeader.DLC);
    }
    // 单播：仅目标节点响应（任何 cmd，含 0x5C）
    else if (id == boardConfig.canNodeId) {
        OnCanCmd(cmd, RxData, RxHeader.DLC);
    }
    // id 非 0 非本节点ID：静默忽略（防误触）
}
```

**改动要点**：
1. 交换判断顺序：`id==0` 特判优先于 `id==nodeID`
2. **保留** `cmd != 0x5C` 排除（0x5C 必须走单播路径，否则所有电机同时回包造成总线冲突）
3. 删除旧的 `cmd >= 0x50` 广播分支（`id==0` 已覆盖所有广播命令）
4. 新单播分支覆盖**任何 cmd**（含 0x50~0x7F 区间），与旧分支功能等价

### 验证

- 编译：3 个电机固件各 `ninja`，0 errors
- 功能：`motorJ[ALL]->SetEnable(true)` 发 `StdId=0x01`，所有电机响应

## 阶段 2 — 电机端 `case 0x09` 急停

### 问题描述

主控 `BroadcastEStop()` 当前发 `StdId=0x89`，电机端 decode 后 `id=1/cmd=0x09`，电机端无 `case 0x09` 处理（只有 `case 0x89` 死代码），**0 个电机响应急停**。

### 改动文件（3个电机固件同构）

- `firmware/motor_fw_f103_35/UserApp/protocols/interface_can.cpp`
- `firmware/motor_fw_f103_42/UserApp/protocols/interface_can.cpp`
- `firmware/motor_fw_f103_57/UserApp/protocols/interface_can.cpp`

### 改动内容

**当前代码**（`interface_can.cpp` 中的 `OnCanCmd` 函数）：

```cpp
case 0x89:  // Broadcast Emergency Stop
{
    extern Motor motor;
    motor.controller->requestMode = Motor::MODE_STOP;
    motor.controller->SetBrake(true);  // P0-5: brake instead of coast
    motor.controller->SetVelocitySetPoint(0);
    motor.controller->SetCurrentSetPoint(0);
    printf("[CAN BROADCAST] Emergency Stop Received!\r\n");
}
    break;
```

**改动后**（替换 `case 0x89` 为 `case 0x09`）：

```cpp
case 0x09:  // [v3.1 新增] ALL 代理广播急停（主控 motorJ[ALL] 发 StdId=0x09）
{
    extern Motor motor;
    motor.controller->requestMode = Motor::MODE_STOP;
    motor.controller->SetBrake(true);
    motor.controller->SetVelocitySetPoint(0);
    motor.controller->SetCurrentSetPoint(0);
    // 急停不清 stallMode，保持 LOCKED 状态
    printf("[CAN BROADCAST] E-Stop (ALL)\r\n");
}
    break;
```

> **删除旧的 `case 0x89`**：电机端 switch 的 `cmd` 是解码后的值（0~127），不可能是 0x89（0x89 解码后 = id=1/cmd=0x09），旧的 `case 0x89` 是死代码，必须删除。

### 验证

- 编译：3 个电机固件各 `ninja`，0 errors
- 功能：发 `StdId=0x09`，电机全部进入 `MODE_STOP` + 抱闸

**当前代码**：

```cpp
{
```

**改动后**：

```cpp
void CtrlStepMotor::BroadcastEStop()
{
    // [v3.1] 走 ALL 代理：StdId = (nodeID<<7) | 0x09
    //   motorJ[ALL] 调用时 nodeID=0 → StdId=0x09
    //   电机端阶段2新增 case 0x09 → 硬急停
    txHeader.StdId = (nodeID << 7) | 0x09;
    uint8_t buf[8] = {0};
```

```cpp
{
```
