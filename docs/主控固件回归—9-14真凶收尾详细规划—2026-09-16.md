## 二、F1 P0 — `CtrlStepMotor::SetEnable(true)` 不再同步 `state=FINISH`

### 2.1 问题（大白话）

`!START` 后电机还没回包，主控侧已经把所有电机 `state` 强行设为 `FINISH`。配合 A1 修复（FINISH→|= 置位），`jointsStateFlag` 立刻全 1，`IsMoving()` 立刻返回 false → **误判"已到位"**。

### 2.2 当前代码（`ctrl_step.cpp:24-26`）

```cpp
void CtrlStepMotor::SetEnable(bool _enable)
{
    state = _enable ? FINISH : STOP;  // ⚠️ enable 时不该同步 FINISH
    // ...
}
```

### 2.3 Bug 路径

1. `!START` → `SetEnable(true)` 串行调用 2 次（`motorJ[ALL]` + `hand`）
2. 8 个电机节点（ALL 代理触发）+ 1 个夹爪，每个 `state` 立刻被同步为 `FINISH`
3. 第一次 `UpdateJointAnglesCallback`（电机还没回包）：
   ```cpp
   if (motorJ[i]->state == CtrlStepMotor::FINISH)
       jointsStateFlag |= (1 << i);  // 立刻全置位
   ```
4. `IsMoving()` 返回 false
5. **后果**：`!START` 后立刻认为"已到位"，但实际电机还在初始定位中，下一次运动指令可能直接覆盖当前正在做的归零动作

### 2.4 解决方案

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 方案 α | enable 时不再同步 `state`（保持原值）| 简单，1 行修改 | 上电首次 `state` 是默认值（未定义行为）|
| 方案 β | enable 时 `state = STOP`（保守起见）| 行为明确 | enable 后第一帧 `UpdateAngleCallback` 必须来纠正，否则 `IsMoving` 一直 true |
| 方案 γ | 沿用 disable 同步 `STOP`，enable 不动；首次 0x23 回包自动纠正 | 与电机端实际语义一致 | 依赖 0x23 回包可靠 |

**推荐方案 γ**（与 9-14 §11.1 #5 一致）：disable 时同步 `STOP`，enable 时不动，由电机端首次 0x23 回包纠正。

```cpp
void CtrlStepMotor::SetEnable(bool _enable)
{
    if (!_enable) state = STOP;   // ✅ disable 同步 STOP
    // ❌ enable 不再同步 state（删除原 state = FINISH 行）
    // 等待电机端首次 0x23 回包自动纠正

    uint8_t mode = 0x01;
    // ... (其余不变)
}
```

### 2.5 风险与缓解

| 风险 | 缓解 |
|---|---|
| enable 后第一帧 `UpdateAngleCallback` 之前 `state` 是上电默认值（可能是 STOP/RUNNING/FINISH 任意）| 启动豁免：主控 `SetEnable(true)` 后**先发**一帧 `UpdateAngle()`（即 `motorJ[ALL]->UpdateAngle()`），等回包到再返回 `ok` |
| 与 A1 修复方向配套 | A1 已要求 `FINISH→\|=`，新逻辑完全兼容 |

**建议**：F1 修改 + 在 `SetEnable(true)` 末尾**先调一次** `motorJ[ALL]->UpdateAngle()` 触发 0x23 回包（确保 jointsStateFlag 不被错填）。

### 2.6 改动范围

- `firmware/ref_core_f405/Robot/actuators/ctrl_step/ctrl_step.cpp:25`（1 行删除）
- `firmware/ref_core_f405/Robot/instances/dummy_robot.cpp:621-624`（`SetEnable(true)` 末尾补一帧 `UpdateAngle`）

## 三、F2 P1 — `SetStallMode()` 移除 `ClearFifo()` + ParseCommand 入口判 `isStalled`

### 3.1 问题（大白话）

堵转期间发了 8 个运动指令，`SetStallMode()` 直接 `ClearFifo()` 把所有指令（包括控制指令 `!START`/`!DISABLE`/`!STOP`）全部清空。用户按了"重启"按钮，串口助手显示"发送失败"——因为 `!START` 被堵转逻辑吃掉了。

### 3.2 当前代码（`dummy_robot.cpp:521-547`）

```cpp
void DummyRobot::SetStallMode(int motorIndex)
{
    SetRGBMode(RGB::RED_HEARTBEAT);
    isStalled = true;
    targetJoints = currentJoints;
    for (int j = 1; j <= 6; j++) {
        motorJ[j]->targetAngle = currentJoints.a[j - 1] - initPose.a[j - 1];
    }
    targetRailPos = currentRailPos;
    commandHandler.ClearFifo();  // ⚠️ 粗暴清空（应改为 ParseCommand 入口判 isStalled）
    (void)motorIndex;
}
```

### 3.3 解决方案（与 9-14 §11.2 #6 一致）

#### 步骤 1：删除 `ClearFifo()` 调用

```cpp
void DummyRobot::SetStallMode(int motorIndex)
{
    SetRGBMode(RGB::RED_HEARTBEAT);
    isStalled = true;
    targetJoints = currentJoints;
    for (int j = 1; j <= 6; j++) {
        motorJ[j]->targetAngle = currentJoints.a[j - 1] - initPose.a[j - 1];
    }
    targetRailPos = currentRailPos;
    // ❌ 删除：commandHandler.ClearFifo();
    (void)motorIndex;
}
```

#### 步骤 2：ParseCommand 入口判 `isStalled` 精确丢弃

```cpp
void DummyRobot::CommandHandler::ParseCommand(const char* _cmd)
{
    // [F2 修复] 堵转期间精确丢弃：运动指令丢，控制指令放行
    if (context->isStalled) {
        // 运动指令（>, &, @）→ 丢弃，返回 ok
        if (_cmd[0] == '>' || _cmd[0] == '&' || _cmd[0] == '@') {
            Respond("ok");
            return;
        }
        // 控制指令（!START / !DISABLE / !STOP）和查询指令（#GETJPOS 等）→ 放行
    }

    // ... (原有解析逻辑)
}
```

### 3.4 指令分级总表

| 指令类型 | 示例 | 堵转期间行为 |
|---------|------|------------|
| **运动指令**（丢弃）| `>...`、`&...`、`@...` | 返回 `ok`，不入队 |
| **控制指令**（放行）| `!START`、`!DISABLE`、`!STOP` | 正常执行（解除堵转 / 急停）|
| **其他指令**（放行）| `!HAND_*`、`!RGB_*`、`#GETJPOS` 等 | 正常执行 |

## 五、F4 P1 — ISR `printf` 0x5A/0x5C 改事件标志 + 主线程 poll

### 5.1 问题（大白话）

CAN RX ISR（优先级 5）里直接调 `printf`，会进入 UART 临界区锁。如果 UART DMA 正在发送，`printf` 会 spin-wait 等待 DMA 完成。**轻微影响 ISR 执行时间**（不是死锁，但每帧堵转广播都触发）。

### 5.2 当前代码（`can_protocol.cpp` 多处）

```cpp
case 0x5A: {
    if (stallCmd == 1) {
        dummy.SetStallMode((int)stallNodeId);
        printf("[STALL] node=%d TRIGGER\r\n", stallNodeId);  // ⚠️ ISR printf
    } else if (stallCmd == 2) {
        dummy.SetStallMode((int)stallNodeId);
        printf("[STALL] node=%d done\r\n", stallNodeId);
    }
    // ...
}
case 0x5C: {
    if (qtype == 1) {
        printf("[STALL_STATUS] node=%d en=%d\r\n", id, qval);  // ⚠️ ISR printf
    }
    // ...
}
```

### 5.3 解决方案

#### 步骤 1：定义事件标志（`can_protocol.cpp` 顶部）

```cpp
// ── 堵转事件标志（修复 F4）──
// 触发时设 1，主线程 poll 后清 0 + printf
static volatile uint8_t _stall_event_flag = 0;
static volatile uint8_t _stall_event_node = 0;
static volatile uint8_t _stall_event_cmd = 0;  // 1=TRIGGER / 2=DONE / 3=TIMEOUT
static volatile uint8_t _stall_status_flag = 0;
static volatile uint8_t _stall_status_node = 0;
static volatile uint8_t _stall_status_type = 0;  // 1=en / 2=lock
static volatile uint8_t _stall_status_val = 0;
```

#### 步骤 2：ISR 内只设标志，不 printf

```cpp
case 0x5A: {
    uint8_t stallNodeId = data[0];
    uint8_t stallCmd = data[1];
    if (stallCmd >= 1 && stallCmd <= 3) {
        dummy.SetStallMode((int)stallNodeId);
        _stall_event_flag = 1;
        _stall_event_node = stallNodeId;
        _stall_event_cmd = stallCmd;
    }
    // state==4 (HEARTBEAT): RETREATING 期间心跳，忽略
    break;
}
case 0x5C: {
    _stall_status_flag = 1;
    _stall_status_node = id;
    _stall_status_type = data[0];
    _stall_status_val = data[1];
    break;
}
```

#### 步骤 3：主线程 poll（OledTask 或 ControlLoopUpdateTask）

在 `ThreadOledUpdate` 末尾或 `ThreadControlLoopUpdate` 入口加：

```cpp
// [F4 修复] 堵转事件 poll（避免 ISR 内 printf）
if (_stall_event_flag) {
    uint8_t node = _stall_event_node;
    uint8_t cmd = _stall_event_cmd;
    _stall_event_flag = 0;
    const char* cmd_str = (cmd == 1) ? "TRIGGER" : (cmd == 2) ? "done" : "timeout";
    printf("[STALL] node=%d %s\r\n", node, cmd_str);
}
if (_stall_status_flag) {
    uint8_t node = _stall_status_node;
    uint8_t type = _stall_status_type;
    uint8_t val = _stall_status_val;
    _stall_status_flag = 0;
    const char* type_str = (type == 1) ? "en" : "lock";
    printf("[STALL_STATUS] node=%d %s=%d\r\n", node, type_str, val);
}
```

### 5.4 风险与缓解

| 风险 | 缓解 |
|---|---|
| 主线程 poll 期间 ISR 又设标志 → 标志丢失 | `volatile` + 单字节读写在 ARM Cortex-M4 上原子，主线程读完清 0 后下一帧 ISR 重新设 |
| 多电机同时堵转 → 标志被覆盖 | 现阶段接受（一次只显示最新事件），后续可改环形缓冲 |
| 0x7C 旧堵转上报不需要 printf | 维持现状（无 printf）|

- `can_protocol.cpp` 6 处 `printf` 替换为标志设置（~20 行）

## 五.5、F4 扩展 P1 — 0x28~0x2B PID 合并 printf 改事件标志（2026-09-16 选项1）

### 五.5.1 问题（大白话）

`can_protocol.cpp` 内 0x28~0x2B（PID 参数查询响应）原本用 4 包合并 + 1 次 printf 保护，但本质仍是"ISR 内 printf"，与 F4 修复原则冲突。`#GET_PID` 调试命令不频繁但仍有隐患。

### 五.5.2 改动（与 F4 完全一致的设计）

**`can_protocol.cpp` 顶部新增**（line 82-83）：
```cpp
static volatile uint8_t _pid_print_pending[9] = {0};      // 合并完成待打印标志
static volatile uint8_t _pid_pending_node[9] = {0};      // 触发合并的节点 ID
```

**`can_protocol.cpp` 新增 PollPidPrint 函数**（line 96-109）：
```cpp
extern "C" void PollPidPrint() {
    for (int idx = 1; idx <= 8; idx++) {
        if (_pid_print_pending[idx]) {
            _pid_print_pending[idx] = 0;  // 先清，再读（原子单字节写）
            printf("ok PID %d kp=%ld kv=%ld ki=%ld kd=%ld\r\n",
                   _pid_node_to_disp(_pid_pending_node[idx]),
                   (long)_pid_tmp_kp[idx], (long)_pid_tmp_kv[idx],
                   (long)_pid_tmp_ki[idx], (long)_pid_tmp_kd[idx]);
        }
    }
}
```

**`can_protocol.cpp` 12 处 ISR 内替换**（三分支 × 4 cmd）：
- J7/地轨（id==7）0x28/0x29/0x2A/0x2B
- J1~J6（id 1~6）0x28/0x29/0x2A/0x2B
- 夹爪（id==8）0x28/0x29/0x2A/0x2B

每处替换为：
```cpp
_pid_print_pending[idx] = 1;
_pid_pending_node[idx] = id;
_pid_rcv_cnt[idx] = 0;
```

**`main.cpp` 顶部新增声明**（line 15-16）：
```cpp
/* ======================================================================
 * [PID 修复] PID 合并打印 poll（由 OledTask 调用，定义见 can_protocol.cpp）
 * ====================================================================== */
extern "C" void PollPidPrint();
```

**`main.cpp` OledTask 内 F4 poll 末尾追加**（line 254）：
```cpp
PollPidPrint();
```

### 五.5.3 风险与缓解

| 风险 | 缓解 |
|---|---|
| 主线程读 tmp 期间 ISR 又写一轮 | 主线程**先清 pending 再读 tmp**（原子单字节写）；最坏丢 1 轮合并，`#GET_PID` 调试命令可接受 |
| 9 slot 遍历开销 | 9 次单字节读 + 9 次比较 ≈ 30 条指令，远小于一次 printf 的 µs 级开销 |
