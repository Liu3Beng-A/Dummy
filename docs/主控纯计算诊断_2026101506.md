## 当前交付范围

这是实测准备文档中的B层：真实FK/IK、TCP变换、限位选解和有界组件工作量。不是完整F/G缓存控制器，不接入连续手柄/滑块运动，不恢复PC逆解。周期20ms是采样目标，尚未记录/验收调度抖动，不能证明完整控制周期实时性。

纯计算核心`Robot/instances/cartesian_benchmark.h/.cpp`没有设备、CAN、Flash、RTOS接口，独立solver和三组冻结数值姿态；不读取真实关节、不修改目标、不调用运动执行器。适配器在`native_cartesian_robot.cpp`，USB提交任务后立即返回；`UserApp/main.cpp`复用8KB普通优先级command任务执行，空闲队列等待改为最多20ms，不把计算放进1kHz泵，不新增任务栈。固定128条结果，样本结构28B，结果区3584B；没有移植20,800B双轨迹缓存。

启动须原子确认idle DISABLED、无startPending、运动/原生owner/流/规划/排队/校准/参数/RGB保存。运行中ASCII写入与运动命令拒绝，查询白名单、STOP/DISABLE和诊断取消保留；START在机器人公共入口也被拦，标定入口通过独立短lease与诊断预约互斥，临界区不包围标定打印。若环境/epoch改变，工作边界中止。后台失能位置查询及外部流诊断仍可能发查询CAN，不能称整板零CAN；本诊断自身没有电机输出。

## 诊断协议v1

仅USB接受`#CBENCH`命令。每个请求仍使用现有ASCII `end`结尾，版本查询有其独立异步结束标记。

```
#CBENCH
#CBENCH RUN op,fixture,work,samples,budget_us
#CBENCH CANCEL
#CBENCH READ offset,count
```

|op|一次work实际内容|
|---:|---|
|0|FK＋结果摘要|
|1|对预先FK所得法兰位姿做IK＋解计数/摘要|
|2|FK→IK＋解计数/摘要|
|3|FK→TCP工具合成/逆变换→IK→限位等价角/最近分支→选中解FK残差|
|4|同3，每work一个地轨候选，Y方向−2/−1/0/+1/+2mm循环；不是完整七轴回收算法|
|5|不可达位姿IK，failed计数是预期无解，非固件故障|

fixture=0..2，分别为数值关节角`{0,-30,80,20,35,0}`、`{35,-20,100,-40,50,20}`、`{-40,10,65,35,-45,-20}`。这些仅是计算输入，禁止解释为实机安全运动目标。DH与当前生产一致，工具固定+Z114mm，不使用用户RAM工具草稿。先保存`#KIN_CONFIG/#TOOL`供解释，不据此误认为本诊断工具可变。

work=1..192；samples=1..128；budget_us=100..20000；READ每次1..8条且不越已完成样本范围。准备FK不含在样本里，`setup_cycles`单列；首次样本保留但不是完全冷启动，因为初始化已做FK。

状态为IDLE/PENDING/RUNNING/DONE/CANCELLED/ABORTED/BUDGET/CLOCK_ERROR。无解/无合法分支计入failed，仍可完成组件任务；DONE不代表规划通过、全部求解成功或运动可行。达到预算则终止本job，已完成work与原始周期保留。预算只能在work前后检查，最坏可能超一个work，不能声称硬抢占截止。

原始结果紧凑输出，避免现Respond 64B缓冲区（needed必须小于62）的限制：

```
CBENCH DATA id,i,cycles,ticks,work,flag
CBENCH RESULT id,i,fk,ik,valid,selected,failed,checksum
```

flag=0完成、1预算、2取消、3环境/参数中止；fk/ik是外部调用数，不含IK内部残差验证。valid累计几何有效分支；selected是成功限位选解并通过FK验证的work数。checksum用于保留实际计算输出。计时包含守护/分支计数/摘要开销，不是裸IK独占CPU时间。

## 计时方式与局限

使用局部DWT单源计数，不清零共享CYCCNT、不替换全局micros，保存原始cycles、SystemCoreClock、DWT CTRL/DEMCR。开始先检查计数递增，再用约20ms延时与HAL独立时基比较尺度，保存probe_cycles/probe_ticks；它是初筛，不是时钟计量校准。

中断保持开启，测得的是包含抢占的墙钟周期；打印、读取结果及准备计算在样本之外。20ms独立采样间隔也不计入组件耗时。预算算式使用64位；每work检查取消、epoch、环境与独立毫秒超时，job总时限10s。不得在采样期间ST-Link停机/单步或并行发送其他诊断来解释正常耗时。

新增测试使用合成DWT/RTOS，只证明逻辑。当前没有任何真实F405耗时/栈水位，不能从现有结果说主控算不完或已经20ms通过。
