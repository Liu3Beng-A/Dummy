# 主控固件重构 — 彻底重建 ALL 代理机制

> **文档目的**：以 `source code/dummy-ref-core-fw/`（pre-v2.7 旧固件）为基线，
> 逐个解决 5 个根本性设计问题，重构 `firmware/ref_core_f405/` 主控固件。
>
> **前置结论**（已确认）：
> - 基线：旧固件 `source code/dummy-ref-core-fw/`
> - 方向：motorJ[0] 改回 ALL 代理，地轨独立为 `motorJ[7]`
> - 范围：ALL 代理机制 + IsMoving 判断逻辑 + 电机端 Rx 路由 + CanSendMessage 信号量策略

## 一、问题溯源：退化是怎么发生的

### 1.1 旧固件的真实架构（基线，2026-02）

```
motorJ[7] = {
    [0] motorJ[ALL] = CtrlStepMotor(hcan, 0, ...)   // 广播代理，nodeID=0
    [1] motorJ[1]   = CtrlStepMotor(hcan, 1, ...)
    [2] motorJ[2]   = CtrlStepMotor(hcan, 2, ...)
    [3] motorJ[3]   = CtrlStepMotor(hcan, 3, ...)
    [4] motorJ[4]   = CtrlStepMotor(hcan, 4, ...)
    [5] motorJ[5]   = CtrlStepMotor(hcan, 5, ...)
    [6] motorJ[6]   = CtrlStepMotor(hcan, 6, ...)
}
hand = new DummyHand(hcan, 7);  // 夹爪，nodeID=7，独立协议
```

电机端 Rx 路由（旧固件，`can.c`）：
```c
uint8_t id  = (StdId >> 7);
uint8_t cmd = (StdId & 0x7F);
if (id == 0 || id == boardConfig.canNodeId) {  // ★ id==0 特判
    OnCanCmd(cmd, ...);
}
```

效果：
- `motorJ[ALL]->SetEnable(true)` 发 `StdId = (0<<7)|0x01 = 0x01`
- 所有电机 `id==0`，响应 `case 0x01`
- **1 帧覆盖全部 6 个关节**

### 1.2 v2.7/v2.8 重构引入的退化

```
motorJ[7] = {
    [0] motorJ[0] = CtrlStepMotor(hcan, 9, ...)   // ← 地轨占用了 index=0
    [1] motorJ[1] = CtrlStepMotor(hcan, 1, ...)
    ...
    [6] motorJ[6] = CtrlStepMotor(hcan, 6, ...)
}
hand = new StepHand(hcan, 8);  // 夹爪，nodeID=8
```

电机端 Rx 路由（新固件）：
```c
if (cmd >= 0x50 && cmd != 0x5C) { ... }       // 广播分支（cmd ≥ 0x50）
else if (id == boardConfig.canNodeId) { ... }   // 单播分支（删掉了 id==0）
```

退化后果：
- `motorJ[0]`（地轨）的 `SetEnable` 发 `(9<<7)|0x01 = 0x481`
- `StdId=0x01` 帧因 `id==0` 特判被删，**没有任何电机响应**
- `SetEnable` 从 1 帧变成 8 帧串行
- 叠加信号量泄漏（`HAL_CAN_AddTxMessage` 失败不释放），最终 RGB 卡死

## 二、设计决策（逐个解决）

### 决策 2.1：急停语义（`!STOP` 走什么路径）

**选项对比**：

| 选项 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| A | `MoveJ(currentJoints)` 自然收敛（旧固件方案） | 实现简单，电机端无需改 | 响应慢，电机继续跑完剩余轨迹 |
| B | `BroadcastEStop` 硬抱闸（0x09）| 立即抱死，物理安全 | 需要电机端改 Rx 路由 + 加 case 0x09 |
| C | `BroadcastEStop` 0x5B 现有急停 | 电机端已有 case 0x5B | 0x5B 是解锁命令，语义不对 |
| D | `BroadcastEStop` 新命令码 0x5D | 语义正确，与 0x5A/0x5B 同族 | 新增命令码，电机端需加 case |

**推荐选项 B**（理由）：新固件电机端已有抱闸能力（`motor.cpp` 里有 `SetBrake(true)`），
且地轨+J1~J6 需要可靠急停。硬抱闸比自然收敛更安全。

**决策结果**：
- `BroadcastEStop` 改发 `StdId = (0<<7)|0x09 = 0x09`（经 ALL 代理）
- 电机端 Rx 路由恢复 `id==0` 特判（见 §二.3）
- 电机端新增 `case 0x09` 执行硬抱闸
- 不再走 `MoveJ(currentJoints)` 路径

---

### 决策 2.2：地轨和夹爪是否参与 ALL 广播

**结论**：参与 `!START/!DISABLE/!STOP`，不参与 `#REBOOT`。

**理由**：
- `!START/!DISABLE` 让所有能动的东西都使能/失能，语义一致
- `!STOP` 急停让所有轴立即停下，包括地轨
- `#REBOOT` 让所有电机重启，但夹爪固件若不支持 `0x7F` 会导致夹爪意外重启
  → 夹爪 `#REBOOT` 单独处理

**具体行为**：

| 命令 | J1~J6 | 地轨 | 夹爪 |
|---|---|---|---|
| `!START` | `motorJ[ALL]->SetEnable(true)` | 同上 | `hand->SetEnable(true)` |
| `!DISABLE` | `motorJ[ALL]->SetEnable(false)` | 同上 | `hand->SetEnable(false)` |
| `!STOP` | `motorJ[ALL]->BroadcastEStop()` | 同上 | `hand->BroadcastEStop()` |
| `#REBOOT` | `motorJ[ALL]->Reboot()` | 同上 | 暂不实现（见 §四.5） |

电机端 `id==0` 特判意味着 `StdId=0x01/0x09/0x7F` **所有节点都响应**。
夹爪固件若支持对应 case 才生效；若不支持，静默丢弃（安全退化）。

---

### 决策 2.3：夹爪是否参与堵转检测

**结论**：不参与。

**理由**：
- 夹爪夹持物体时电流持续高是正常现象，堵转检测会误触发
- 堵转广播（0x5A）主要影响关节电机，夹爪不需要响应
- 夹爪固件独立，不改

**具体行为**：
- 主控 `SetStallMode()` 只处理 J1~J6 + 地轨
- `hand` 不参与任何 0x5A/0x5B/0x5C 逻辑
- `QueryStallStatus()` 查询 J1~J6 + 地轨，不查夹爪

---

### 决策 2.4：IsMoving() 的边界条件

**旧固件**（无地轨）：
```cpp
bool DummyRobot::IsMoving() {
    return jointsStateFlag != 0b1111110;  // bit1~6 全置位 = 全部 FINISH
}
```

**新固件**（有地轨 + 夹爪）：

```
jointsStateFlag 位分配（8 bits）：
  bit 7  | bit 6 | bit 5 | bit 4 | bit 3 | bit 2 | bit 1 | bit 0
  (保留)    J6      J5      J4      J3      J2      J1    (地轨位，恒为 0)

7 轴全部 FINISH 时：flag = 0b01111110 = 0x7E
```

**结论**：
```cpp
bool DummyRobot::IsMoving() {
    return jointsStateFlag != 0x7E;  // 地轨位 bit0 恒为 0，不影响判断
}
```

**设计约束**：
- `UpdateJointAnglesCallback` 内**不更新地轨的 flag 位**（bit0 始终为 0）
- 地轨到位判断由 `IsMoving()` 显式检查 `rail->AllAtTarget()` 或 `currentRailPos == targetRailPos`
- 若需要地轨也参与 flag，可以改为 9-bit flag，但这增加了复杂度——**先不加**

**EmergencyStop 后的 IsMoving 行为**：
- `EmergencyStop` 发抱闸后，电机端 state = STOP，回包 isFinished = 0
- `jointsStateFlag` 会因为回包被清零（`RUNNING` → `flag &= ~(1<<i)`）
- 结果：`IsMoving()` 会在抱闸后 ~25ms 内变为 true（被回包打破）
- **解法**：`EmergencyStop` 后将 `isEnabled = false`，`IsMoving()` 短路返回 false：
```cpp
bool DummyRobot::IsMoving() {
    if (!isEnabled) return false;  // 失能时直接返回，不依赖 flag
    return jointsStateFlag != 0x7E;
}
```

### 决策 2.5：UpdateAngle 广播频率与 CAN 总线压力

**旧固件**：每 tick（~100Hz）发 1 帧 `motorJ[ALL]->UpdateAngle()`，6 个电机回包。

**新固件**（7 轴 + 地轨）：每 tick 发 1 帧，7 个电机回包。

**总线压力估算**：
- 每 tick：1 帧查询 + 7 帧回包 = 8 帧 × 130µs/帧 ≈ 1.04ms 总线占用
- 100Hz：104ms/s，占总线约 10.4%（CAN 500kbps 标称最大 ~50%）
- **可接受**

**结论**：保持每 tick 1 帧 ALL 广播，不做 4 组轮询。
若未来出现 CAN 总线问题，可改回 4 组轮询（只需改 `UpdateJointAngles()` 一处）。

## 三、重构目标架构

### 3.1 对象布局

```cpp
// dummy_robot.h
#define ALL 0   // 广播代理 index
#define RAIL 7  // 地轨 index

class DummyRobot {
private:
    CtrlStepMotor* motorJ[8] = {nullptr};
    // motorJ[0] = ALL 广播代理（nodeID=0，占位对象）
    // motorJ[1..6] = J1~J6（nodeID=1..6）
    // motorJ[7] = 地轨（nodeID=9）
    
    StepHand* hand = nullptr;  // 夹爪（nodeID=8），不在 motorJ[] 内

    DOF6Kinematic* dof6Solver;
    bool isEnabled = false;
    volatile uint8_t jointsStateFlag = 0;  // bit1~6 = J1~J6，bit0 恒为 0
};
```

### 3.2 关键常量

```cpp
// IsMoving 判断常量
static constexpr uint8_t ALL_FINISH_FLAG = 0x7E;  // 0b01111110，J1~J6 全 FINISH

// 地轨参数（丝杆 1605，直连，5mm/圈）
static constexpr float RAIL_LIMIT_MIN = -250.0f;  // mm
static constexpr float RAIL_LIMIT_MAX =  250.0f;  // mm
```

### 3.3 方法语义规范

以下方法**仅限**使用 `motorJ[ALL]`，不得用于其他目的：

| 方法 | 帧数 | 覆盖节点 |
|---|---|---|
| `motorJ[ALL]->SetEnable(bool)` | 1 | J1~J6 + 地轨 + 夹爪（若支持 id==0）|
| `motorJ[ALL]->UpdateAngle()` | 1 | J1~J6 + 地轨 |
| `motorJ[ALL]->Reboot()` | 1 | J1~J6 + 地轨（夹爪独立处理）|
| `motorJ[ALL]->BroadcastEStop()` | 1 | J1~J6 + 地轨 |

以下方法**禁止**使用 `motorJ[ALL]`：

| 方法 | 原因 |
|---|---|
| `motorJ[ALL]->SetAcceleration()` | 会同时改所有电机加速度，可能非预期 |
| `motorJ[ALL]->ApplyPositionAsHome()` | 会同时标定所有电机零点，非预期 |
| `motorJ[ALL]->SetDceKp/Kv/Ki/Kd()` | 会同时改所有电机 PID |

### 3.4 急停完整流程

```
!STOP
  └─ dummy.commandHandler.EmergencyStop()
       ├─ motorJ[ALL]->BroadcastEStop()    // 发 StdId=0x09，所有电机抱闸
       ├─ hand->BroadcastEStop()           // 夹爪独立急停
       ├─ isEnabled = false               // 停止 5kHz 实时环下发
       ├─ ClearFifo()                    // 清空指令队列
       └─ 返回 "ok"

电机端收到 StdId=0x09（id=0/cmd=0x09）：
  └─ case 0x09:
       ├─ requestMode = MODE_STOP
       ├─ SetBrake(true)
       ├─ SetVelocitySetPoint(0)
       └─ SetCurrentSetPoint(0)

回包处理（isFinished=0）：
  └─ UpdateAngleCallback: state=RUNNING → flag &= ~(1<<i)
       └─ IsMoving() 因 isEnabled=false 直接返回 false（短路）
```

## 四、改动清单（按依赖顺序）

### 阶段 0（前置）：信号量泄漏修复

**独立于其他所有改动**，最先做，防止重构过程中引入新死锁。

**文件**：`firmware/ref_core_f405/Bsp/communication/interface_can.cpp`

**改动**：在 `CanSendMessage` 中增加 `HAL_CAN_AddTxMessage` 返回值检查。

```cpp
void CanSendMessage(CAN_context* canCtx, uint8_t* txData, CAN_TxHeaderTypeDef* txHeader) {
    osStatus semaphore_status;
    if (canCtx->handle->Instance == CAN1)
        semaphore_status = osSemaphoreAcquire(sem_can1_tx, osWaitForever);
    else if (canCtx->handle->Instance == CAN2)
        semaphore_status = osSemaphoreAcquire(sem_can2_tx, osWaitForever);
    else
        return;

    if (semaphore_status == osOK) {
        HAL_StatusTypeDef ret = HAL_CAN_AddTxMessage(
            canCtx->handle, txHeader, txData, &canCtx->last_heartbeat_mailbox);
        if (ret != HAL_OK) {
            // ★ 新增：失败时释放信号量，防止永久泄漏
            if (canCtx->handle->Instance == CAN1)
                osSemaphoreRelease(sem_can1_tx);
            else if (canCtx->handle->Instance == CAN2)
                osSemaphoreRelease(sem_can2_tx);
        }
    }
}
```

**验证**：`ninja` 编译通过即可。

### 阶段 2：电机端新增 `case 0x09` 急停处理

**依赖**：阶段 1

**目标**：让 `!STOP` 经 ALL 代理发 `StdId=0x09` 后，电机端能执行硬抱闸。

**改动文件**（35/42/57 电机同构；gripper 固件不动）：

| 文件 | 改动 |
|---|---|
| `firmware/motor_fw_f103_35/UserApp/protocols/interface_can.cpp` | 新增 `case 0x09`，删除 `case 0x89` |
| `firmware/motor_fw_f103_42/UserApp/protocols/interface_can.cpp` | 同上 |
| `firmware/motor_fw_f103_57/UserApp/protocols/interface_can.cpp` | 同上 |

**改动内容**：

```cpp
// 在 OnCanCmd switch 中，删除 case 0x89，新增 case 0x09
case 0x09:  // [v3.1 新增] ALL 代理广播急停（主控发 StdId=0x09）
{
    extern Motor motor;
    motor.controller->requestMode = Motor::MODE_STOP;
    motor.controller->SetBrake(true);
    motor.controller->SetVelocitySetPoint(0);
    motor.controller->SetCurrentSetPoint(0);
    printf("[CAN] E-Stop (ALL)\r\n");
}
    break;

// 删除 case 0x89（StdId=0x89 已被电机端 switch 解析为 cmd=0x09，
// 不再有调用路径发原始的 0x89 StdId，保留是死代码）
```

**注意**：`case 0x89` 删除是安全的——主控 `BroadcastEStop()` 改用公式后不再发 `StdId=0x89`。
