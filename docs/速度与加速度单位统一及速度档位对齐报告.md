# 速度与加速度单位统一及速度档位对齐报告

日期：2026-10-04。开发目标：`firmware_new`。状态：代码修改与编译完成，尚未烧录及进行本轮实机测试。

## 一、功能定义

物理速度统一为**电机轴 r/s**，加速度统一为**电机轴 r/s²**。不是关节输出轴的转速；位置输入仍为 J1～J6 的角度（°）和 J7 地轨的毫米（mm）。夹爪保留独立的速度控制。

运动命令的 speed 是无单位档位，范围 1～100：

| 档位 | 电机轴速度上限 |
|---|---|
| 1 | 0.3 r/s |
| 35 | 10.5 r/s |
| 50 | 15 r/s |
| 100 | 30 r/s |

映射为 `档位 × 0.30`。这是同步规划的速度上限：短行程、加速度约束、各轴同步及电机自身限制可能使实际速度低于此值，不能把档位 100 理解成每条运动都能达到 30 r/s。

## 二、对比结论与原有问题

参考 `firmware/ref_core_f405/Robot/instances/dummy_robot.cpp` 的速度档位、直接加速度设置和正常模式保留参数的思路，保留 `firmware_new` 自身的轴索引与同步规划。

1. `firmware_new` 的 MoveJ 已使用 r/s，并已有 100→30 的换算和七轴同步规划，因此无需整体迁移参考算法。
2. 原 SetJointSpeed 修改的状态与 MoveJ 默认分支断开；省略速度时 MoveJ 固定使用 50。MoveL 虽调用 SetJointSpeed，随后转入默认 MoveJ 时仍丢失指定速度。
3. 原全局 SetJointAcceleration 把输入解释为 0～100 百分比，再乘各轴基数，并且只设置 J1～J6。
4. 原模式切换重新设置加速度，并使用 TRJ 的 0.3 速度比例；初始化也经过该入口，会覆盖电机已保存的加速度。
5. 七参数 MoveJ 已成功解析地轨目标，却随后将其替换为当前位置。
6. 电机驱动的 CAN 速度/加速度接收已分别按 r/s、r/s² 换算为内部细分步单位，查询加速度反向换算；不需修改电机算法或 EEPROM 格式。

全局加速度输入的有限值限制到 1～5000 r/s²，CAN 保存标志为 false，仅运行时应用；后续电机查询确认实际值。J8 夹爪不参与全局加速度设置，保持独立控制。已有逐节点 `#ACC_J` 的应用/保存协议保持原样。

## 四、协议与兼容性

| 入口 | 含义 |
|---|---|
| `>j1,j2,j3,j4,j5,j6,j7,speed`（或 `&` 前缀） | 八参数，j7 单位 mm，speed 为 1～100 档位；显式档位同时成为后续默认值 |
| `>j1,j2,j3,j4,j5,j6,j7`（或 `&` 前缀） | 七参数，保留地轨目标，沿用当前档位 |
| `@X,Y,Z,A,B,C,speed` | 指定位姿和速度档位；通过现有 IK→MoveJ 链路执行，地轨保持当前位置 |
| `@X,Y,Z,A,B,C` | 沿用当前档位 |
| Fibre `set_joint_speed(speed)` | 设置默认档位，有限值限制到 1～100 |
| Fibre `set_joint_acc(acc)` | 设置 J1～J7 电机轴加速度，单位 r/s²；不保存 EEPROM |
| `#ACC_J <node> <acc> [&]` | 原逐节点加速度入口，acc 为 r/s²，尾随 & 表示保存 |

MoveJ C++ API 的 speed=0 保留为“沿用当前档位”的内部标记。固件中有限的非零超范围速度会限制到 1～100；串口助手严格拒绝超范围或 NaN/Inf。串口发送显式 0 时先经过全局档位设置，最终使用档位 1；不将 0 当成停止指令。

兼容性变化：七参数命令的第七个值现在明确作为地轨目标，不再被丢弃。历史调用端若使用“六关节＋速度”的七参数格式，需要升级为八参数格式。本轮不新增六参数 MoveJ 支持。

加速度从百分比改为物理量后，旧 Fibre 客户端的 `set_joint_acc(15)` 现在表示 15 r/s²，调用端需要按新单位设置。MoveL 保持原有目标位姿运动实现，本轮没有新增直线插补算法。

## 七、后续实机反馈：高速地轨拖尾已定位（2026-10-04）
