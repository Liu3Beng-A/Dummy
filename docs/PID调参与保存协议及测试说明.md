## 本次修复的依据与边界

旧主控的 `SetDceKp/Kv/Ki/Kd` 每帧均带保存位 1，电机 `Main()` 原来在使能状态也处理 `CONFIG_COMMIT` 并擦写 EEPROM 所在 Flash。旧 ASCII `#SET_PID` 连发四帧后立即打印成功，没有等待电机确认。四项可能分别生效，串口的旧 `ok SET PID` 也不能证明实际保存成功。

F103 擦写 Flash 会阻塞从 Flash 取指，可能造成 20kHz 编码器采样间隔异常；位置跳变判据拒绝反馈后，存在进入 `NO_ENCODER` 的软件路径。本次日志尚不足以证明这是实机故障的唯一原因。其他轴的 `phase=6` 是联停状态，不能据此判断它们各自发生了机械堵转。原编码器合理性判据、NO_ENCODER 阈值和堵转检测参数均保留。

用户的慢速持续 ±0.03mm 摆动仍需实机确认。采用用户指定参数不等同于证明摆动已经消失；本轮修复配置过程和保存时机，没有增加位置死区或修改位置控制算法。

## 使用方法

主控与电机端协议有同步变更，需要配套更新。J7 使用 `dummy-motor-fw/build/motor-57.hex`，主控使用 `dummy-ref-core-fw/build/Core-STM32F4-fw.hex`；其余电机按实际硬件使用 35、42 或 gripper 固件。全部节点的 PID 查询/设置能力需要对应节点也更新。继续使用旧电机固件会返回拒绝或超时，不能把主控更新当成电机端已支持新协议。重启目标 `串口助手_old.py`。

按顺序发送，每一步等终结回执后再继续，不能一次粘贴全部指令：

```text
!DISABLE
```

等待 `Disabled ok`，再发送：

```text
#SET_PID 7 350 320 25 50
```

初始 `ok PID_APPLY [7] pending` 只表示受理。成功时先输出电机实际四项回读，再输出：

```text
ok PID [7] kp=350 kv=320 ki=25 kd=50
ok PID_APPLY [7] RAM
```

此时只应用到 RAM。需要运动测试时发送 `!START`，等待 `Started ok` 再测试地轨往返及到位保持。如果结果满意，再次 `!DISABLE`，等待 `Disabled ok`，然后发送：

```text
#SAVE_PID 7
```

只有收到 `ok PID_SAVE [7] saved` 才表示物理 Flash 写入及回读核验成功。保存的是当前已应用参数，编辑框中未点击“应用”的数值不会被保存。重新上电后用 `#GET_PID 7` 核对四项。没有执行 SAVE 时，重新上电恢复原 EEPROM 参数。

助手新增“保存已应用值”，应用和保存按钮仅在已知失能、无保护/校准锁、无 PID 等待任务时可用。没有收到终结回执时显示结果未知，不自动重试保存或自动使能。断开连接清理旧等待状态，重新连接需要重新确认电机状态。

## ASCII 命令

| 命令 | 行为 |
|---|---|
| `#GET_PID <0..8>` | 按事务读取电机当前运行值；0 顺序读取全部 8 节点 |
| `#SET_PID <1..8> <kp> <kv> <ki> <kd>` | 失能后整组暂存、原子应用到 RAM、四项回读确认 |
| `#SET_DCE_KP/KV/KI/KD <1..8> <value>` | 同样走事务，只改指定一项，保留其他三项 |
| `!HAND_KP/KV/KI/KD <value>` | 夹爪单项别名，同样要求失能 |
| `#SAVE_PID <1..8>` | 失能后显式保存当前运行值，等待物理回读确认 |

增益必须是 0～32767 的十进制整数。设置和保存不支持节点 0，不接受负数、小数、NaN、溢出、缺项、多余字段或尾随 `&`。`error PID...` 表示未成功完成；通信超时可能发生在电机已经提交之后，因此须回读，不把超时等同于一定未生效。

PID 事务期间 START 返回 busy，不挂起自动启动。STOP/DISABLE 取消主控任务，并重试发送带原事务号的 ABORT（包括不参与普通软停的 J8）；电机收到 STOP/DISABLE/ABORT 时清理暂存及尚未开始的 PID 保存。等待 ABORT 回执期间继续阻止 START/新的 PID 事务；2.5 秒未确认会记录 `error PID abort_timeout Jn`。已开始或已完成的 Flash 写入不能通过 STOP 回滚，取消后的结果仍须回读核对。孤立 PID 暂存组 2 秒无更新自动清理。

## CAN 与存储

保留标准 ID `(nodeID << 7) | cmdCode`，复用带事务号的 `PARAM_SET=0x30`、`PARAM_GET=0x31`、`PARAM_REPLY=0x32`、`CONFIG=0x33`。

- PID 字段 ID：64=KP、65=KV、66=KI、67=KD；参数值使用 float32，只允许范围内的精确整数。
- CONFIG 操作：5=PID_BEGIN、6=PID_COMMIT、7=PID_SAVE，沿用 4=ABORT。BEGIN 的 argument 低四位声明要改哪些项；全部声明字段收齐才允许 COMMIT。COMMIT 在短 IRQ 临界区内一次应用四项，清积分及检测历史，不做 Flash 写入。
- 回复同时匹配节点、事务号、字段或操作；旧回执不能满足新事务。重复 COMMIT 幂等，重复 SAVE 返回该次物理保存结果，不再次擦写。
- 运行 DCE 参数与 BoardConfig 中“已保存 PID”分离。CAL_SAVE、STALL_SAVE 和其他 BoardConfig 保存不会顺带持久化 PID 试调值。
- PID_SAVE 以 Flash 中已保存的 BoardConfig 为基础，只替换四项 PID，保留其他已保存字段、保护扩展记录及页尾；不会顺带保存未持久化的加速度或电流试调值。直接读取物理 Flash，核对整个 1KiB 重写页。保护参数数量、记录版本、BoardConfig 布局及 Flash 分区不变。
- 旧 CAN 0x17～0x1A 仅允许失能、保存位为 0 的 RAM 写入；保存位为 1 一律拒绝。旧 0x28～0x2B 返回实际运行值。
- 旧配置保存位同样要求电机实际失能，主循环保存与 START 互斥；`#ACC_J ... &` / `#I_LIMIT_J ... &` 在主控使能时明确拒绝。它们仍沿用旧回执，未升级为 PID 的物理保存确认协议。
