# 主控固件回归 — ALL 代理恢复统一规划

> **日期**：2026-09-15
> **核心目标**：恢复 ALL 代理机制（`motorJ[ALL]` 虚拟对象 + 电机端 `id==0` 特判），覆盖 `!START / !DISABLE / #REBOOT / !STOP` 四个群发语义命令，**配套修复**信号量泄漏导致 `!START` 后 RGB 卡死的真凶
> **关键架构变更**：发现 `motorJ[ALL]=slot[0]` 与 `motorJ[0]=rail` 下标冲突的硬伤——必须先把地轨从 `motorJ[0]` 剥离为 `motorJ[Rail]=slot[7]`（数组 7→8），PR 3 的 ALL 代理才能正确工作。**拆为独立 PR 5**，全工程 ~65 处替换。
> **REBOOT 简化决策**：删除 `#REBOOT <node>`（per-axis）变体——`0x7F` 命令码落入 broadcast 区间会让所有电机同时重启，无法真正实现"单轴重启"。统一改为 `#REBOOT`（不带参）= 全量重启 + 主控 reset，简单明确。
> **夹爪设计决策**：夹爪（ID=8）不参与 ALL 代理广播（`!STOP` / 堵转检测），由 `hand->` 独立控制；夹爪固件无需任何修改。

---

## 一、问题分析

### 1.1 症状

`!START` 后 RGB 灯效卡死、串口无响应。电机能响应使能，但 ASCII 线程被严重阻塞。

### 1.2 根因

- **真凶 A**：`DummyRobot::SetEnable` 在 v2.7/v2.8 重构中，把 1 帧 CAN 广播使能（ALL 代理）改成了 **8 次串行** `CtrlStepMotor::SetEnable` 调用（6 个关节 + 地轨 + 夹爪）。ASCII 线程最长阻塞 ~240ms。

- **真凶 B**：`CanSendMessage` 不检查 `HAL_CAN_AddTxMessage` 返回值。STM32 HAL 在 mailbox 满时返回 `HAL_ERROR`，信号量已 `Acquire` 但 TX 完成 ISR 永不触发 → **信号量永久泄漏 → 死锁**。

- **真凶 C（与 !STOP 修复关联）**：`!STOP` 急停帧 StdId=0x89 在电机端 11-bit StdId `(nodeID<<7)|cmd` 解码后实际为 `id=1/cmd=0x09`，电机端 switch 没有 `case 0x09`，**0 个电机响应**（详细分析见 §3.2）。

### 1.3 下标冲突硬伤详解

```cpp
#define ALL 0
CtrlStepMotor* motorJ[7] = {nullptr};

// 即使"先 ALL 后 [0]"的写法：
motorJ[ALL] = new CtrlStepMotor(_hcan, 0, false, 1, -180, 180);  // slot[0] = nodeID=0 (ALL)
motorJ[0]   = new CtrlStepMotor(_hcan, 9, true,  1, -250,  250); // slot[0] = nodeID=9 (rail) ← 覆盖
```

`ALL=0`，`motorJ[ALL]` 和 `motorJ[0]` 是同一数组槽，无论赋值顺序如何，第二个赋值都覆盖第一个。最终 `motorJ[ALL]` 实际指向地轨，内含 `nodeID=9`。

调用 `motorJ[ALL]->SetEnable(true)` 实际发送 `StdId = 9<<7 | 0x01 = 0x481`（地轨单播），而非广播 `0x01`：

| 命令 | 预期 StdId | 实际 StdId | 真实效果 |
|---|---|---|---|
| `!START` | 0x01（广播） | 0x481 | ❌ 仅地轨使能 |
| `!DISABLE` | 0x01（广播） | 0x481 | ❌ 仅地轨失能 |
| `#REBOOT` | 0x7F（广播） | 0x4FF | ⚠️ 0x7F 在 broadcast 区间，实际全电机重启 |
| `!STOP` | 0x09（广播） | 0x489 | ❌ 仅地轨急停 |

**结论**：PR 3 全部失效。必须先做 PR 5 把地轨剥离到独立 slot，PR 3 才能写出正确的 `motorJ[ALL]=slot[0]` + `motorJ[Rail]=slot[7]` 双 slot 架构。

## 二、ALL 代理机制设计

### 2.1 核心原理

**ALL 代理 = `motorJ[ALL]` 虚拟对象（nodeID=0）+ 电机端 Rx 路由识别 `id==0` 为广播**。

`motorJ[ALL]->Xxx()` 发 `(0<<7)|cmd = cmd` 形式的 StdId，电机端 `id==0` 特判覆盖全部 0x00~0x7F 命令码，所有电机响应。

### 2.2 旧/新固件 Rx 路由对比

| | 旧固件（工作正常） | 新固件（ALL 代理失效） |
|---|---|---|
| **代码** | `if (id == 0 \|\| id == boardConfig.canNodeId)` | `if (cmd >= 0x50 && cmd != 0x5C)`<br>`else if (id == boardConfig.canNodeId)` |
| **ALL 支持** | ✅ 任何 cmd 自动群发 | ⚠️ 仅 cmd 0x50~0x7F（不含 0x5C） |
| **影响** | 0x01/0x7F 等都走 id==0 自动群发 | 0x01 走普通区间，主控单播需匹配 nodeID —— **id=0 帧被丢弃** |

**PR 1 修复方案**（保留 0x5C 单播排除，**不排除单播**）：

```c
// 新（正确版本）
if (id == boardConfig.canNodeId) {           // 单播：任何 cmd（含 0x5C）
    OnCanCmd(cmd, RxData, RxHeader.DLC);
}
else if (id == 0 && cmd != 0x5C) {           // 广播：仅排除 0x5C
    OnCanCmd(cmd, RxData, RxHeader.DLC);
}
```

**关键**：0x5C 是查询堵转状态命令（单播查询），不应被 ALL 代理广播，但单播路径仍允许 0x5C。

### 2.3 主控 8 slot 架构

`motorJ[]` 数组从 7 扩展为 **8**，ALL 和 Rail 占用不同 slot：

```cpp
// dummy_robot.h
#define ALL  0  // slot[0] = ALL 广播代理（nodeID=0）
#define Rail 7  // slot[7] = 地轨（nodeID=9，独立 slot 避免与 ALL 冲突）

class DummyRobot {
private:
    CtrlStepMotor* motorJ[8] = {nullptr};
    // motorJ[0]=ALL(广播代理, ID=0), motorJ[1..6]=J1~J6(ID=1~6), motorJ[7]=Rail(ID=9)
    StepHand* hand = nullptr;
};
```

**构造函数**（`dummy_robot.cpp`）：

```cpp
motorJ[ALL]  = new CtrlStepMotor(_hcan, 0, false, 1, -180, 180);  // ALL 广播代理（占位参数）
motorJ[1]    = new CtrlStepMotor(_hcan, 1, false, 50, -175, 175);  // J1
motorJ[2..6] = ...;
motorJ[Rail] = new CtrlStepMotor(_hcan, 9, true,  1, -250, 250);  // 地轨（ID=9）
hand         = new StepHand(_hcan, 8);                             // 夹爪（独立指针）
```

**析构函数**：

```cpp
for (int j = 0; j <= 7; j++) delete motorJ[j];  // 边界 6 → 7
delete hand;
delete dof6Solver;
```

**关键点**：

- `motorJ[ALL]` 与 `motorJ[Rail]` 占用不同 slot，避免 §一.3 的下标覆盖陷阱
- `hand` 独立指针（ID=8），不在 ALL 范围，需单独发帧
- ALL 是占位对象，构造参数 `reduction=1, limit=[-180,180]` 无害（不映射真实电机）

## 三、命令协议映射

### 3.1 命令一览

| 命令 | 主控当前实现 | ALL 代理后实现 | 电机端 case | StdId | 依赖 PR |
|---|---|---|---|---|---|
| `!START` | 8 次循环 `SetEnable` | `motorJ[ALL]->SetEnable(true)` 1 帧 | `case 0x01` | 0x01 | PR 1 + PR 3 |
| `!DISABLE` | 8 次循环 `SetEnable` | `motorJ[ALL]->SetEnable(false)` 1 帧 | `case 0x01` | 0x01 | PR 1 + PR 3 |
| `#REBOOT` | `#REBOOT <node>`（per-axis，但 0x7F 实际 broadcast） | `motorJ[ALL]->Reboot()` 1 帧 | `case 0x7F` | 0x7F | PR 3 |
| `!STOP` | 写死 `StdId=0x89`（死代码） | `motorJ[ALL]->BroadcastEStop()` 1 帧 | **`case 0x09`（新增）** | 0x09 | PR 1 + PR 2 + PR 3 |
| `!RESET` | 应用层 `Resting()` | 不走 ALL（每电机目标不同） | — | — | 不在范围 |
| `!CALIBRATION` | ASCII handler | 已下线（CLEANUP-2，PR 5 同步清理） | — | — | — |

> `#REBOOT` 不依赖 PR 1（cmd=0x7F 在广播区间，新旧 Rx 路由都覆盖）；其他三个在单播区间必须先有 PR 1。
>
> **`#REBOOT <node>` 已删除**（per-axis 重启无法实现，详见 PR 5-J 清理列表）。仅保留 `#REBOOT`（不带参）= 全量重启 + 主控 reset。

### 3.2 !STOP 死代码 bug 详细分析

**主控当前实现**（`ctrl_step.cpp::BroadcastEStop`）：

```cpp
void CtrlStepMotor::BroadcastEStop() {
    txHeader.StdId = 0x89;  // 写死（bug）
    uint8_t buf[8] = {0};
    CanSendMessage(get_can_ctx(hcan), buf, &txHeader);
}
```

**电机端解码**：

```c
uint8_t id  = (RxHeader.StdId >> 7);    // 0x89 >> 7  = 1
uint8_t cmd = (RxHeader.StdId & 0x7F);  // 0x89 & 0x7F = 0x09
```

**结论**：`StdId=0x89` 解码为 `id=1, cmd=0x09`，电机端无 `case 0x09`，**0 个电机响应**。

**修复方案**：

1. 主控 `BroadcastEStop()` 改用公式 `(nodeID<<7)|0x09`，`motorJ[ALL]` 调用时 `nodeID=0` → 发 `StdId=0x09`（PR 3-E）
2. 电机端 Rx 路由恢复 `id==0` 特判（PR 1）后，0x09 走 `id==0` 分支 → 调 `OnCanCmd(0x09)`
3. 电机端 `interface_can.cpp` 新增 `case 0x09`，复用 `case 0x89` 的急停逻辑（PR 2）

### PR 4（配套）— 信号量泄漏修复

**依赖**：无（独立可并行，由其他 agent 实施）

**目标**：修复 `CanSendMessage` 在 mailbox 满时不释放信号量导致的死锁，同时加固以主动预防。

> ⚠️ **PR 5 不涉及此 PR**——PR 5 是 motorJ 索引重构，与 CAN 发送层信号量逻辑无关。

**改动文件**：`firmware/ref_core_f405/Bsp/communication/interface_can.cpp`

**具体改动**（加强版：预检查 mailbox + 10ms 超时 + 失败时释放信号量）：

```cpp
void CanSendMessage(CAN_context* canCtx, uint8_t* txData, CAN_TxHeaderTypeDef* txHeader) {
    // 加固#1：发送前查 mailbox 空闲，避免 Acquire 后失败导致信号量浪费
    uint32_t startTick = HAL_GetTick();
    while (HAL_CAN_GetTxMailboxesFreeLevel(canCtx->handle) == 0) {
        if (HAL_GetTick() - startTick > 5) {
            return;  // 5ms 还腾不出 mailbox，放弃本次发送
        }
    }

    // 加固#2：10ms 超时替代 osWaitForever，避免永久阻塞
    osStatus semaphore_status;
    if (canCtx->handle->Instance == CAN1)
        semaphore_status = osSemaphoreAcquire(sem_can1_tx, 10);
    else if (canCtx->handle->Instance == CAN2)
        semaphore_status = osSemaphoreAcquire(sem_can2_tx, 10);
    else
        return;

    if (semaphore_status == osOK) {
        HAL_StatusTypeDef ret = HAL_CAN_AddTxMessage(
            canCtx->handle, txHeader, txData, &canCtx->last_heartbeat_mailbox);
        if (ret != HAL_OK) {
            osSemaphoreRelease(sem_can1_tx);  // ★ 失败时释放信号量，防止泄漏
        }
    }
    // semaphore_status != osOK 表示超时：放弃本次发送，下一循环重试
}
```
