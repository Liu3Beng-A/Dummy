主控栈溢出修复 20261012.01

设备：Dummy STM32F405 主控。不是电机驱动固件。
修复前快照提交：8bbb848。构建组：1ECA73CD852E42D3。
source_sha256：4c6edcbdbb765303e19d3326a01f1ac1513721a03d591db270310a9a818dc96a

烧录文件：Core-STM32F4-fw.hex（推荐，包含地址）；或 bin，起始地址 0x08000000。
本代理未烧录、复位或恢复被调试暂停的设备。请用你现有的主控烧录流程操作。
固件链接范围不包含 0x080E0000 起的配置扇区；保留配置时不要选择全片擦除。
本包保留当前仓库的默认加速度修改及此前 newlib 重入/锁修复。

原因与修改
现场 PC 在 vApplicationStackOverflowHook，ControlLoopUpdate 的 2000 字节栈底保护区被覆盖。
旧浮点解析路径固定帧合计至少 2072 字节，尚未计入更深函数和任务上下文，已超过栈容量。
改为 4096 字节静态 SRAM 命令栈，并把 608 字节任务控制块也静态放入 SRAM。
MoveJ/MoveL 解析改为受限 CSV + strtof，移除 sscanf -> __ssvfscanf_r -> sprintf 路径。
拒绝超长、缺项、多项、尾部垃圾、NUL、非有限数和浮点溢出/下溢；可选速度格式保留。
保留栈保护，增加 #STACK 的 cmd/rt/oled/rgb 栈历史最小余量与 RTOS heap_min。

内存核算（Release 链接结果）
命令栈：0x20006528，4096 字节；TCB：0x200062c8，608 字节。
SRAM 静态区结束/C 堆起点：0x2000C0C0；C 堆上限 0x2001F800。
C 堆地址容量：79,680 字节，旧版 84,384，减少 4704 字节；这不是运行时空闲量。
MSP 单独保留 2048 字节，未削减。链接 RAM 使用 66,752/131,072（含最低堆/MSP预留）。
CCM 的 65,536 字节仍整体留给 FreeRTOS 堆。linker 的 CCM 100% 表示堆数组已预留，不是堆耗尽。
移走旧栈与 TCB，释放 CCM 动态占用 (2000+8)+(608+8)=2624 字节。
旧现场 RTOS 当前空闲6440、历史最低3816；同负载估算提升到9064、6440字节。
上述 CCM 提升是账面估算，新固件还没有在设备上运行。
Flash 镜像占用454644/917504字节；配置扇区没有纳入代码链接区。

栈核算与边界
本工程开启 -fstack-usage；关键帧：任务入口32、ParseCommand520、CSV解析128、
PlanMoveJ208、PlanMoveL392、SolveIK232字节；newlib反汇编 strtof32、_strtod_l160。
新解析前缀32+520+128+32+160=872字节，主控MoveL前缀32+520+392+232=1176字节。
两条为不同路径，不应相加。更深库函数仍耗栈；浮点任务切换最坏还需约208字节。
这些前缀不是完整最坏调用深度，不能把4096-872称为已经实测的可用余量。
4096提供扩容并移除了已确认超预算的scanf嵌套路径，最终高水位以 #STACK 为准。
strtof 正常解析不会进入原嵌套 sprintf；newlib 断言失败的诊断分支仍可能格式化文本。

已完成验证
ARM GCC 15.2.1、Ninja Release 全量构建通过，202个构建步骤；保留既有RWX LOAD段警告。
解析器本机回归118504条断言通过，包含10000组生成数据、2030条真实运动命令重放。
检查最终 ELF 无 ParseCommand -> sscanf，命令栈/TCB地址正确；489份源文件清单哈希匹配。
本机测试不等于在 ARM 上执行测试，更不等于机械臂实测。
