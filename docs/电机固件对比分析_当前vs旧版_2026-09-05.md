## 7. 电机端 `state` 在 A1/A3 路径上的行为闭环

下面是完整的"主控 IsMoving → 电机端 state → 0x23 isFinished → 主控 jointsStateFlag"链路，证明 A1/A3 修复只动主控就够：

```
TIM7 5kHz 主控环
  ↓ 每 100ms 调 motorJ[i]->UpdateAngle() 发 CAN 0x23
电机端 20kHz 控制环
  ↓ motor.cpp::CloseLoopControlTick() 更新 controller->state
  ↓   位置模式：softPosition==goalPosition && softVelocity==0 → STATE_FINISH
  ↓   其他状态：RETREATING/LOCKED/STOP → STATE_STALL/STATE_STOP
电机端 interface_can.cpp::OnCanCmd(0x23)
  ↓ _data[4] = (state == STATE_FINISH) ? 1 : 0
  ↓ 回 CAN 0x23 帧
主控 can_protocol.cpp::CanRxHandler
  ↓ 调 motorJ[i]->UpdateAngleCallback(pos, isFinished)
  ↓ state = isFinished ? FINISH : RUNNING
主控 dummy_robot.cpp::UpdateJointAnglesCallback (A1 新增)
  ↓ if (motorJ[i]->state == CtrlStepMotor::FINISH)
  ↓   jointsStateFlag &= ~(1 << i);   // 清位 = 该轴到位
  ↓ else
  ↓   jointsStateFlag |= (1 << i);    // 置位 = 该轴运动中
主控 dummy_robot.cpp::IsMoving (A3 修复)
  ↓ return jointsStateFlag != 0;
  ↓   → 等所有 6 个 bit 都被清零（即电机真实到位）才返回 false
```

**结论**：A1/A3 修复的语义闭环只在主控侧，电机端契约（`state==FINISH ⇔ 0x23 isFinished=1`）新旧一致，零改动。

## 8. A4（急停走 0x89）在电机端的行为

```
主控 !STOP / EmergencyStop() (A4 修复)
  ↓ motorJ[1]->BroadcastEStop() 发 StdId=0x89, 8B 全 0
电机端 interface_can.cpp::OnCanCmd(0x89)
  ↓ requestMode = MODE_STOP
  ↓ SetBrake(true)         ← 物理抱闸，电机停在当前位置
  ↓ SetVelocitySetPoint(0)
  ↓ SetCurrentSetPoint(0)
  ↓ 不清 stallMode（保留 LOCKED 状态，符合堵转场景）
  ↓
电机端 20kHz 控制环 (50μs 后)
  ↓ requestMode=STOP → modeRunning=STOP
  ↓ controller->state = STATE_STOP
  ↓ 主控 0x23 查询回 _data[4]=0 (不是 FINISH)
主控 A1 UpdateJointAnglesCallback
  ↓ jointsStateFlag |= (1 << i)   ← 所有位都置 1
主控 A4 EmergencyStop()
  ↓ jointsStateFlag = 0           ← 手动清零（物理已停）
  ↓ isEnabled = false; ClearFifo();
```

**结论**：A4 的电机端接收代码（`case 0x89`）已经在新版固件里完整实现，不需要再改。

## 12. 一句话总结

**电机固件的所有接口契约（0x23 isFinished、0x89 广播急停、state 枚举）在新版 v3.2 已完整实现且与旧版兼容，所以修复主控退化（A1/A3/A4）只需动主控；后续若主控侧要新增命令码或修改堵转策略，才需要回电机端协同改动。**
