## 2. 总体方案

### 2.1 节点表（最终态）

```
nodeID=0   → ALL 代理（占位）             CtrlStepMotor(_hcan, 0, …)
nodeID=1~6 → J1~J6 关节                   CtrlStepMotor(_hcan, 1..6, …)
nodeID=7   → J7 / 地轨                    CtrlStepMotor(_hcan, 7, true, 1, -250, 250)
nodeID=8   → 夹爪                          StepHand（继承 CtrlStepMotor, hcan, 8）
```

**`motorJ[]` 数组长度由 7 → 8**（索引 0 是 ALL 代理，1..6 是 J1~J6，7 是地轨）。`hand` 仍是独立指针，ID 由 7 改为 8。

### 2.2 复用现有 `CtrlStepMotor` 而不是新增类

参考 `firmware/ref_core_f405` 的做法：地轨电机使用与 J1~J6 **完全相同**的 `CtrlStepMotor` 类，不引入新的地轨驱动类。理由：

1. 电机端协议栈（0x01/0x07/0x14/0x15/0x17~0x1A 等）已通用，57 电机端固件只要烧同一份，**主控侧无需差异代码**。
3. reduction=1（直连丝杆 1605，5 mm/圈）；位置含义以"圈数 × 5 = mm"换算；
4. `angleLimitMin/Max = -250 / 250`（mm 单位）作为软限位栅栏，越界 MoveJ 一律拒绝（仿照参考 `firmware/ref_core_f405`）。

`firmware/ref_core_f405` 中地轨类多做了"伪°"换算和 `inverse=true`，本次实现要保留这个语义。

### 2.3 关于 StepHand（夹爪）

当前 `DummyHand` 实现类独占通道阶（独立 `CAN_TxHeaderTypeDef txHeader`、独立协议 0x01/0x02），但参考 `firmware/ref_core_f405` 已改用 `StepHand : public CtrlStepMotor`，更通用、命令集与关节一致。本期**保持**当前 `DummyHand` 类结构不变（最小变动原则），但把构造时的 nodeID 7 改为 8 即可。

如果将来要统一为 `StepHand`，可作单独一期任务。

**MoveJ**（核心：仿参考 `firmware/ref_core_f405` 的 7 轴版本，按当前 `firmware_new` 简化）：

```cpp
bool DummyRobot::MoveJ(float _j1, float _j2, float _j3, float _j4,
                       float _j5, float _j6, float _j7_mm, float _speed) {
    DOF6Kinematic::Joint6D_t targetJointsTmp(_j1, _j2, _j3, _j4, _j5, _j6);

    // 地轨限位
    if (_j7_mm > motorJ[7]->angleLimitMax || _j7_mm < motorJ[7]->angleLimitMin)
        return false;
    // 关节限位
    for (int j = 1; j <= 6; j++) {
        if (targetJointsTmp.a[j-1] > motorJ[j]->angleLimitMax ||
            targetJointsTmp.a[j-1] < motorJ[j]->angleLimitMin)
            return false;
    }

    // 本期简化版：先按用户给定 speed 直接下发（按各轴距离反推电机轴 r/s）
    // 后续同步抵达算法可参考 ComputeSyncSpeeds 实现，但本期不要求
    float slider = _speed > 0 ? _speed : (jointSpeedSlider); // 1~100
    float baseRps = slider * 0.30f;  // 100 → 30 r/s

    DOF6Kinematic::Joint6D_t deltaJoints = targetJointsTmp - currentJoints;
    float deltaRail = _j7_mm - currentRailPos;
    uint8_t idx;
    float maxJointAngle = AbsMaxOf6(deltaJoints, idx);
    float maxAbs = maxJointAngle;
    if (fabsf(deltaRail) > maxAbs) maxAbs = fabsf(deltaRail);
    // 单轴限速 30 r/s；地轨直连 reduction=1 直接 rps；关节 reduction=50 转/°×s/360
    for (int j = 1; j <= 6; j++) {
        float rps = fabsf(deltaJoints.a[j-1]) * motorJ[j]->reduction / 360.0f / maxAbs * baseRps;
        dynamicJointSpeeds7[j] = rps;
    }
    dynamicJointSpeeds7[0] = fabsf(deltaRail) / 5.0f / maxAbs * baseRps;

    jointsStateFlag = 0;
    targetJoints = targetJointsTmp;
    targetRailPos = _j7_mm;
    return true;
}
```

### 3.3.1 加强版：物理同步算法（梯形曲线 + 迭代收敛）

> **状态**：在 §3.3 简化版"按距离比例限速"基础上加强。本节方案与参考版本 `firmware/ref_core_f405/Robot/instances/dummy_robot.cpp:31-128` 的 `ComputeSyncSpeeds` v2.7 对齐。
>
> **简化版与加强版的关系**：简化版代码保留在 §3.3 作为对照（中间稿）；加强版代码将直接替换 §3.3 中 `MoveJ` 的速度分配段落。
>
> **索引约定**：本节数组索引 `[0..6]` 7 个槽位 — `i=0`=地轨，`i=1..6`=J1~J6。与 §3.3 的 `dynamicJointSpeeds7[7]` 索引相反（那里 `dynamicJointSpeeds7[0]`=地轨，`[1..6]`=关节）；调用时需做一次索引映射。

#### A. 为什么做加强版

简化版"按距离比例限速"存在三个根本缺陷，无法满足"7 轴同步抵达"的物理语义：

| 缺陷 | 说明 |
|---|---|
| **单位混用** | `maxAbs = max(maxJoint(°), |Δrail(mm)|)` 把"度"和"毫米"直接比大小。当 `J1=90°`+`rail=100mm` 时，`maxAbs=100`（mm 更大），关节会被压速；反之 `J1=180°`+`rail=50mm` 时，`maxAbs=180`，地轨被压速。同步语义取决于"哪个数字碰巧更大"，与物理无关。 |
| **没有物理上限** | 不查每轴 `ratedVelocity`（电机端 EEPROM 上限速 `velocityLimit`）。简化版下发的速度可能超过电机端能力，被电机端梯形曲线再次压回，结果是"主控说 3.33s 跑完，电机端 4.2s 才到位"，IsMoving() 的 FINISH 时间与主控预估不一致。 |
| **没有加速度约束** | 电机端 PositionTracker 走梯形加减速，主控的"瞬时到顶速"模型与电机端不一致。短距离运动（如 `J1=5°`）时，电机端因为距离太短会退化为三角形曲线（无匀速段），主控以为的匀速段在电机端根本不存在。 |

**对比示例**（`slider=100`、`V_max=30 r/s`、地轨与 J1 同跑、J1 用 `A=150 r/s²`）：

| 输入 | 简化版预估时间 | 加强版预估时间 | 差异原因 |
|---|---|---|---|
| `J1 90°`，`rail=0` | 3.0s | 0.825s（电机轴 20 r/s × 360/50=144°/s） | 简化版用 `baseRps=30` 给关节分摊，关节角速度 = 30°/s；加强版按 J1 物理 V_max=30 r/s 走，速度=144°/s |

#### B. 算法概述

每个电机端跑自己的梯形曲线（`firmware_new/dummy-motor-fw/Ctrl/Motor/motion_planner.cpp PositionTracker`）。主控要为 7 个轴算出"同一时刻到达"的匀速段速度 `v_i`：

```
已知：
  D_i   — 各轴电机轴转数（关节: |Δ°| × reduction/360；地轨: |Δmm| / 5）
  V_max_i — 各轴额定速度（电机端 EEPROM velocityLimit；本期用主控常量）
  A_i   — 各轴额定加速度（电机端 EEPROM velocityAcc；本期用主控常量）
  sliderSpeed — 用户意图上限（slider × 0.30 r/s，slider∈[1,100]）

约束：
  各轴匀速段速度 v_i ≤ min(V_max_i, sliderSpeed)
  梯形曲线时间 T_i = timeTrapezoid(D_i, v_i, A_i)
  同步时间 T_sync = max_i(T_i) 最小化
```

**步骤 1**：把每个轴目标位移换算成电机轴圈数
```
D_motor[0] = |Δmm| / RAIL_MM_PER_CIRCLE   // 地轨 reduction=1
D_motor[i] = |Δ°| × MOTOR_REDUCTION[i] / 360   // i=1..6
```

**步骤 2**：单轴梯形曲线总时间 `timeTrapezoid(D, v, a)`
```
d_acc = v² / (2a)            // 单边加速距离
if 2*d_acc >= D:              // 距离太短 → 三角形（无匀速段）
    T = 2 × sqrt(D / a)
else:                          // 梯形（加速→匀速→减速）
    T = 2v/a + (D - 2*d_acc)/v = v/a + D/v
```

**步骤 3**：迭代收敛（最多 10 轮，一般 2~3 轮收敛）

- **初始预算**：`T_sync = max_i timeTrapezoid(D_i, min(V_max_i, sliderSpeed), A_i)`
- **每轮**：对每个轴解二次方程反推匀速段速度
  ```
  T = v/a + D/v
  → v² - (T·a)·v + D·a = 0
  → v = (T·a - sqrt((T·a)² - 4·D·a)) / 2
  ```
  - 钳制：`v = min(v, V_max_i, sliderSpeed)`
  - 用 `v` 重算 `timeTrapezoid(D_i, v, A_i)` → 新一轮的 `T_sync`
- **收敛**：`|T_new - T_sync| < 1e-3` 退出

**步骤 4**：输出 `outSpeeds[7]`（电机轴 r/s）+ `timeBudget`（同步总时间，秒）

> ⚠️ 二次方程判别式 `< 0` 处理：当 `T_sync` 不足某轴跑完所需最低三角形时间时，`disc<0`。钳到 0 让反推公式自然算出"刚够用"的速度，避免短距离运动突然飙到 cap。

#### E. 关键代码示意

```cpp
// dummy_robot.cpp（新增静态函数，文件作用域）

static float timeTrapezoid(float d, float v, float a) {
    if (d < 1e-6f || v < 1e-6f || a < 1e-6f) return 0;
    float d_acc = v * v / (2.0f * a);
    if (2.0f * d_acc >= d)
        return 2.0f * sqrtf(d / a);          // 三角形曲线
    return 2.0f * v / a + (d - 2.0f * d_acc) / v;  // 梯形曲线
}

static float ComputeSyncSpeeds(const float deltaRails[7],
                               const float sliderCaps[7],
                               const float accel[7],
                               float sliderSpeed,
                               float outSpeeds[7]) {
    // 步骤 1：距离 → 电机轴圈数（索引 0=地轨 mm，1..6=关节°）
    float distMotor[7];
    for (int i = 0; i < 7; i++) {
        distMotor[i] = (i == 0)
            ? fabsf(deltaRails[i]) / RAIL_MM_PER_CIRCLE
            : fabsf(deltaRails[i]) * (float)MOTOR_REDUCTION[i] / 360.0f;
    }

    // 步骤 2：初始预算 = 各轴在 sliderSpeed（钳到 cap）下的梯形时间，取 max
    float timeBudget = 0;
    for (int i = 0; i < 7; i++) {
        if (distMotor[i] < 1e-6f) continue;
        float a = (accel[i] > 1e-6f) ? accel[i] : JOINT_ACC_FALLBACK[i];
        float v = fminf(sliderSpeed, sliderCaps[i]);
        float t = timeTrapezoid(distMotor[i], v, a);
        if (t > timeBudget) timeBudget = t;
    }
    if (timeBudget < 1e-6f) {
        for (int i = 0; i < 7; i++) outSpeeds[i] = 0;
        return 0.0f;
    }

    // 步骤 3：迭代收敛（最多 10 轮）
    for (int iter = 0; iter < 10; iter++) {
        float newTimeBudget = 0;
        for (int i = 0; i < 7; i++) {
            if (distMotor[i] < 1e-6f) { outSpeeds[i] = 0; continue; }
            float a = (accel[i] > 1e-6f) ? accel[i] : JOINT_ACC_FALLBACK[i];
            float vc = sliderCaps[i];
            float disc = timeBudget * timeBudget - 4.0f * distMotor[i] / a;
            if (disc < 0) disc = 0;     // 临界抖动
            float v = (timeBudget - sqrtf(disc)) * a * 0.5f;
            if (v > vc) v = vc;
            if (v > sliderSpeed) v = sliderSpeed;
            outSpeeds[i] = v;
            float t = timeTrapezoid(distMotor[i], v, a);
            if (t > newTimeBudget) newTimeBudget = t;
        }
        if (fabsf(newTimeBudget - timeBudget) < 1e-3f) {
            timeBudget = newTimeBudget;
            break;
        }
        timeBudget = newTimeBudget;
    }
    return timeBudget;
}
```
