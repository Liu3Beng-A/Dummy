## 修订

1. **本方案是「查询端」**：设置端已在 `firmware_new/dummy-ref-core-fw/UserApp/protocols/ascii_protocol.cpp:131-250` 落地（Step 4）。本次仅补查询端。
2. **电机端 0 改动**：经核对 `firmware_new/dummy-motor-fw/UserApp/protocols/interface_can.cpp:264-320`，0x28~0x2D 全部命令的回包响应**已实现**，主控只缺查询路径。
3. **不做 `SetAcceleration_persist` / `SetCurrentLimit_persist`**：当前 `#ACC_J` / `#I_LIMIT_J` 走基类 `SetAcceleration`/`SetCurrentLimit`，默认 `canBuf[4]=0` 不写 EEPROM，**已经满足"不持久化"语义**。ref 的 `_persist(val, persist)` 变体是为 ASCII 显式选持久化用的——本方案用更轻的"`#ACC_J` 永远不写 EEPROM"语义，简化接口面。
4. **`jointAccRuntime` 索引从 `[7]` 改为 `[9]`**：对齐 ref 的 `[9]`（[1..7] + [8]=hand），[0] 留给 ALL 代理空闲槽。影响 `dummy_robot.cpp:218-222` 共 3 行访问点。
5. **`#GET_PID` 必须有 30ms 超时保护**：ref 用 4 帧合并计数器，丢 1 帧**永远 pending**——本方案加起始时间戳 + 30ms 超时回退到 `error GET_PID timeout (got X/4)`。
6. **ALL 模式替代 `#SYNC_*`**：用户决策**不新增** `#SYNC_ACC` / `#SYNC_I` / `#SYNC_PID` 三条异步批量命令（ref 的 `#SYNC_ACC` 也不做）。ALL 模式（`#GET_PID 0` / `#GETJACC 0` / `#GETI 0`）提供相同能力，3 条命令代替原 6 条，UI 「全部读取」按钮触发 3 条 ALL 命令而非 3 条 `#SYNC_*`。
7. **UART4 通道延后到「最后一步」**：本期只做 USB ASCII 通道的查询类命令。UART4 开放 `#GET_PID/GETJACC/GETI` 单独拎出来放在所有功能完成后再做（避免分散测试精力）。**本期不写 UART4 任何代码**，但 ASCII 协议层保留扩展位。

## 修订 (2026-10-04 追加)

8. **PID 维持总写 EEPROM**：用户 2026-10-04 09:45 确认 `SetDceKp/Kv/Ki/Kd` 不加 `_persist` 变体，`#SET_PID` 不解析 `&`（与 ref 行为对齐；ref 的 `#SET_PID` 也不支持 `&`）。
9. **`&` 语义恢复**：用户同意方案 A1（与 ref 完全对齐）。`#ACC_J <node> <v> [&]` 和 `#I_LIMIT_J <node> <A> [&]` 默认不写 EEPROM，加 `&` 才写。基类新增 `SetAcceleration_persist` / `SetCurrentLimit_persist` 两个变体。**行为变更**：`#I_LIMIT_J` 默认从不写 EEPROM（之前写 EEPROM），电机掉电恢复上次 EEPROM 值。
10. **`#GET_PID` 改用时间戳模式（同步路径与异步 PollPidPrint 解耦）**：新增 `motorPidLastUpdateMs[9]` 字段（与 `jointAccLastUpdateMs` 同模式），`motorPidRcvdCount[9]` 加 `volatile`。ISR 合并 4 帧时同时设 `motorPidLastUpdateMs[idx] = HAL_GetTick()`。同步等待改检查时间戳变化，**不再共享 `_pid_print_pending` 单一信号**。
11. **`#GET_PID` 等待 30ms → 10ms**：单节点同步等由 30ms 缩到 10ms（CAN 实测 < 3ms 回包，10ms 给 3× 余量）。`#GETJACC` / `#GETI` 不动，保持 30ms。
12. **`SyncAllMotorPid()` 帧间加 `osDelay(1)`**：32 帧错峰 ~32ms，避免撞 5ms 控制环；`tx_busy_errors` 不再累加；200Hz 控制环不掉拍。`SyncAllMotorAcceleration()` / `SyncAllMotorCurrentLimit()` 不动（单帧 0x2C/0x2D 不撞总线）。

## 3. 改进点（我们要做得比 ref 好的地方）

### 3.1 `#GET_PID` 加 30ms 超时 + 帧数诊断

**ref 问题**（`firmware/ref_core_f405/UserApp/protocols/can_protocol.cpp:36-56`）：
```cpp
static uint8_t _pid_rcv_cnt[9] = {0};
// ISR 内 4 帧合并，丢 1 帧 _pid_rcv_cnt 就停在 1/2/3，_pid_print_pending 永远不置位
```

**本方案修复**（`ascii_protocol.cpp` 的 `#GET_PID` 分支）：
```cpp
const uint32_t t_start = HAL_GetTick();
// 触发 4 个查询
dummy.motorJ[node]->QueryDceKp();
dummy.motorJ[node]->QueryDceKv();
dummy.motorJ[node]->QueryDceKi();
dummy.motorJ[node]->QueryDceKd();
// 同步等 30ms
while (...) {
    osDelay(1);
    waited++;
    // 检查 _pid_rcv_cnt[idx]，达到 4 提前 break
}
if (got_4) {
    Respond("ok PID [%lu] kp=%ld kv=%ld ki=%ld kd=%ld", node, ...);
} else {
    Respond("error GET_PID [%lu] timeout (got %lu/4)", node, _pid_rcv_cnt[idx]);
}
```

**优势**：
- 丢 1 帧也不卡死，30ms 内回退到错误诊断
- 用户知道具体缺哪个（`got 2/4`）
- 与 `#GETJACC` / `#GETI` 超时模式对齐

### 3.2 `node==0` ALL 广播查询

**ref 漏**：ref 5 `ascii_protocol.cpp:584-625` 的 `#GET_PID` / `#GETJACC` / `#GETI` 只支持 `node 1~7 + 8`，**不支持 `node==0` 一次性查所有节点**。

**本方案加**：ASCII 层加 `if (node == 0)` 分支，遍历 1~8 触发 8 套查询，回包逐行打印（避免串口合并怪行）：
```
ok PID [1] kp=1000 kv=80 ki=200 kd=250
ok PID [2] kp=1000 kv=80 ki=200 kd=200
...
ok PID [8] kp=800 kv=80 ki=300 kd=100 (HAND)
```

**优势**：用户 1 条命令拿全 8 个电机 PID，无需脚本循环。

### 3.3 ALL 模式替代 `#SYNC_*`（用户决策不新增）

**用户决策（2026-10-03 21:20）**：**不新增** `#SYNC_ACC` / `#SYNC_I` / `#SYNC_PID` 三条异步批量命令（ref 的 `#SYNC_ACC` 也不引入），由 `node==0` ALL 模式查询提供相同能力：

| 旧方案（ref + 早期本方案） | 新方案（用户决策后） |
|---|---|
| `#SYNC_ACC` 异步批量查询 8 个 0x2C | `#GETJACC 0` ALL 模式（同步触发 8 节点 0x2C，回包由 OledTask 周期 poll 打印）|
| `#SYNC_I` 异步批量查询 8 个 0x2D | `#GETI 0` ALL 模式 |
| `#SYNC_PID` 异步批量查询 32 帧 PID | `#GET_PID 0` ALL 模式（同步触发 32 帧，回包由 OledTask PollPidPrint 分行打印）|

**3 条命令代替原 6 条**（`#GET_PID/GETJACC/GETI 0` 三条 ALL + ref 的 3 条 `#SYNC_*`）。串口助手「全部读取」按钮触发这 3 条 ALL 命令。

**DummyRobot 仍保留 3 个 Sync 方法**（被 `#GET_PID/GETJACC/GETI 0` 内部调用，作为 ALL 模式的实现细节，不暴露给 ASCII 层）：

```cpp
// 内部使用：被 #GET_PID 0 / #GETJACC 0 / #GETI 0 调用
dummy.SyncAllMotorAcceleration();   // 8 个 0x2C
dummy.SyncAllMotorCurrentLimit();   // 8 个 0x2D（ref 无，本期新增）
dummy.SyncAllMotorPid();            // 32 个 PID 查询（ref 无，本期新增）
```

**API 表面更简洁**：ASCII 协议层**不**暴露 `#SYNC_*`，只暴露 `#GET_PID/GETJACC/GETI` 三条 + `node==0` 变体。`SyncAll*` 是 C++ 内部方法，对外不可见。

**优势**：
- ASCII 协议命令数从 7 条降到 4 条
- 用户语义统一：「想查节点 N 改 N 即可，0=ALL」——不需要区分同步/异步触发 vs 单节点查询
- 文档/测试矩阵从 6×3=18 个组合简化为 3×2=6 个

```cpp
// ── 文件作用域辅助 ──
static inline int _pid_node_to_idx(uint8_t nodeId) {
    if (nodeId == 7) return 7;
    if (nodeId == 8) return 8;
    return (int)nodeId;
}

void OnCanMessage(CAN_context* canCtx, CAN_RxHeaderTypeDef* rxHeader, uint8_t* data)
{
    if (canCtx->handle->Instance == CAN1) {
        uint8_t id = rxHeader->StdId >> 7;
        uint8_t cmd = rxHeader->StdId & 0x7F;

        // 现有 0x23/0x25 处理保留（含 id==8 → dummy.hand 分流）

        // 新增：0x28~0x2D
        switch (cmd) {
            case 0x28: case 0x29: case 0x2A: case 0x2B:
                if (id >= 1 && id <= 8) {
                    int idx = _pid_node_to_idx(id);
                    int32_t val = *(int32_t*)data;
                    if      (cmd == 0x28) dummy.motorDceKps[idx] = val;
                    else if (cmd == 0x29) dummy.motorDceKvs[idx] = val;
                    else if (cmd == 0x2A) dummy.motorDceKis[idx] = val;
                    else                  dummy.motorDceKds[idx] = val;
                    dummy.motorPidRcvdCount[idx]++;
                    if (dummy.motorPidRcvdCount[idx] >= 4) {
                        dummy._pid_print_pending[idx] = 1;
                        dummy._pid_pending_node[idx] = id;
                        dummy.motorPidRcvdCount[idx] = 0;
                    }
                }
                break;
            case 0x2C:
                if (id >= 1 && id <= 8) {
                    int idx = _pid_node_to_idx(id);
                    dummy.jointAccRuntime[idx] = *(float*)data;
                    dummy.jointAccLastUpdateMs[idx] = HAL_GetTick();
                }
                break;
            case 0x2D:
                if (id >= 1 && id <= 8) {
                    int idx = _pid_node_to_idx(id);
                    dummy.jointCurrentLimitRuntime[idx] = *(float*)data;
                    dummy.jointCurrentLimitLastUpdateMs[idx] = HAL_GetTick();
                }
                break;
            default: break;
        }
    }
}
```

**注意**：`id==8` (夹爪) 走 `dummy.hand->*` 现有逻辑；0x28~0x2D 都走 `dummy.*` 字段（无需 hand 专用字段，因为 `jointAccRuntime[8]` / `motorDceKps[8]` 等是 DummyRobot 层面的缓存）。

| `#GET_PID 0` 触发 32 帧让 CAN 总线短期拥塞 | 一次 32 帧突发：32 × 135 bit / 500 kbps = 8.6 ms 总线占用；ASCII handler 立刻返回（不阻塞），回包由 ISR 处理；**本期先实测一次性发 32 帧**，后续如需可在 `SyncAllMotorPid()` 内加 `osDelay(1)` 间隔（总线更平稳，~160ms 全部回包完）|
| ALL 模式 ASCII 回包量大（8×3=24 行 × 50 字节 = 1200 字节）| 115200 波特率下 104ms 串口时间；每行 64 字符内，STM32 `Respond` buffer 够用；RTOS 串口有互斥锁，OledTask printf 与 ASCII Respond 不会交错 |
| `串口助手_old.py` 的 `qry_text` Text widget 在多线程更新可能闪烁 | 用 `root.after(0, ...)` 异步追加（与现有 RX 处理一致）|
