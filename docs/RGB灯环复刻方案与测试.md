## 功能

- 24颗灯珠整帧GRB输出，目标50Hz；动画按毫秒相位运行，调度迟到不逐帧补播。静态且亮度不变时不重复发送。
- 独立开关和0～100%设定亮度。关灯保留亮度；关灯时修改亮度保持熄灭，下次开灯恢复新值。0%全黑，开灯也不擅自改成非零。
- 默认渐开/渐关各1000ms，调亮度/普通换效果各300ms；允许0ms立即切换。渐变途中更改目标从当前过渡值继续。
- 颜色、效果、渐变时间、状态绑定、独立自动动效与开关/自动模式可查询和显式保存。上电恢复有效v4配置；合法v1/v2/v3记录在RAM中迁移，其他不支持版本/CRC/范围不合法则用默认，不自动擦写。
- 低亮度使用单调感知亮度表；内部采用浮点渐变，最终仍受灯珠8位通道量化限制。状态查询的current是当前亮度过渡百分比，不是电流测量或光度测量。
- 手动预设0/1/2与AUTO SEQ/INT/TRJ三组颜色分别保存。AUTO默认待机常亮、运动同色圆圈；修改手动预设或动画8均不改变自动默认动效。动画3～9保留原主/副色、周期、方向、拖尾及闪烁亮灭参数。四个自动目标槽分别保存周期250～30000ms、反向0/1、宽度1～12（默认1400/0/3），与8号独立。

## 状态映射

`DummyRobot::GetRGBState`只读取已有状态，RGB不新增CAN查询、不改变运动完成条件，J8不加入普通IsMoving。TUN只有tuningFlag非零才按工作中显示；其余1～3模式按motionActive。未实现TRQ/SRV控制或对应状态绑定。

|---|---|
| BOOT | 彩虹流光；上电后持续显示，受理START/DISABLE/STOP或进入校准、故障等状态后结束 |
| DISABLED | 白色呼吸，效果幅度15% |

| RUN_TUN | 紫色呼吸 |
| CALIBRATION | 黄色旋转；包含失能和保存阶段 |

| FAULT | 固定红色双心跳；含堵转回退、保护锁定、STOP故障或校准/保护失败 |

保护报警优先；正常校准持续显示校准，包括内部失能阶段；STOP/DISABLE取消校准后，由既有取消流程退出calibration，分别按STOP锁定/普通失能显示。尚未清除的故障优先，不因失能请求改成白色。启动pending不能清除报警；最终Started ok、Disabled ok或全校准成功后，由既有状态机清除相应意图。普通换效果平滑过渡，进入FAULT/STOP立即换效果，仍遵守用户亮度和关灯渐变；灯效不是EEPROM写入或失能确认回执。

用户可修改除FAULT以外的状态灯效及颜色来源：预设/动画颜色、该状态单独RGB、AUTO_SEQ、AUTO_INT、AUTO_TRJ。STARTING历史绑定继续存储/查询兼容，但本版实际播放保留原场景，不使用该绑定。选定覆盖颜色时优先于该动画的主色；彩虹仍自行生成颜色。失能/待机的15%/25%效果幅度是固定规则，实际全局设定亮度不被修改。

STARTING只改变显示选择，不改变主控使能状态机或确认条件。RGB_RUNTIME的实际state仍为STARTING，RGB_STATUS的mode及RGB_RUNTIME的source反映保留场景；状态查询在下一RGB tick之前也不会误报青色。首次渲染就处于STARTING且没有前一场景时，以DISABLED（手动模式则使用手动场景）回退。全局亮度及开关渐变继续生效；FAULT/STOP仍优先立即切换。BOOT标志在START受理时照常结束，但已在播放的BOOT画面可延续至确认完成，之后不会重新进入BOOT。

16.03验证：`tools/tests/test_rgb_start_hold.py`编译真实完整rgb.cpp，10471断言、1734对原始帧/GRB检查通过；冻结16.02旧代码隔离编译后按预期失败，确认可发现旧STARTING覆盖。上位机RGB121项通过；完整原生RGB701476断言和主/host185472动效帧对照通过。Render/Phase/Smooth/SelectScene/Gain/QuantizeFrame与16.02函数文本一致，未修改波形。统一2026101603/buildset2E9042E3131A4B19；主控Flash541040B（+208），linked RAM107536B/余23536B及RGB静态栈保持，四电机除56B身份外与16.02一致。原生HAL/RTOS/DMA为stub，不代替实物/时序/并发验收。证据与历史基线调用不适用的失败记录保留于`firmware_artifacts/.qa/rgb-start-hold-2026101603/`，版本说明见根产物`rgb-start-hold-notes-2026101603.txt`。

STOP 默认绑定7号、颜色来源1、RGB(255,180,0)。选用7号时始终与FAULT使用同一1800ms双心跳幅度曲线（两次亮度脉冲及4%微亮底色），状态颜色保持独立；手动预览7号仍使用用户编辑的动画参数，主动绑定其他效果仍按所选效果运行。

BOOT没有自动超时。上电尚未操作时，实际状态仍为DISABLED，但自动灯效来源为BOOT；START/DISABLE/STOP指令受理时一次性结束BOOT，即使操作在两次RGB刷新之间完成，之后回到DISABLED也不会重新显示启动彩虹。只读查询不结束BOOT；手动灯效、关灯及已保存配置仍按用户设置生效。

默认READY_SEQ/INT/TRJ分别绑定10/11/12，颜色来源0；RUN_SEQ/INT/TRJ绑定13，颜色来源2/3/4分别引用对应AUTO槽。校准默认13号、显式黄色。改变AUTO颜色同时影响同组待机与运动。状态绑定页仍可主动选择手动预设0/1/2或指定其他颜色来源；主动保留8号绑定仍按手动8号参数运行。

已保存v4配置直接恢复。合法v1/v2按原规则识别STOP旧默认黄色闪烁并迁至7号；v3不再次迁移STOP，因此用户主动保存的普通闪烁保持。v1由原READY有效颜色推导三组AUTO颜色，其他自定义绑定保留。三个旧版本均只把四目标中的8号迁成13，各槽复制旧effects[8]的周期、方向、拖尾；旧颜色来源0在替换前冻结为原8号主色（显式来源1），避免以后改8号影响自动颜色。非8号绑定保持。迁移仅在RAM，storage=1、dirty=1；实际失能确认后显式!RGB_SAVE写v4，不自动擦写。

## 协议

USB和UART4共用同一RGB解析器。整数只接受十进制非负数字；严格检查参数个数、尾部、溢出及范围。设置只应用到RAM；显式保存或合法末尾`&`才请求保存。旧RGB命令名称保留，但颜色和状态绑定不再隐式保存。

| 指令 | 用途 |
|---|---|
| `!RGB_ON` / `!RGB_OFF` | 独立渐开/渐关 |
| `!RGB_ENABLE <0/1>` | 同上，用于程序控制 |
| `!RGB_AUTO <0/1>` | 自动联动开关 |
| `!RGB_BRIGHT [0..100]` | 无参数查询设定亮度；有参数设置 |
| `!RGB_MODE <0..12>` | 手动选择效果，auto=0；10/11/12预览各AUTO常亮颜色 |
| `!RGB_COLOR <0..2> <r> <g> <b>` | 单色预设，RGB均0～255 |
| `!RGB_AUTO_COLOR <1..3> <r> <g> <b>` | 1=SEQ、2=INT、3=TRJ独立AUTO颜色，RGB均0～255 |
| `!RGB_FADE <on> <off> <bright> <transition>` | 单位ms；前三项0～10000，最后0～5000 |
| `!RGB_EFFECT <mode> <r> <g> <b> <r2> <g2> <b2> <period> <reverse> <tail> <on> <off>` | mode3～9；period250～30000ms，reverse0/1，tail1～12，on/off20～30000ms |
| `!RGB_MOTION <slot> <kind> <period> <reverse> <width>` | slot0/1/2/3=SEQ/INT/TRJ运动/校准；kind0/1/2/3=圆圈/伸缩光弧/双峰/汇聚；原子更新参数及该状态绑定，保留颜色与自动开关 |
| `!RGB_SET_STATE <状态名> <mode> [r g b]` | 不带颜色恢复使用预设/动画颜色；FAULT禁止修改 |
| `!RGB_SET_STATE <状态名> <mode> <AUTO_SEQ/AUTO_INT/AUTO_TRJ>` | 动画或常亮引用指定AUTO颜色，例如RUN_INT 8 AUTO_INT |
| `!RGB_SET_START <mode>` | BOOT绑定兼容命令 |
| `!RGB_SET_ENABLE <mode>` | 同时设置四模式待机及工作共8个绑定 |
| `!RGB_SET_DISABLE <mode>` | DISABLED绑定兼容命令 |
| `!RGB_RESET` | 临时恢复全部默认，包括开灯、100%、自动 |
| `!RGB_SAVE` | 保存整组配置 |
| `#RGB_STATUS` / `#RGB_GET` | 当前机械臂状态下所选灯效及实际亮度过渡/完整配置 |

回执：`ok RGB applied`只表示RAM配置已受理；`ok RGB saved`表示保存/回读成功。成功的简单设置直接回短状态；手动/AUTO颜色、时间、动画、状态绑定/旧绑定别名和RESET直接回完整配置，不需助手追加查询。mode/source按已受理配置与当前机械臂状态解析，current仍是RGB任务实际渲染亮度；光色渐变继续由RGB任务完成。末尾`&`的设置先应用RAM，若保存门禁拒绝或Flash失败，RAM修改仍存在，错误回执不能当作已保存。

RGB状态查询以及无参数亮度查询是纯本地主控读取，允许穿过STOP/校准门禁；设置和保存不允许。每行响应保持现有Respond的62字节载荷限制：

- RGB_STATUS：on/auto/bright/current/mode
- RGB_RUNTIME：state/source（source可为BOOT、各状态、MANUAL或OFF）
- RGB_STORAGE：dirty/storage/dma；storage=0未保存默认、1有效、2无效或写失败
- RGB_DMA：frames/errors；RGB_TIMEOUT：timeouts
- 完整查询先输出RGB_CAPS motion=1；RGB_CONFIG及RGB_TIMING给出渐变配置，另有3行手动颜色、3行RGB_AUTO_COLOR、7行动画、4行RGB_MOTION及14行绑定，以RGB_GET end结束。RGB_MOTION格式为slot period reverse width，形态由该状态RGB_STATE的mode13～16决定。RGB_STATE的颜色来源字段0=预设/动画、1=状态RGB、2/3/4=AUTO SEQ/INT/TRJ。10Hz短状态不输出CAPS或整组参数。

## 驱动与存储

TIM2_CH4/PA3复用原硬件：APB1定时器84MHz，ARR=104，每bit1.25us；0/1高电平分别30/70 ticks（约0.357/0.833us），整帧尾部256个零周期约320us。设计时序以代码计算为准；实际灯珠型号、电气幅度和波形容限仍需实机验证。现有ioc原本将TIM2描述为Encoder，与现有手写PWM代码已不一致，本轮没有用CubeMX重新生成工程。

RGB线程拥有唯一PWM缓存；发送前先标记busy，并在短临界区启动DMA，ISR只停止TIM2_CH4并释放状态。DMA1_Stream6句柄仅绑定TIM2_CC4：同时绑定CC2时HAL按指针先识别成CH2，导致CH4完成回调被过滤，实机每帧都超时；本轮移除CC2绑定及对应DeInit。未完成时不重写缓存；超过10ms未完成则停止/重试并累加timeout；启动错误、DMA错误分别累加errors并重发。CPU不忙等灯珠。

配置使用主控最后一个Flash扇区11，记录地址0x080FFC00，magic/version/size/CRC和整组范围校验；v4 Config258字节、含头与CRC记录272字节，仍在原1024字节RGB槽内。前缀保留v1/v2/v3真实布局及padding，各自验证CRC后再迁移。TCP槽仍为0x080FFB00的256字节；共同保存按Flash实际字节备份另一槽，不写入对方未保存RAM草稿。仅写实际记录，保存后直接回读比较。链接代码区仍896KiB，电机EEPROM/编码器分区不变。

- 保存入口需DISABLED、无运动/队列任务、无保护/校准任务/故障，且无pending START。
- 保存期间保留互斥标志；START及校准不能进入，STOP/DISABLE仍可请求。不把单Bank Flash擦写描述为完全无停顿的后台任务。
- 配置未变化时不重复擦写。写入中断电可能丢失本次及此前RGB配置，下一次上电按校验回默认；没有双扇区断电保留保证。
- 初次烧录不要整片擦除其他配置；无有效旧RGB记录时使用默认dirty状态，已有合法v1/v2记录按上述条件迁移。

## old助手

参照串口助手.py，RGB与电机参数放在中栏同一个Notebook，通过“RGB / 电机参数”标签切换；右栏保留关节控制、MoveL、夹爪。RGB含亮度/灯效、自动颜色、动画参数、状态绑定四个子页，状态文字按页面宽度换行。自动颜色页独立选择SEQ/INT/TRJ、选色/应用、常亮预览及恢复自动；状态绑定页可选择10/11/12及AUTO颜色来源。滑块只修改编辑值，应用才发送；保存需先DISABLE等Disabled ok。开关、设置亮度、当前过渡、效果来源、存储/未保存状态和DMA计数均可查看。

亮度应用、自动联动、渐开/渐关、手动灯效选择、保存以及颜色/时间/动画/绑定/恢复默认均只发设置指令，直接消费主控返回的短状态或完整配置；不再追加#RGB_STATUS或#RGB_GET，避免重复回包。连接及“查询全部”仍发送#RGB_GET；主动短状态查询仍可使用#RGB_STATUS。调亮度或开启自动联动不会刷出整组参数，也不覆盖其他尚未应用的编辑值。

接收线程继续通过root.after投递，RGB解析在Tk主线程；发送复用原队列、代次、STOP及校准门禁。连接后自动发只读#RGB_GET，重连清缓存。校准/STOP锁定时仍能查询RGB；malformed配置行不覆盖有效编辑缓存。没有新增串口依赖，仍使用原pyserial。
