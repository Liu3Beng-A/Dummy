# 地轨重构为 J7 — 彻底对齐 7 关节架构

> **日期**：2026-09-15  
> **性质**：ALL 代理修复的**前置依赖项**（必须先做）  
> **目标**：将地轨从"特殊边缘节点"变为"第 7 个关节 J7"，CAN ID 从 9 改为 7，`motorJ[7]` = 地轨，`motorJ[0]` 干净留给 ALL 代理

---

## 一、架构变更总览

### 1.1 当前架构（问题）

```
motorJ[0] = 地轨 (CAN ID=9)   ← 与 ALL=0 冲突，无法做 ALL 代理
motorJ[1..6] = J1~J6 (ID=1~6)
hand = 夹爪 (ID=8)
```

MoveJ 格式：`>Rail,j1,j2,j3,j4,j5,j6,speed`（地轨在第 1 位，特殊处理）

### 1.2 目标架构（重构后）

```
motorJ[0] = ALL 广播代理 (ID=0, 占位对象)
motorJ[1..7] = J1~J7 (ID=1~7)
  其中 motorJ[7] = J7/地轨 (CAN ID=7, 直连丝杆1605)
hand = 夹爪 (ID=8, 独立指针)
```

MoveJ 格式：`>j1,j2,j3,j4,j5,j6,j7(rail),speed`（地轨在第 7 位，与所有关节对齐）

### 1.3 CAN ID 变更

| 对象 | 当前 ID | 目标 ID | 说明 |
|-----|-------|-------|-----|
| J1 | 1 | 1 | 不变 |
| J2 | 2 | 2 | 不变 |
| J3 | 3 | 3 | 不变 |
| J4 | 4 | 4 | 不变 |
| J5 | 5 | 5 | 不变 |
| J6 | 6 | 6 | 不变 |
| **J7/地轨** | **9** | **7** | **核心变更** |
| 夹爪 | 8 | 8 | 不变 |
| ALL 代理 | - | 0 | 新增（motorJ[0]） |

### 1.4 motorJ[] 索引映射（新架构）

| 数组下标 | 对象 | CAN ID | 说明 |
|---------|-----|-------|-----|
| `motorJ[0]` | ALL 代理 | 0 | 虚拟占位，ALL 代理用（待后续阶段实现） |
| `motorJ[1]` | J1 | 1 | 不变 |
| `motorJ[2]` | J2 | 2 | 不变 |
| `motorJ[3]` | J3 | 3 | 不变 |
| `motorJ[4]` | J4 | 4 | 不变 |
| `motorJ[5]` | J5 | 5 | 不变 |
| `motorJ[6]` | J6 | 6 | 不变 |
| `motorJ[7]` | **J7/地轨** | **7** | **核心变更**：从 motorJ[0] 移来 |

> **ID=9 正式废弃**：CAN ID 9 不再使用，所有地轨通信改用 ID=7。

### 3.11 dummy_robot.cpp — CommandHandler::ParseCommand（MoveJ 解析 + 地轨下发）

> **关键澄清**：sscanf 是按**位置**赋值，与注释标签无关。当前格式串 `"%f,%f,%f,%f,%f,%f,%f,%f"` 按位置解析 8 个值：
> - **旧格式** `>Rail,j1,j2,j3,j4,j5,j6,speed`：joints[0]=Rail, joints[1..5]=J1..J5, j7=J6
> - **新格式** `>j1,j2,j3,j4,j5,j6,j7(rail),speed`：joints[0]=J1, joints[1..5]=J2..J6, j7=Rail
>
> 因此 **sscanf 格式串确实不变**（都是 8 个 `%f`），但 **MoveJ 调用参数顺序必须改变**：
> - 旧：`MoveJ(joints[0], ..., joints[5], j7, speed)` → `_j7_mm = j7 = J6` ❌
> - 新：`MoveJ(j7, joints[0], ..., joints[5], speed)` → `_j7_mm = j7 = Rail` ✅

#### 3.11.1 SEQUENTIAL 模式的 MoveJ 解析（8 个 %f，有 speed）

**当前代码**（注释描述与实际 sscanf 行为不符，sscanf 按位置解析）：

```cpp
float joints[6];
float j7 = 0.0f;
float speed = 0.0f;

argNum = sscanf(_cmd, (_cmd[0] == '>') ?
                ">%f,%f,%f,%f,%f,%f,%f,%f" : "&%f,%f,%f,%f,%f,%f,%f,%f",
                joints, joints+1, joints+2, joints+3, joints+4, joints+5, &j7, &speed);

if (argNum == 8) context->SetJointSpeed(speed);
if (argNum >= 7)
{
    // [v3.1] 新格式 >j1,j2,j3,j4,j5,j6,j7(rail),speed
    // sscanf 解析：joints[0]=j1, ..., joints[5]=j6, j7=rail, speed=speed
    // MoveJ 参数顺序：_j1, _j2, _j3, _j4, _j5, _j6, _j7_mm, _slider
    // 因此：j7(rail) 作为第1参数，joints[0..5] 作为第2~7参数，speed 作为第8参数
    if (context->MoveJ(j7, joints[0], joints[1], joints[2],
                   joints[3], joints[4], joints[5], speed))
    {
        // ...
        context->motorJ[0]->SetPositionWithMotorRps(
            context->targetRailPos / 5.0f, context->railSpeedRps);
```

**改动后**（SEQUENTIAL 模式）：

```cpp
float j1, j2, j3, j4, j5, j6, j7;  // j7=地轨
float speed = 0.0f;

argNum = sscanf(_cmd, (_cmd[0] == '>') ?
                ">%f,%f,%f,%f,%f,%f,%f,%f" : "&%f,%f,%f,%f,%f,%f,%f,%f",
                &j1, &j2, &j3, &j4, &j5, &j6, &j7, &speed);

if (argNum == 8) context->SetJointSpeed(speed);
if (argNum >= 7)
{
    // sscanf 解析: 值顺序不变(j0=rail,j1~j5=j1~j5,j6=j6)，但命名清晰化
    if (context->MoveJ(j1, j2, j3, j4, j5, j6, j7, speed))
    {
        // ...
        context->motorJ[7]->SetPositionWithMotorRps(
            context->targetRailPos / 5.0f, context->railSpeedRps);
```

> **sscanf 格式串不变**：仍然是 8 个 `%f`，但因为**输入数据顺序变了**（Rail 从第1位移到第7位），解析结果也变了：
> - 旧格式 `>Rail,j1,j2,j3,j4,j5,j6,speed`：joints[0]=Rail, ..., j7=J6
> - 新格式 `>j1,j2,j3,j4,j5,j6,Rail,speed`：joints[0]=j1, ..., j7=Rail
>
> **MoveJ 参数必须调整**：`MoveJ(joints[0], ..., joints[5], j7, speed)` → `MoveJ(j7, joints[0], ..., joints[5], speed)`

**同样的 8 值改动应用于 CONTINUES_TRAJECTORY 和 INTERRUPTABLE 模式**（共 3 处 `motorJ[0]->SetPositionWithMotorRps` → `motorJ[7]->`，SEQUENTIAL + CONTINUES_TRAJECTORY + INTERRUPTABLE 各 1 处）。

### 3.12 dummy_robot.cpp — $ 力矩模式解析

**当前代码**（`$` 分支）：

```cpp
// $c0(地轨),c1~c6(关节),c7(夹爪)
float cur[7];
argNum = sscanf(_cmd, "$%f,%f,%f,%f,%f,%f,%f",
                &cur[0], &cur[1], &cur[2], &cur[3], &cur[4], &cur[5], &cur[6]);

if (argNum == 7)
{
    context->SetJointCurrents(cur[0], cur[1], cur[2], cur[3], cur[4], cur[5], cur[6], 0.0f);
```

**新格式**：`$c1,c2,c3,c4,c5,c6,c7(地轨)`（共 7 个电流值，与 MoveJ 顺序对齐；夹爪由 `!HAND_*` 单独控制）。

sscanf 解析后：`c[0]=c1, c[1]=c2, ..., c[5]=c6, c[6]=c7(地轨)`。

`SetJointCurrents` 函数签名是 `SetJointCurrents(c0, c1, c2, c3, c4, c5, c6, c7)`，其中 `c0`=地轨电流，`c1~c6`=J1~J6，`c7`=夹爪。

**正确映射**：

```cpp
if (argNum == 7)
{
    // c[6]=c7(地轨) → SetJointCurrents 第1参数(c0=地轨)
    // c[0]=c1~c[5]=c6 → SetJointCurrents 第2~7参数(c1~c6=J1~J6)
    context->SetJointCurrents(
        c[6],   // 地轨电流 = c[6]（第7个值）
        c[0], c[1], c[2], c[3], c[4], c[5],  // J1~J6
        0.0f);  // 夹爪单独控制
```

> **示例对比**：
> - 旧格式 `$7,1,2,3,4,5,6` → 地轨=7A, J1=1A, J2=2A, ..., J6=6A
> - 新格式 `$1,2,3,4,5,6,7` → J1=1A, J2=2A, ..., J6=6A, 地轨=7A

## 九、运动学求解器（DOF6Kinematic）

### 9.1 状态

**DOF6Kinematic 内部使用 `Joint6D_t`（6元素）**，与 J7/地轨无关。地轨是笛卡尔空间的额外自由度（沿 X 轴），不影响关节空间 IK/FK。

- `DOF6Kinematic::Joint6D_t`：仍是 6 个元素（对应物理 J1~J6）
- `MoveJ` 函数内部：处理 7 轴同步速度规划（`ComputeSyncSpeeds`），但 FK 只算 6 关节

### 9.2 地轨与 IK 的关系

当前 `MoveL` 使用 IK 求解 6 轴关节角，地轨保持不变（`currentRailPos` 不参与 IK）。这是**当前设计约束**，与 CAN ID 重构无关。

> 如果未来要让 MoveL 也移动地轨，需要将 IK 扩展为 7-DOF，涉及到 `DOF6Kinematic` 的全面重构。本阶段**不涉及**此变更。

6. **⚠️ 3 个 MoveJ 模式都要改**：SEQUENTIAL、CONTINUES_TRAJECTORY、INTERRUPTABLE 三个模式都有 MoveJ 解析分支，**都要修改 MoveJ 调用参数顺序**
7. **⚠️ can_protocol.cpp 遗漏**：`_pid_node_to_idx` 中 `if (nodeId == 9) return 0;` → `if (nodeId == 7) return 7;`
8. **⚠️ can_protocol.cpp 遗漏**：地轨回包分支（id==9）中的 0x25 温度回包：`motorJ[0]->temperature` → `motorJ[7]->temperature`

**总计**：约 ~140 行代码改动（含上位机配套 ~5 行）。

### 16.4 关键提醒（最终版）

1. **⚠️ ASCII 双通道**：`ascii_protocol.cpp` 中 `OnUsbAsciiCmd` 和 `OnUart4AsciiCmd` 几乎完全相同，所有 `node=9` 分支**必须同时修改两处**

3. **⚠️ SERVO_J 是 7 值**：sscanf 格式串为 7 个 `%f`（无 speed），不是 8 个
