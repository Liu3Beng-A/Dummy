# commit 63b4b16 中 5 个问题的形式分析

> 分析日期：2026-09-16  
> 目标版本：63b4b16 (2026-09-02 23:34)  
> `fix: !START 抖动修复 + ApplyPosAsHomeOffset 同步 + ascii 乐观同步清理`

---

## 关键发现

**`63b4b16` 时的 firmware/ref_core_f405 处于"过渡状态"：部分特性已更新，部分问题尚未引入。**

5 个问题的状态：
| # | 问题 | 63b4b16 状态 | 是否存在问题 |
|---|---|---|---|
| 1 | CanSendMessage 10ms 超时 | `osWaitForever` 无限等待 | ❌ 不存在 |
| 2 | Homing() 无超时保护 | `while(IsMoving())` 阻塞等待，无超时 | ⚠️ 存在但形式不同 |
| 3 | 实时环 50Hz 节流 | 已有 50Hz 节流 + 100Hz 分组轮询 | ✅ 存在 |
| 4 | SetEnable 用 ALL 代理 | **逐帧发送**，无 ALL 代理，无配套 UpdateAngle | ⚠️ 形式不同 |
| 5 | UpdateJointAngles 轮询 | 分组轮询（每组 2 轴），无单播轮询 | ⚠️ 形式不同 |

## 逐项详细分析

### 问题 1：CanSendMessage 信号量超时

**63b4b16 时的实现：**

```cpp
// firmware/ref_core_f405/Bsp/communication/interface_can.cpp
void CanSendMessage(CAN_context* canCtx, uint8_t* txData, CAN_TxHeaderTypeDef* txHeader)
{
    osStatus semaphore_status;
    if (canCtx->handle->Instance == CAN1)
        semaphore_status = osSemaphoreAcquire(sem_can1_tx, osWaitForever);  // ← 无限等待
    else if (canCtx->handle->Instance == CAN2)
        semaphore_status = osSemaphoreAcquire(sem_can2_tx, osWaitForever);
    else
        return;

    if (semaphore_status == osOK)
        HAL_CAN_AddTxMessage(canCtx->handle, txHeader, txData, &canCtx->last_heartbeat_mailbox);
    // ← 未检查 HAL_CAN_AddTxMessage 返回值
    // ← 失败时信号量泄漏
}
```

**结论：问题 1 尚未引入。**  
- 没有 5ms mailbox 预检
- 没有 10ms 超时
- 没有失败时释放信号量
- **旧版问题（信号量泄漏）仍存在，但没有"静默失败"问题**

### 问题 2：!HOME 执行路径

**63b4b16 时的实现：**

```cpp
// firmware/ref_core_f405/Robot/instances/dummy_robot.cpp
void DummyRobot::Homing()
{
    float lastSlider = jointSpeedRps / SLIDER_TO_RPS;
    SetJointSpeed(10);

    MoveJ(0, 0, 90, 0, 0, 0, 0, 10);
    MoveJoints(targetJoints);
    motorJ[0]->SetPositionWithMotorRps(0, railSpeedRps);  // 地轨

    while (IsMoving())    // ← 阻塞等待
        osDelay(10);

    SetJointSpeed(lastSlider);
}

void DummyRobot::Resting()
{
    float lastSlider = jointSpeedRps / SLIDER_TO_RPS;
    SetJointSpeed(10);

    MoveJ(REST_POSE.a[0], REST_POSE.a[1], REST_POSE.a[2],
          REST_POSE.a[3], REST_POSE.a[4], REST_POSE.a[5], 0, 10);
    MoveJoints(targetJoints);
    motorJ[0]->SetPositionWithMotorRps(0, railSpeedRps);

    while (IsMoving())    // ← 阻塞等待
        osDelay(10);

    SetJointSpeed(lastSlider);
}
```

**与当前版本的差异：**

| | 当前版本 | 63b4b16 |
|---|---|---|
| 阻塞方式 | `while(IsMoving())` + 30s 超时兜底 | `while(IsMoving())` **无超时保护** |
| 超时调试输出 | 有 `printf("[HOME TIMEOUT]")` | **无** |

**结论：问题 2 存在但形式不同。**  
- 当前版本有 30s 超时兜底 + 调试输出
- `63b4b16` **没有超时保护**，可能永久挂死
- 两者都会阻塞 ASCII 线程，但原因不同

### 问题 3：实时环 50Hz 下发

**63b4b16 时的实现：**

```cpp
// firmware/ref_core_f405/UserApp/main.cpp
void ThreadControlLoopFixUpdate(void* argument)
{
    for (;;) {
        static uint32_t updateCounter = 0;
        ulTaskNotifyTake(pdTRUE, portMAX_DELAY);

        if (dummy.IsEnabled()) {
            switch (dummy.commandMode) {
                case DummyRobot::COMMAND_TARGET_POINT_SEQUENTIAL:
                case DummyRobot::COMMAND_TARGET_POINT_INTERRUPTABLE:
                case DummyRobot::COMMAND_CONTINUES_TRAJECTORY:
                    // 50Hz 下发（总线节流）
                    if (updateCounter % 100 == 0) {
                        dummy.MoveJoints(dummy.targetJoints);
                        dummy.motorJ[0]->SetPositionWithMotorRps(...);  // 地轨
                    }
                    // 100Hz 分组轮询（每组 2 轴）
                    if (updateCounter % 50 == 25) {
                        dummy.UpdateJointAngles();
                    }
                    dummy.UpdateJointPose6D();
                    break;
                // ...
            }
        }
        updateCounter++;
    }
}
```

**结论：问题 3 存在，与当前版本相同。**  
- 50Hz 下发机制完全一致
- 分组轮询（每组 2 轴）与当前版本的单播轮询不同（见问题 5）

### 问题 4：SetEnable 用 ALL 代理

**63b4b16 时的实现：**

```cpp
// firmware/ref_core_f405/Robot/instances/dummy_robot.cpp
void DummyRobot::SetEnable(bool _enable)
{
    if (_enable) {
        isStalled = false;
        SetRGBMode(rgbStateEnable);
    } else {
        isStalled = false;
        SetRGBMode(rgbStateDisable);
        for (int i = 0; i < 6; i++)
            targetCurrents[i] = 0.0f;
        SetCommandMode(DEFAULT_COMMAND_MODE);
        targetJoints = currentJoints;
    }

    // ← 没有 motorJ[ALL] 代理，逐帧发送
    for (int i = 1; i <= 6; i++)
        motorJ[i]->SetEnable(_enable);   // J1~J6 各 1 帧
    motorJ[0]->SetEnable(_enable);      // 地轨 1 帧
    hand->SetEnable(_enable);            // 夹爪 1 帧
    
    // ← 没有 enable 后预发 UpdateAngle 配套
}
```

**与当前版本的差异：**

| | 当前版本 | 63b4b16 |
|---|---|---|
| 使能方式 | `motorJ[ALL]->SetEnable()` 1 帧广播 + `hand->SetEnable()` 1 帧 | 逐帧发送 J1~J6 + 地轨 + 夹爪 = **8 帧** |
| ALL 代理 | 存在（`motorJ[0]` = ALL） | **不存在**（`motorJ[0]` = 地轨，ID=9） |
| 配套 UpdateAngle | enable 后调用 `motorJ[ALL]->UpdateAngle()` | **无** |

**结论：问题 4 在 `63b4b16` 中不存在 ALL 帧失败风险。**  
- 当前版本的"ALL 帧静默失败 → jointsStateFlag 永远无法更新"问题，在 `63b4b16` 中**不存在**
- 但逐帧发送 8 帧会带来更大的总线负载

### 问题 5：UpdateJointAngles 轮询

**63b4b16 时的实现：**

```cpp
// firmware/ref_core_f405/Robot/instances/dummy_robot.cpp
void DummyRobot::UpdateJointAngles()
{
    static uint8_t group = 0;

    switch (group) {
        case 0:
            motorJ[1]->UpdateAngle();   // J1
            motorJ[2]->UpdateAngle();   // J2
            break;
        case 1:
            motorJ[3]->UpdateAngle();   // J3
            motorJ[4]->UpdateAngle();   // J4
            break;
        case 2:
            motorJ[5]->UpdateAngle();   // J5
            motorJ[6]->UpdateAngle();   // J6
            break;
        case 3:
            motorJ[0]->UpdateAngle();   // 地轨
            break;
    }

    group = (group + 1) % 4;
}
```

**与当前版本的差异：**

| | 当前版本 | 63b4b16 |
|---|---|---|
| 查询方式 | **单播轮询**（每次 1 轴） | **分组轮询**（每次 2 轴，地轨单独） |
| 每帧 CAN 帧数 | 1 帧 | 2 帧（J1+J2, J3+J4, J5+J6）或 1 帧（地轨） |
| 轮询周期 | 7 轴 × 1 帧 = 7 tick | 4 组 = 4 tick |
| 每轴查询频率 | ~14Hz（100Hz / 7） | ~28Hz（100Hz / 4 × 每组 2 轴） |

**结论：问题 5 存在但形式不同。**  
- `63b4b16` 的分组轮询每轴查询频率约 **28Hz**（比当前版本快一倍）
- 当前版本的单播轮询每轴查询频率约 **14Hz**
- 两者都没有旧版的 ALL 全量查询（每轴 5kHz）

## 总结对比表

| 维度 | 当前版本（有全部 5 个问题） | 63b4b16（过渡状态） |
|---|---|---|
| **CanSendMessage** | 10ms 超时静默失败 | `osWaitForever` 无限等待（无超时） |
| **Homing()** | 30s 超时兜底 + 调试输出 | 无超时保护，可能永久挂死 |
| **实时环节流** | 50Hz 下发 + 100Hz 单播轮询 | 50Hz 下发 + 100Hz 分组轮询（相同） |
| **SetEnable** | ALL 代理 2 帧广播 | 逐帧发送 8 帧（无 ALL 帧失败风险） |
| **UpdateJointAngles** | 单播轮询 14Hz/轴 | 分组轮询 28Hz/轴（更快） |

---

## 根因链条变化

### 当前版本（引入 5 个问题后）：
```
CanSendMessage 10ms 超时 → 静默失败
        ↓
SetEnable/UpdateAngle 的 ALL 帧丢失
        ↓
jointsStateFlag 无法更新
        ↓
IsMoving() 永远返回 true
        ↓
Homing() 30s 超时退出
        ↓
ASCII 线程"发送就卡死"
```

### 63b4b16（问题 1、4 尚未引入）：
```
CanSendMessage osWaitForever → 无限等待，不静默失败
        ↓
SetEnable 逐帧发送 8 帧 → 无 ALL 帧失败风险
        ↓
jointsStateFlag 正常更新（但查询频率 28Hz，低于旧版 5kHz）
        ↓
IsMoving() 依赖 jointsStateFlag 判定
        ↓
Homing() 无超时保护 → 可能永久阻塞
        ↓
ASCII 线程"永久挂死"（原因：IsMoving() 判定失败，而非发送失败）
```
