### 1.2 当前实现（v2026-10-02 现状审计）

`firmware_new/dummy-ref-core-fw/Robot/instances/dummy_robot.{h,cpp}` 已有一个 `DummyHand` 类，但经过逐行审计，**当前实现存在多处严重 bug**：

#### 1.2.1 `DummyHand::SetAngle()` 用错协议命令（致命）

```cpp
// dummy_robot.cpp:506-521
void DummyHand::SetAngle(float _angle) {
    ...
    uint8_t mode = 0x02;   // ← BUG：0x02 在电机端是 "Do Calibration"
    txHeader.StdId = nodeID << 7 | mode;
    ...
    CanSendMessage(get_can_ctx(hcan), canBuf, &txHeader);
}
```

**电机端** `cmd=0x02` **行为**（两套固件都一样）：


| 文件                                                                         | 处理                                                   |
| -------------------------------------------------------------------------- | ---------------------------------------------------- |
| `firmware_new/dummy-motor-fw/UserApp/protocols/interface_can.cpp:42-45`    | `encoderCalibrator.isTriggered = true;`（**触发编码器校准**） |
| `firmware/motor_fw_f103_gripper/UserApp/protocols/interface_can.cpp:38-41` | `encoderCalibrator.isTriggered = true;`（同样）          |


`0x02` 完全不读取 4 字节浮点 payload，**与** `_angle` **数值无关**。

**应当使用**：`0x05`（Set Position）或 `0x07`（Set Position with Velocity-Limit，**本期采用**）。

#### 1.2.2 `DummyHand::SetMaxCurrent()` 用错协议命令（致命）

```cpp
// dummy_robot.cpp:523-538
void DummyHand::SetMaxCurrent(float _val) {
    ...
    uint8_t mode = 0x01;   // ← BUG：0x01 是 "Enable Motor"，不是 "Set Current Limit"
    txHeader.StdId = nodeID << 7 | mode;
    ...
}
```

**电机端** `cmd=0x01` **行为**：

```cpp
// interface_can.cpp（两套固件一样）
case 0x01:  // Enable Motor
    motor.controller->requestMode = (*(uint32_t*) (RxData) == 1) ?
                                    Motor::MODE_COMMAND_VELOCITY : Motor::MODE_STOP;
    break;
```

`0x01` 不读 float payload（读 `uint32_t`，`uint32 1` = 进入速度模式 / `uint32 0` = 进入停止模式）。主控发 `float 1.0`（`0x3F800000`）时，电机端判 `!= 1` → 进入 STOP。结果：


| 调用                   | 旧实现行为（错误）                                   | 应有行为                 |
| -------------------- | ------------------------------------------- | -------------------- |
| `SetMaxCurrent(1.0)` | 进入 `MODE_STOP`（停机，`1.0f` 的 IEEE 754 位模式 `0x3F800000` ≠ `uint32 1`） | 设定额定电流 1.0A 写 EEPROM |
| `SetMaxCurrent(0)`   | 进入 `MODE_STOP`（停机，字节全 0 → `uint32 0` → false → STOP）               | 设定额定电流 0A（=失能）       |


**应当使用**：`0x12`（Set Current-Limit，**写 EEPROM**）。

#### 1.2.3 `DummyHand::SetEnable(true)` 后立刻进入 STOP 模式（致命）

```cpp
// dummy_robot.cpp:540-546
void DummyHand::SetEnable(bool _enable) {
    if (_enable)
        SetMaxCurrent(maxCurrent);   // ← 内部就是 0x01 错误触发
    else
        SetMaxCurrent(0);
}
```

`!START` → `DummyRobot::SetEnable(true)` → `hand->SetEnable(true)` → 发 `cmd=0x01, data=1.0` → 夹爪固件把 `1.0f`（`0x3F800000`）当 `uint32` 读 ≠ `1` → 切换到 `MODE_STOP`。

**后果**：电机在 STOP 模式下完全不动，夹爪无法响应任何位置指令，`!HAND_OPEN` 等动作完全没有效果。

**应当**：使能后**先发** `cmd=0x07`**（Set Position with Velocity-Limit）让电机切到位置模式**，或者在使能路径上额外发 `cmd=0x07, data=(0, 0)` 把模式切到位置模式（详见 §3.4）。

#### 1.2.4 完全没暴露速度/加速度/PID/DCE 的设置接口

当前 `DummyHand` 仅有 `SetAngle` / `SetMaxCurrent` / `SetEnable` / `Reboot` 四个方法，**没有**：

- `SetAcceleration(float)` —— 电机端 `cmd=0x14`
- `SetVelocityLimit(float)` —— 电机端 `cmd=0x13`
- `SetDceKp/Kv/Ki/Kd(int32_t)` —— 电机端 `cmd=0x17~0x1A`
- `SetEnableOnBoot(bool)` —— 电机端 `cmd=0x16`（掉电保持）
- `EraseConfigs()` —— 电机端 `cmd=0x7E`

**影响**：用户无法通过串口/ASCII 协议调整夹爪的运行表现（电机端初始值由 EEPROM 决定，烧录时锁定；运行期不可调）。

#### 1.2.5 没接位置回包（但本期有意为之）

当前 `DummyHand` 不参与 `UpdateJointAngles` 轮询、不处理 `cmd=0x23` 回包。

**本期维持**：按 §1.1 项目目标"不参与 IsMoving"+"不加角度查询"+"尽可能少反馈"，夹爪确实不需要回包位置。本文档 §3.3.2 解释这个设计的 CAN 总线节省量化。

## 2. 节点与硬件定位

### 2.1 节点表（最终态）

```
nodeID=0   → ALL 广播代理（占位）       CtrlStepMotor(0)
nodeID=1~6 → J1~J6 关节                CtrlStepMotor(1..6, reduction=50/30)
```

## 3. 功能需求详细

### 3.1 总览

夹爪的功能**只**包含三类：

```
┌─────────────────────────────────────────────────────────────┐
│  夹爪功能                                                     │
├─────────────────────────────────────────────────────────────┤
│  ① 位置控制（开/关/任意开度）        cmd 0x07（位置 + 限速）  │
│  ② 配置管理（电流/速度/加速度/PID/启动行为）                  │
│     速度限制    cmd 0x13                                       │
│     加速度限制    cmd 0x14                                     │
│     电流限制    cmd 0x12                                      │
│     PID/DCE Kp cmd 0x17                                      │
│     PID/DCE Kv cmd 0x18                                      │
│     PID/DCE Ki cmd 0x19                                      │
│     PID/DCE Kd cmd 0x1A                                      │
│     启动使能    cmd 0x16                                      │
│     擦除配置    cmd 0x7E                                      │
│  ③ 控制开关                                                    │
│     使能    cmd 0x01（切到位置模式，需先发 0x07）              │
│     失能    cmd 0x01（=0，电机切到 STOP）                       │
│     重启    cmd 0x7F                                          │
└─────────────────────────────────────────────────────────────┘
```

**夹爪不包含的功能**（与关节电机区分）：

| 功能                     | J1~J7 | 夹爪  | 理由                                 |
| ---------------------- | ----- | --- | ---------------------------------- |
| 角度查询（0x23 轮询）          | ✅     | ❌   | 按"最少反馈"原则；电机端 0x23 已实现可随时启用                       |
| 角度显示在 `currentJoints`  | ✅     | ❌   | "不参与 IsMoving"（即便回包也无法转 FINISH 状态） |
| 进入 `jointsStateFlag`   | ✅     | ❌   | 同上                                 |
| 进 OLED 行               | ✅     | ❌   | "不进 OLED"                          |
| 走 `ComputeSyncSpeeds`  | ✅     | ❌   | 同步抵达仅适用 J1~J7                      |
| `!STOP` 急停参与           | ✅     | ✅   | 夹爪**参与**急停（与 J1~J7 一致）                  |
| `!START`/`!DISABLE` 跟随 | ✅     | ✅   | 全局使能信号                             |


### 3.2 位置控制（核心功能）

#### 3.2.1 单位约定


| 字段                            | 单位                                                                                                        | 电机端含义                                |
| ----------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `set_angle(angle)` 入参 `angle` | **百分比开度** 0~100                                                                                           | 0 = 完全闭合（碰限位），100 = 完全张开（碰限位）        |
| `angle` 在主控与电机端换算             | `motorAngle = CAN` 字段 0 = 0 圈电机轴；`set_angle(100)` → `motorAngle=100` 圈电机轴                                 | 电机端 `cmd=0x07` 直接接收 float "圈数"       |
| reduction                     | 主控 `motorJ[]` 类有 `reduction` 字段，**DummyHand 不继承**                                                         | 夹爪电机带 `16:1` 减速箱|
| 物理限位                          | `-100 ≤ motorAngle ≤ 100` 圈（电机轴相对角，硬编码常量） | 撞电机端硬限位（电机堵转后电流限位到 `currentLimit`）   |


#### 3.2.2 软限位 vs 硬限位

夹爪使用与 35/42 电机同型号的 MT6816 14-bit 绝对编码器（固件 `firmware_new/dummy-motor-fw/Ctrl/Sensor/Encoder/mt6816_base.cpp`，与 35 关节电机该文件字节级相同），物理上有角度反馈能力：电机端能返回 `rectifiedAngle`（0~16383）、支持 `0x15` Home-Position 校准与 `0x23` 角度查询（参见 `firmware_new/dummy-motor-fw/UserApp/protocols/interface_can.cpp`）。

但本期按"最少反馈"原则：

- 主控侧**不**轮询 `0x23`，因此主控没有软限位检查
- 电机端 `softLimitPos/Neg` 本期**不**配置——物理限位由挡块实现，撞挡块后堵转、电流限位到 `currentLimit`
- **不**暴露夹爪单独 `apply_home_offset` / `cmd=0x15` 入口：归零/校准由 `!CALIBRATION` 全局任务统一处理



#### 3.2.3 开度映射

开度 0~100% 按线性映射到电机轴相对角：

```
motorAngle = ClosedMotorAngle + (OpenMotorAngle - ClosedMotorAngle) * (angle / 100.0f)
```

**本期默认值**（`DummyHand` 类的成员初值）：

```cpp
float ClosedMotorAngle = 0.0f;     // 开度 0% 对应的电机轴相对角
float OpenMotorAngle   = 100.0f;   // 开度 100% 对应的电机轴相对角
```

**首次使用对齐**：默认值假定"沿电机正方向 100 圈 = 张开物理限位"。实际安装后**用户需自行确认物理位置与默认值一致**；若不一致，由统一的 `!CALIBRATION` 任务处理（详见 `docs/CALIBRATION方案.md`，待编）。

**注意**：

- **不复刻** `firmware/ref_core_f405/.../StepHand::!HAND_ZERO`（参考实现通过 `cmd=0x15` Home-Position 校准让用户手动标定闭合位置）。本期**不暴露** `apply_home_offset`/`cmd=0x15` 的运行时接口给夹爪；夹爪归零/对齐是 `!CALIBRATION` 全局任务的一部分（含地轨/J1~J6/夹爪），不在夹爪单独 ASCII 命令中处理。
- **不暴露** `CmdHandO/C`（电流透传开/关）；夹爪开/关一律走位置模式（`!HAND_OPEN/CLOSE`），用户不需要手动施加电流。
- **不暴露** `set_current`（电流透传）Fibre 字段；夹爪用 `cmd=0x07` 一帧完成位置+速度控制，不需要单独的电流命令接口。

#### 3.2.5 ASCII 协议层命令

**UART4 协议层（无线通道）**：

按 PROJECT_GUIDANCE 既有规则，UART4 不暴露 `#SET_*`/`!REBOOT` 类危险操作。`!HAND_OPEN`/`!HAND_CLOSE`/`!HAND_SET`/`!HAND_DIS` 等运行时操作**允许**通过 UART4；`!HAND_ERASE`/`!HAND_ONBOOT`/`!HAND_VEL`/`!HAND_ACC`/`!HAND_I`/`!HAND_KP/KV/KI/KD` 等配置操作**禁止**通过 UART4。

**夹爪校准/归零**：本期**不**单独提供 `!HAND_ZERO`，校准/归零由统一 `!CALIBRATION` 全局任务处理（详见 `docs/CALIBRATION方案.md`，待编）。`!CALIBRATION` 作为全局危险操作，按既有规则**禁止**通过 UART4。

### 3.3 控制策略（与 J1~J7 区分的关键点）

#### 3.3.1 不加入角度查询（CAN 总线节省）

J1~J7 在 `UpdateJointAngles()` 100Hz 节奏下，每轴约 14 Hz 一次 `cmd=0x23` 轮询，**7 帧主控发 + 7 帧电机 ACK 回包 = 14 帧/100ms**（参见 `firmware_new/dummy-motor-fw/UserApp/protocols/interface_can.cpp:cmd=0x23` 与 §4.2）。

夹爪按 §1.1 要求**不**进入轮询，**节省 2 帧/100ms**（1 主控发 + 1 电机回包）。注意 1 Mbps 总线下 14 帧/100ms 利用率仅约 0.9%，节省的实际带宽意义极小；真正价值在**逻辑同构**（夹爪独立于 `IsMoving()`，避免对全局状态机造成干扰），不在带宽本身。

#### 3.3.2 不参与 IsMoving

`IsMoving()` 当前实现（`dummy_robot.cpp:478`）：

```cpp
bool DummyRobot::IsMoving() {
    return (jointsStateFlag & 0b11111110) != 0b11111110;
}
```

`jointsStateFlag` 是 8 位 bit 标记（`uint8_t`，物理上只有 bit0~bit7）：bit0 闲置，bit1~bit6 = J1~J6，bit7 = J7/地轨。夹爪按 §1.1 / `PROJECT_GUIDANCE §1.1` "最低级别、不参与 IsMoving" 要求，**不进入** `jointsStateFlag`（无对应 bit，物理上也不可能新增 bit8）。

**含义**：用户发 `>j1,...,j6,j7,speed` 之后，`IsMoving()` 只看 J1~J7 是否到位，**不管夹爪是否到位**。这意味着：

- 夹爪独立于臂同步逻辑：用户可以发 `!HAND_OPEN` 后立即发 `>...` 让臂走，不必等夹爪到位
- 夹爪完成后不会触发任何回调/回显给串口（节省总线）
- `!HAND_OPEN` 之后用户应自行 `osDelay` 或轮询 `#GET_HAND_STATE`（本期不实现）确认到位

#### 3.3.3 不进 OLED

当前 OLED 代码（`firmware_new/dummy-ref-core-fw/UserApp/main.cpp:102-107`）：

```cpp
oled.setCursor(0, 30);
oled.printf(">%3d|%3d|%3d|%3d|%3d|%3d|", ...);  // 只显示 J1~J6
oled.setCursor(17, 40);
oled.printf("rail:%.2fmm", dummy.currentRailPos);   // 只显示 Rail
```

第二行已有 rail 显示，**夹爪位置不上 OLED**（保持 7 行字符容量留给 J1~J6 + Rail）。

OLED 状态字符 `buf[7]`（`main.cpp:117-118`）当前是 8 个 char，覆盖 J1~J7 状态（bit1~bit7）；夹爪不需要这个位，buffer 不变。

#### 3.3.4 `!STOP` 软停逻辑（夹爪参与急停）

**结论（2026-10-02 用户明确决策）**：夹爪**参与** `!STOP` 软停，与 J1~J7 同级别响应。

**含义**：

- 主控 `EmergencyStop()` 路径发 ALL 广播 `cmd=0x09`（`motorJ[ALL]->BroadcastEStop()`）时，**夹爪也要响应**该广播命令（电机端 `case 0x09:` 无差别执行 `requestMode = MODE_STOP + SetBrake(true)`）。
- 因此**不**需要、也**不应当**在夹爪固件 `cmd=0x09` 处理器前加 `#if MOTOR_TYPE == 8 ... #endif` 跳过块（**删除该方向**）。
- 夹爪主控侧**不**主动额外发任何 `cmd=0x09`（与 J1~J7 一致）；由 ALL 广播统一覆盖。

**文档立场**：`!STOP` 软停机制本身（含 ALL 广播发射、`?` 路由重构路径）**已迁移至** `docs/STOP软停机制方案.md`，**本文档不重复**。夹爪在 `!STOP` 路径上的具体副作用（`SetBrake(true)` 后电机可手动掰动、急停后 `jointsStateFlag` 的位运算）由 stop 文档统一描述，夹爪无需特殊处理。

**反例（之前错误设计，已废弃）**：

- ❌ "夹爪固件 `cmd=0x09` 处理器当前无 `#if MOTOR_TYPE == 8` 跳过，是未来 `!STOP` 重构的雷区" —— **删除**。夹爪就是要参与急停，不应跳过。
- ❌ "夹爪 `!STOP` 不下发 `cmd=0x09`" —— **删除**。夹爪通过 ALL 广播与 J1~J7 同步响应，不需要单独的差异化逻辑。

### 3.4 使能顺序重构（关键修复）

旧 `SetEnable(true)` → `SetMaxCurrent(maxCurrent)` → 发 `cmd=0x01, data=1.0` → 进入 STOP 模式（**BUG**：`1.0f` 字节不等于 `uint32 1`，电机端判 false → STOP）。

**新实现**（分两步）：

```cpp
void DummyHand::SetEnable(bool _enable) {
    if (_enable) {
        // 发 cmd=0x07 设当前位置（电机实际不动）+ 期望速度，强制切到位置模式
        SetAngleWithVelocityLimit(currentMotorAngle, currentVelocityLimit);
        // 注意：旧实现曾计划在此补一步 cmd=0x01 使能，但分析后发现 cmd=0x01 会导致电机进 STOP（类型错配），
        //       因此新实现直接去掉 cmd=0x01，仅用 cmd=0x07 一帧完成"切模式 + 设位置"，
        //       主控端记录"已使能"状态即可。
        isEnabled = true;
    } else {
        // 失能：发 cmd=0x01, data=0 → 切到 MODE_STOP
        uint8_t mode = 0x01;
        txHeader.StdId = nodeID << 7 | mode;
        uint32_t val = 0;
        auto* b = (unsigned char*) &val;
        for (int i = 0; i < 4; i++) canBuf[i] = *(b + i);
        CanSendMessage(get_can_ctx(hcan), canBuf, &txHeader);
        isEnabled = false;
    }
}
```

**核心要点**

- **使能路径**只发 `cmd=0x07, pos=currentMotorAngle, vel=velocityLimit` 一帧：电机切到位置模式并按 velocityLimit 限速（电机端 `cmd=0x07` 会自动 `SetCtrlMode(MODE_COMMAND_POSITION)`，无需先发 `cmd=0x01` 切模式）
- 当前位置 `currentMotorAngle` 默认 0（闭合位置）；上电首次 `!START` 后**会保持闭合**，不会乱跳
- **失能路径**发 `cmd=0x01, data=uint32(0)` 切到 `MODE_STOP`：电机可手动掰动，扭矩释放
- 主控记录 `isEnabled` 状态用于 ASCII 协议查询（`#GET_HAND_STATE` 本期不实现）

> ⚠️ **本节是关键修复**：当前 `DummyHand::SetEnable` 完全不可用，必须重写。本期方案由 `cmd=0x07`（位置+限速）一帧直接切到位置模式，不走「`cmd=0x01` 先使能、再二次偏转切模式」的两步路径。

### 4.1.1 ACK 控制方案决策（v2026-10-02）

**问题**：电机端 `cmd=0x07`（Set Position with Velocity-Limit）当前**无条件**发 0x23 ACK 回包（`firmware_new/dummy-motor-fw/UserApp/protocols/interface_can.cpp`），与 `cmd=0x05/0x06` 已有的"按 `_data[4]` 控制 ACK"模式**不一致**。

后果：

- 夹爪按"最少反馈"原则不需要 ACK，但每次 `!HAND_OPEN/CLOSE/SET` / `!START` 仍会触发 1 帧 ACK，**占用 CAN 总线 + 主控 RX FIFO**
- `CtrlStepMotor::SetPositionWithVelocityLimit`（`ctrl_step.cpp:114-126`）未显式设置 `canBuf[4]`，依赖成员变量残留——是潜在隐患（电机端无条件发 ACK 时未触发）

**决策（采纳方案 A + 同期修 J1~J7 潜在 bug）**：

1. **电机端** `cmd=0x07` **加 ACK 控制**（`interface_can.cpp:130`）：把无条件 ACK 包到 `if (_data[4])` 块内，与 `cmd=0x05/0x06` 对齐
2. **J1~J7 显式** `canBuf[4] = 1`（`ctrl_step.cpp:114-126`）：修复 `SetPositionWithVelocityLimit` 的潜在 bug，保持 J1~J7 现有 ACK 行为不变
3. **夹爪显式** `canBuf[4] = 0`（新 `DummyHand::SetAngleWithVelocityLimit`，`dummy_robot.cpp`）：夹爪稳态零 ACK 帧，符合"最少反馈"原则

**收益**：夹爪稳态 CAN 帧从"0 + 切换时 +1 ACK"降为**完全 0**；J1~J7 行为不变；跨模式协议层对齐。

**改动清单**：


| 文件                                                                       | 行                                        | 改动                                                     |
| ------------------------------------------------------------------------ | ---------------------------------------- | ------------------------------------------------------ |
| `firmware_new/dummy-motor-fw/UserApp/protocols/interface_can.cpp`        | `cmd=0x07` 段                             | 无条件 ACK → `if (_data[4])` 条件 ACK（与 `cmd=0x05/0x06` 对齐） |
| `firmware_new/dummy-ref-core-fw/Robot/actuators/ctrl_step/ctrl_step.cpp` | `SetPositionWithVelocityLimit` (114-126) | 末尾 `canBuf[4] = 1; // Need ACK`                        |
| `firmware_new/dummy-ref-core-fw/Robot/instances/dummy_robot.cpp`         | 新 `DummyHand::SetAngleWithVelocityLimit` | 末尾 `canBuf[4] = 0; // No ACK for gripper`              |


**跨模块同步烧录**：本期本来就要烧夹爪固件 + 主控固件，**无额外烧录代价**。
