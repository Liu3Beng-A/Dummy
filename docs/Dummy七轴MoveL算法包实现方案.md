# Dummy 七轴 MoveL 算法包实现方案

版本：讨论稿 v1.1；日期：2026年10月11日。新增耗时与延迟评估、上位机/主控逆解切换。本文用于确认实现范围，尚未实现算法包、修改运动代码或执行实机动作；仅在聊天工作目录运行了不连接设备的算子微基准。

目标是在独立 Dummy 上位机内提供通用笛卡尔运动入口，并可选择两个逆解后端：上位机算法统一处理六轴机械臂与地轨，通过现有串口 MoveJ 输出；主控后端发送原生MoveL，保留当前六轴逆解行为。运动页、拖发、示教、手柄等 MoveL 场景遵守同一后端选择。上位机后端第一阶段以现有固件验证协同运动和近似直线跟随，实际轨迹精度通过实机测量验收。

## 1 已确认的需求与阶段边界

| 项目 | 本次约定 |

| 算法复用 | 上位机独立包，不依赖手柄、Qt、串口或三维界面 |
| 逆解切换 | 新增“上位机七轴逆解 / 主控六轴逆解”选择；仅空闲切换，细节见第14节 |
| 本轮工作 | 整理方案及项目记录，等待用户确认后再实现 |
| 首期实现范围 | 七轴模型、逆解、直线/在线规划、反馈估计、统一执行器、现有入口适配、工具变换数据结构、离线验证 |
| 后续工具设置 | 提供工具XYZ及姿态偏移设置；首期预留完整变换与工具版本，暂不扩展完整工具管理界面 |

## 2 已核实的项目基础

- 上位机：Python 3.11环境，PySide6、pyserial、pygame；当前requirements没有NumPy、SciPy。
- 现有MoveJ格式：`>J1,J2,J3,J4,J5,J6,rail_mm,speed`，正文最长63字节。七轴已有同步到达规划；速度档位1～100，100对应电机轴30r/s，并非末端mm/s。
- 固件MoveL只求终点六轴逆解，再调用MoveJ并保持地轨当前位置，没有笛卡尔逐点插补。
- 当前SEQ、TRJ等待本段运动完成，INT受理后允许新目标覆盖当前目标；TRJ不能直接作为连续轨迹接口使用。
- 固件队列16项；INT下新目标也先经过队列，不能把它理解为设备侧只保留最新值的邮箱。
- `GETJPOS`返回七轴缓存，无电机采样时间戳。运动任务名义200Hz、逐节点轮询七轴，正常轮转名义约35ms，另有完成查询门控。30/50Hz串口响应不等于同频七轴同步采样。
- 上位机正解已经按固件六轴几何实现，但输出为法兰XYZ/ABC并忽略地轨；新核心需保留完整旋转矩阵，避免用欧拉角往返作为内部表示。
- 当前显示模型地轨沿+Y；显示侧有62.3mm高度补偿和J4/J5符号映射，这些显示转换不能直接当作运动学参数。
- 现有手柄默认工具长度114mm，只是现有配置值；不能未经几何核对就认定它等于本次指定的夹持中心。URDF指爪关节原点的58mm也不等于指尖/夹持中心偏移。

主要源码依据位于 `E:/Dummy-code/Dummy上位机/app/` 与 `E:/Dummy-code/firmware_new/dummy-ref-core-fw/`。详细定位见第12节。

## 3 算法包分层与对外接口

建议包名 `dummy_motion`，放在 `E:/Dummy-code/Dummy上位机/dummy_motion/`。它是纯计算Python包，可直接导入，也预留独立打包能力。现有应用通过一个适配执行器调用。

| 模块 | 职责 |
|---|---|
| `types.py` | 位姿、关节状态、限制、请求、求解结果、轨迹及状态枚举 |
| `model.py` | 固件几何、关节轴、地轨模型、正解与6×7雅可比 |
| `frames.py` | 世界/基座/法兰/TCP变换及协议单位转换 |
| `ik.py` | 有界阻尼最小二乘迭代、种子管理、残差核验 |
| `rail_policy.py` | 自动协同偏好、固定地轨约束、后续指定地轨接口 |
| `path.py` | 直线位置路径、姿态插值、自适应几何采样 |
| `planner.py` | 在线推进、时间缩放、七轴位置/速度/加速度约束 |
| `feedback.py` | 回读质量、短时状态估计、跟随误差及超前量管理 |
| `validation.py` | 可行性、路径/量化检查与结构化诊断 |

应用侧新增 `app/core/cartesian_session.py`，负责Qt生命周期、控制权、串口发送、回执和示教完成事件；增加后端适配层，由 `PcSevenAxisBackend` 与 `FirmwareMoveLBackend` 处理同一笛卡尔请求。前者调用算法包并发送MoveJ，后者做必要坐标转换后发送原生MoveL，不偷偷运行上位机IK。算法包不访问UI、不发送命令、不自行切换设备模式。

实时计算由一个专用工作线程串行拥有规划状态，使用单调时钟与实际dt；Qt主线程只提交不可变输入/回读快照和显示结果。每个会话只保留最新待处理在线目标，离线整线预检使用可取消任务；所有返回值携带会话代次，主线程丢弃已取消任务结果。不得在串口回调中直接运行整线IK，也不通过增加工作线程同时修改同一个规划器。最初以独立线程隔离为主，若性能分析确认Python计算影响UI，再评估进程隔离，不预先增加跨进程复杂度。

建议公开接口：

```python
model.fk(q, tool, frame="world") -> Pose
solver.solve_pose(target, seed, constraints, rail_policy) -> IKResult
planner.plan_line(start_state, target, motion_limits, tool) -> PlanResult
session.update_feedback(sample) -> FeedbackQuality
session.step(dt, request) -> StepResult
```

`solve_pose`解决几何问题，不代表可瞬间执行；`plan_line`输出经过验证的连续分支及名义时间安排；`step`结合上次规划状态、实际回读及本周期限制产生可执行候选目标。算法中的session是纯状态对象，与Qt适配器区分命名。

输入必须携带单位/坐标系、工具ID和版本。内部关节顺序统一 `[q1,q2,q3,q4,q5,q6,r]`，前六项rad、地轨m；UI和串口边界转换为度、mm。禁止用一个无单位列表跨层传递位姿或关节。

输出除七轴目标外，包含：位置/姿态残差、路径进度、降速系数、受限轴、求解耗时、反馈质量、计划代次及状态。建议状态包括 `OK`、`SLOWED`、`NO_LOCAL_SOLUTION`、`LIMIT_BLOCKED`、`FEEDBACK_STALE`、`BUDGET_EXCEEDED`、`INVALID_INPUT`。局部求解失败不能直接宣称目标在几何上不可达。

## 4 坐标系和默认TCP

使用统一变换：

`T_world_tcp = T_world_rail0 · T_rail(r) · T_mount · T_arm_flange(q1…q6) · T_flange_grip · T_grip_tool`

- 世界坐标固定在地轨/工作台参考上；地轨运动不会带着世界坐标走。
- 地轨位移方向、安装变换和零位参考分开配置，名义方向使用现有+Y，实机核对后固化。
- `T_flange_grip`定义两指有效夹持区域中心。对称开合模型下该中心不随开度变化；其沿手指长度方向的位置须依据实际夹持区域/CAD尺寸确定。
- 首期新增工具偏移 `T_grip_tool` 为单位变换；未来工具设置及标定都修改这个统一模型，不在各入口重复加长度。
- 114mm可作为需要核对的候选名义值，若缺乏尺寸证据，显示为“名义TCP”并保留待核对状态，不称为已标定。
- 内部姿态使用旋转矩阵/四元数；ABC仅在原有UI、协议解析和兼容导入时使用，保持与固件一致的RPY定义。
- J4等有明确有限行程，选择等价角时同时检查真实限位与上一解，不能统一折返到±180°。

现有手柄工具长度配置导入为明确的旧工具配置，避免把用户自定义偏移静默覆盖。切换到新“夹持中心”配置通过显式工具选择完成。

## 5 七轴逆解与地轨自动协同

### 5.1 求解方法

建议使用NumPy做小型矩阵运算，SciPy提供有界线性最小二乘与旋转工具；实施时锁定兼容当前Python环境且通过回归的版本，不直接套用文档站最新版本号。

在每次线性化处，构造世界坐标TCP误差：位置差和 `log(R_target · R_current.T)` 的旋转向量。使用同一世界表达的雅可比：转动轴列为 `axis × (p_tcp-p_axis)` 与`axis`；地轨列为 `[rail_direction, 0, 0, 0]`（前三项为方向向量，后三项为零）。

令 `dq = D*u`，其中D按各轴速度/行程尺度归一化；最小化：

`||W_task (J D u - e)||² + lambda² ||u||² + mu² ||W_preference (u-u_preference)||²`

并对u施加本轮允许的上下界。位置和姿态残差分别按容差缩放，不能把米、弧度、地轨位移直接不加区分地相加。

具体软边界与速度上限通过已验证模型参数换算：J1～J5减速比50、J6减速比30、地轨5mm/电机圈；电机轴30r/s分别对应理论216°/s、360°/s与150mm/s上限，运行配置可以更低。加速度也按相同传动关系转换，并依据本机当前有效设置取保守值，不因为理论上限存在就直接用满速。

实现使用 `scipy.optimize.lsq_linear` 的小规模稠密有界求解，首选BVLS与exact线性代数，离线比较性能后再确定配置。内部线性问题的收敛不代表完整非线性IK成功；每步还需正解核验与回溯。[SciPy有界最小二乘接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.lsq_linear.html)

### 5.2 约束与连续性

1. 位置边界使用固件六轴及地轨真实限位，测量数据不截断。算法可设更小的运行软边界，但不得扩大固件限位。
2. `solve_pose`使用位置边界与数值信赖步长；在线`step`额外将速度、加速度转为增量上下界。速度/加速度从已知电机能力和用户运行配置转换，不以URDF默认速度替代实物值。
3. 上一有效关节解是首选种子。新会话用可信且稳定的七轴回读初始化；运行中保持连续解，不反复用滞后的回读重置目标。
4. 接近奇异时按归一化雅可比奇异值增大阻尼、降低路径推进；满足不了误差容差则拒绝候选解。
5. 每次候选解通过正解复核，再作步长回溯。不能“先任意求解、最后把超限关节裁剪”。
6. 只在离线预检或静止初始化时尝试有限多种子；在线失败不突然切到遥远的肘形或腕部构型。
7. 目标与姿态精度是接受条件。若次级偏好妨碍目标，先减弱偏好；仍不满足时缩小推进量或返回受限状态，不能牺牲TCP路径换取更好看的构型。

初始预算建议：在线每周期最多8次非线性修正、每次最多5次回溯；单个有界线性求解也设迭代上限。以50Hz周期为目标，计算部分争取P99低于10ms，最终值通过性能测试确定。Python/SciPy不是硬实时系统；超时结果在返回后丢弃，不声称能在任意矩阵调用中强制中断。

### 5.3 地轨参与规则

采用连续代价与软区间，避免“超过一个阈值立即切换模式”：

- 机械臂构型余量充足、目标变化较小时，增加地轨运动代价，使六轴承担主要调整。
- 随着机械臂偏离适合工作的构型区域、接近关节边界或可操作性下降，逐渐减小地轨运动代价，并增强改善构型的偏好。
- 地轨接近端部时增加端部代价并收紧可用速度，转由六轴承担可行部分。
- 地轨速度/加速度独立限幅，权重随时间平滑，使用滞回避免临界区反复切换。
- 所有目标不再变化且剩余跟随完成后，次级构型重排关闭；不为了回中继续移动。

代价权重在仿真中调参；首版不承诺固定毫米阈值或固定分配比例。中心偏好也不是强迫所有关节回到行程中点，应结合可用构型区域及上一姿态。

包内预留 `RailPolicy.AUTO / LOCKED / PRESCRIBED` 的模型语义。首期产品默认AUTO，LOCKED用于离线对照及模型验证；PRESCRIBED对应后续“锁TCP移轨”，首期不实现该产品功能或返回虚假的成功结果。

## 6 直线规划与在线控制

本节描述上位机后端；主控后端保留现有单目标/在线MoveL发送方式，不因同一套界面而宣称具备这里的插补能力。

### 6.1 运动页和示教直线

- 位置路径使用 `p(s)=p0+s*(p1-p0)`；姿态使用最短旋转插值，位置与姿态共用路径进度s。保持姿态的平移是其特例；纯旋转单独处理零平移长度。
- 使用四元数SLERP而非直接线性插值ABC，并处理q与−q等价及180°附近的连续选择。[SciPy姿态插值说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Slerp.html)
- 起点来自稳定实际状态；执行前核验起点没有因其他操作漂移，否则重新预检。
- 先检查整条路径的连续逆解分支，再开始发送；首期不自动绕路改变用户要求的直线。
- 几何预检从不大于2mm/1°的间隔起步，在高曲率、限位和姿态变化区域继续细分，并检查段内中点。该检查证明规划采样的质量，不证明实物段内运动一定如此。
- 对连续关节路径做前后向速度/加速度约束，生成名义时间安排；执行时按反馈和实际发送能力统一缩放s的推进速度，保持位置/姿态同步。

### 6.2 手柄和拖发

手柄产生TCP速度/增量，拖发产生持续变化的目标位姿；它们都进入同一个在线规划器。每周期只推进可行的小段，并限制目标相对测量/估计的超前量。回中停止新增路径并平滑结束剩余跟随；不能无限积累操作者已经撤回的输入。

### 6.3 发送频率与速度的耦合

建议规划周期目标50Hz；GETJPOS先以已实测的30Hz为基线，提供50Hz实验选项。MoveJ发送先沿用现有手柄100ms间隔作为对照，再测试20Hz及更高频率；30Hz回读通过不代表同频MoveJ已通过。

实际发送点必须满足段长、七轴变化和路径偏差要求，不能直接丢掉中间规划点后仍宣称原精度成立。例如规定发送点间隔最多2mm且发送10Hz时，软件路径推进上限也只能约20mm/s；要更快，就需要验证更长段的误差或更高发送频率。现有200mm/s手柄参数可保留为请求上限，实际推进受到这些约束时必须明确显示降速。

较远的目标不一次灌入设备16项队列。上位机保留待写出的最新可行目标和有限前瞻；已写出的指令保留不可变回执记录，避免延迟回执回退状态。

## 7 反馈估计与三维显示

分别保存 `q_measured`、`q_estimated`、`q_reference` 和 `q_last_written`。收到GETJPOS时记本机接收时间、对应请求实际写出时间和连接代次，更新观测；不能把本机时间当作电机采样时刻。

首期估计器采用保守的短时速度滤波/预测和限幅创新修正，不使用复杂动力学模型宣称高精度。相同读数不直接当作零速；跨轴非同步读数也不能作为精确瞬时雅可比速度。缺乏设备时间戳时降低反馈修正增益，优先依靠规划限速与跟随量限制。

反馈用于控制路径超前量、适当减速及连续修正状态；真实跟随误差持续过大时暂停推进。若已下发目标仍可能继续运动，暂停发令不等于已停止，超时/故障需要走现有STOP状态流程，不能仅显示“已停”。

显示侧保留真实回读模型；需要更流畅时可增加明确标注的插值/估计显示。规划目标、估计状态与测量状态不得混称“实际”。TCP由编码器正解得到，无法直接发现工具装夹、连杆几何或弹性变形误差。

比较30/50Hz时记录请求往返延迟、回包间隔、P95/P99抖动、超时、发送积压、计算耗时和跟随偏差。不将重复静止数值当作过期证据。需要严格反馈时序时，再单独讨论固件时间戳/各轴年龄字段。

## 8 串口执行器与任务完成语义

本节描述上位机七轴后端；主控后端保留现有SEQ/INT/TRJ及MOVEL回执语义，按第14节独立适配。逆解后端与固件命令模式是两个不同设置。

### 8.1 统一执行会话

采用一段上位机笛卡尔任务对应多条固件MoveJ：

`空闲 → 预检 → 模式就绪 → 运行 → 末点等待 → 完成`

以及独立的暂停、取消、保护和失败状态。上位机任务ID、采样序号、固件运动ID分开记录。

开始执行时由适配器确认设备空闲、使能和控制权，按任务入口管理INT模式并等待模式回执；不能运动中切模式，也不能把发送了模式指令当作已经生效。开始动作前界面明确显示新MoveL使用INT执行，任务结束保留当前模式并显示，不暗中恢复。

普通单点MoveJ保持原使用方式；含新MoveL的混合示教序列由上位机顺序管理。该会话内MoveJ点也等实际完成后再推进下一点，不依赖原先只接受SEQ的示教回执逻辑。

### 8.2 回执及末点确认

- 连续轨迹样本通过MOVEJ回执识别；初始化MoveJ、普通关节点和轨迹采样必须按任务身份区分，不能按命令名混用。
- 实际写出后释放发送槽，受理回执独立跟踪；不恢复逐条等待accepted才发下一点的门禁。
- `queued/accepted`仅证明排队/受理，不能当作轨迹完成。
- 最后一个目标写出后停止推进，使用匹配末点运动ID的`#MOTION_STATUS`确认 `phase=3`（COMPLETED），并检查七轴/TCP误差与稳定窗口，然后完成上位机任务。
- 状态查询低频按需进行，不随50Hz规划查询；反馈/状态过期时不能完成任务。
- 连接切换、STOP或任务取消使旧代次失效；串口写前再次验证，禁止旧目标稍后写出。
- 协议queued没有客户端token；缺失/异常回执造成映射不能证明时暂停该任务并报告，不能把后一个编号猜给前一个目标。

### 8.3 字符串精度和执行限制

优先沿用三位小数并去掉尾零，检查63字节限制；必要时按明确精度策略尝试更紧凑表达，对最终量化后的七轴目标重新正解核验。量化使误差超标时返回错误，不默默降低精度或截断字符串。去重依据实际发送内容，但完整规划目标继续保留。

固件当前MoveJ收到目标后再次按自身位置/加速度缓存规划，且INT运动中更新目标时电机已有速度。因此，上位机名义时间和关节参考约束不能视为实物严格执行保证。需要仿真回放与实机一起验证，不能仅检验两个关节目标之间的线性插值。

## 10 与标定同期的固定TCP移轨功能

用户已提出此功能，本期仅设计接口。建议默认锁定完整TCP位姿，即XYZ和朝向都不变；用户只要求XYZ的模式可后续扩展，但需另设姿态偏好，首版不让姿态自由漂移。

操作流程：停稳后点击“锁定TCP”→从可信七轴回读计算并保存世界TCP位姿→操作者指定地轨位置或正反向速度→规划器缓慢改变r，同时求六轴补偿→统一发送七轴MoveJ。

给定地轨位置r时，六轴目标为：

`T_arm_flange_target = inverse(T_world_base(r)) · T_world_tcp_locked · inverse(T_flange_tcp)`

因此可复用同一模型和IK，把地轨变量改为已指定约束。速度级关系是 `J_arm*qdot_arm = -J_rail*rdot`，是否有满足限位和速度约束的解决定可移行程。

该模式与AUTO互斥：自动模式由算法选择地轨，锁TCP移轨由操作者指定地轨、六轴补偿。固定变量从有界求解变量中消去，避免向要求严格上下界的求解器传入相等上下界。

必须沿整个地轨路径连续预检或前瞻，并根据六轴补偿能力限制地轨速度。接近边界时协调降速/停止推进；不能地轨先动、六轴随后补偿，也不能六轴失败后继续单独移动地轨。

数学复用较直接，但并非所有地轨位置都有解，也不能仅靠现有MoveJ保证实物TCP毫无偏移。模型、工具偏移和执行跟随都会影响结果；以正解残差及独立实物观察验证。这个功能可用于检查地轨模型和标定结果，但自身不是完成标定的证据。

TCP标定继续按已记录的固定地轨、同点多姿态方案执行；其功能与固件`!CALIBRATION`不同。完整工具偏移设置、标定界面及锁TCP移轨作为同一后续阶段。

## 11 实施顺序与验收

### 阶段A 纯算法和模型核对

建立包、完整变换、FK与雅可比；核对固件几何、符号、默认夹持中心尺寸。运行FK已知姿态对照、解析雅可比与有限差分对照、坐标变换往返、工具偏移只应用一次、地轨方向/单位和角度等价测试。暂不接串口。

### 阶段B 逆解和路径验证

实现有界求解、自动地轨代价及在线/直线路径。以有效关节状态正解生成可达目标测试IK闭环；覆盖不同地轨位置、J4大角度、姿态跨±180°、纯旋转、腕部奇异、接近行程端部、路径中间失败及目标回中。验证小幅移动不使地轨反复摆动、长距离平滑接入、末端停下后无自主重排。

建议离线初始目标：IK位置残差≤0.1mm、姿态残差≤0.05°；发送量化后≤0.2mm、≤0.1°。这些是软件数值门槛，不是实机精度承诺。连续规划与最终发送采样都检查位置、速度、加速度约束；不在验证器中重复调用同一求解公式当作独立证据。

### 阶段C 假串口和全部入口接入

实现统一执行会话及存储迁移，覆盖运动页、手柄、拖发、示教混排及终端。验证实际写出才释放槽、延迟/乱序/缺失回执、末点受理不能提前完成、STOP与旧代次取消、串口重连、模式不符和队列积压。保持现有后台控制、释放、夹爪和主动STOP语义，不扩大改动为重新设计所有交互。

### 阶段D 实机逐级验证

1. 固定地轨低速六轴TCP运动，核验方向、TCP定义和姿态。
2. 开启AUTO，先小位移再沿轨长距离，观察地轨参与平滑度。
3. 先保持30Hz回读，单独改变MoveJ发送频率和末端请求速度。
4. 再以相同运动对照50Hz回读，避免同时改变多个变量。
5. 用独立标尺、固定指针或相机等观察直线偏差；编码器FK自洽不能单独证明真实直线精度。

每组报告轨迹误差、速度波动、求解耗时、时序、超时/回执匹配和停止行为。实机路径误差目标在首轮测量后与用户确定；不把达到数值残差等同于实机通过。

阶段A～D验收后，再实施工具偏移设置、TCP标定和固定TCP移轨功能。首期不做打包发布或Git提交，除非用户另行要求。

## 13 计算开销与端到端延迟评估

### 13.1 本机算子微基准

2026年10月11日，在当前电脑Python 3.11.7、NumPy 2.4.6、SciPy 1.17.1环境运行只读模型/纯计算基准，未加载Qt、连接串口或调用机器人。先预热50次，再采样；FK 2000次，单次线性求解各1500次，组合工作负载各500次。

| 测量项目 | 中位数 | P99 |
|---|---:|---:|
| 现有六轴正解 | 0.038ms | 0.083ms |
| 普通6×7问题的有界求解 | 0.037ms | 0.170ms |
| 约束激活问题的有界求解 | 0.246ms | 0.788ms |
| 3轮正解+SVD+约束求解 | 0.937ms | 1.887ms |
| 8轮正解+SVD+约束求解 | 2.681ms | 4.265ms |
| 8轮正解+SVD+近奇异矩阵约束求解 | 2.546ms | 3.973ms |

微基准中的雅可比为构造矩阵，3/8轮是固定次数运算，不是完整逆解迭代收敛测试。没有包含真实雅可比构建、约束组装、姿态误差/回溯、线程调度、UI、通信或实机运动，普通问题直接得到无约束可行解时内部迭代为0。近奇异组合的本轮最大耗时为7.384ms，不能据此给出将来最大耗时保证。

据此给完整在线step的初始工程预估：常规小步约1～5ms，较复杂约束场景约5～10ms；这不是已实现算法的实测。50Hz对应20ms周期，有实现余地；仍以完整实现P99/超时处理验收。离线整线预检按采样点数累积，不能套用单周期耗时，例如200个点、每点1～5ms就约0.2～1s，尚不含额外细分与多种子。

### 13.2 USB与现有调度开销

已核对原生STM32 USB CDC：数据端点Bulk、最大包64B，`CDC_SET_LINE_CODING`为空，`CDC_GET_LINE_CODING`报告115200。此处115200不限制USB链路为115200bit/s；USB转UART适配器是另一种链路，不能混用这一结论。

固件USB接收用信号量唤醒任务，并在当前包解析结束后重开接收；运动控制任务名义5ms周期。上位机发送线程被队列唤醒，`queue.get(timeout=0.1)`不意味着每条命令固定等待100ms；真正的现有100ms节流在手柄send_interval。接收线程每轮调用10ms等待，名义上额外带来0～10ms察觉等待，Windows调度可能更长。

以下仅作原生USB、系统负载正常、INT无积压时的测试预算，均非实测，也不是最大保证：

| 环节或口径 | 初始预算/估计 | 说明 |
|---|---|---|
| 完整在线step计算 | 常规1～5ms，复杂5～10ms | 由算子基准外推，待完整实现测量 |
| PC写出到主控解析 | 毫秒级，暂按1～10ms预算 | 驱动、USB任务和输出回执拥塞会改变它 |
| 主控发布到电机目标下发 | 暂按1～10ms预算 | 包含等待5ms控制节拍、CAN排队；重试/故障会明显更长 |
| 50Hz规划及50Hz发令时，输入到电机收到新目标 | 约20～60ms量级 | 假定高频发令已验证，含规划/发送节拍等待；不等于机械响应/到位时间 |
| 反馈用于修正后再形成下一次有效输出 | 约40～100ms量级 | 还涉及逐轴缓存年龄、GETJPOS相位、接收线程和下一次发令 |

若发令仍为现有10Hz，单发令节拍就额外等待0～100ms、均匀相位下平均约50ms；只提高GETJPOS到50Hz不会消除它。当前手柄另有60ms速度平滑参数，这是输入滤波时间尺度，不应简单当作固定60ms传输延迟相加。实物开始明显移动、达到速度和最终到位还取决于电机加速度、限流、负载和机械间隙。

USB Bulk没有保留带宽，因此不能仅用“USB很快”承诺确定延迟。[Microsoft USB带宽说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-bandwidth-allocation)

### 13.3 可实现性判断与验证点

七轴局部逆解与50Hz规划在当前电脑上有合理算力基础，USB命令数据量也较小，例如50Hz×64B约3.2kB/s（不含回读、回执和USB开销）。主要尚未验证的是高频MoveJ重规划后的实物轨迹连续性、七轴跟随一致性及反馈时间信息，而非仅是矩阵运算量。

下一步在离线完整step中测P50/P95/P99/超时，再通过实验记录目标生成、规划结束、实际write、queued/accepted、GETJPOS到达时间；这些时间只测PC可见链路。要知道电机真实接收/机械响应时间，需使用现有固件分发诊断与可对齐时基，必要时再加入专门设备时间戳或外部观测，不能把accepted当作电机已执行。

## 14 上位机逆解与主控逆解切换

建议新增独立于SEQ/INT/TRJ的“MoveL逆解来源”设置：

| 能力 | 上位机七轴逆解 | 主控六轴逆解 |
|---|---|---|
| 串口输出 | `>J1…J6,rail,speed` | `@X,Y,Z,A,B,C,speed` |
| 逆解位置 | PC调用dummy_motion | 主控现有PlanMoveL |
| 地轨 | 自动协同 | 按现有固件保持当前位置 |
| 直线路径 | PC插补及可行性检查 | 当前固件终点逆解，不能标成严格直线 |
| TCP坐标转换 | 统一世界TCP接口后求解七轴 | 同一世界TCP先换算为基座法兰目标，再发`@` |
| 七轴反馈修正 | 参与状态估计与规划 | 用于显示/监督，不注入PC七轴补偿 |
| 后续固定TCP移轨 | 支持该专用模式 | 禁用，提示需上位机后端 |
| 用途 | 七轴协同及新算法能力 | 保留已测试路径、调试与对照 |

切换规则：

1. 任务开始时冻结所选后端；只有任务结束、设备确认空闲且本机发送/回执队列已收敛时允许切换。运动中不直接改一个布尔变量继续发另一种命令。
2. 切换取消未执行的预览/规划任务，更新会话代次；重新读取实际七轴状态并确认工具及坐标参考。操作本身不自动使能或发送运动。
3. 保持界面中的世界TCP目标语义，两个后端共用工具变换。主控后端使用本次会话固定地轨参考：`T_base_flange = inverse(T_world_base(r_anchor)) * T_world_tcp * inverse(T_flange_tcp)`。不直接把世界TCP六个数当作主控法兰坐标发送。
4. 主控后端保留现有模式/示教/手柄受理流程；上位机后端使用第8节的INT轨迹执行器。模式条件不满足时显示所需状态，不暗中在运动中切换。
