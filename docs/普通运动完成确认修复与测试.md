# 普通运动完成确认修复与测试（2026-10-06）

## 1. 授权、现象和范围

用户15:22～15:27复测没有再次出现保护查询超时，HOME/RESET、STOP/START多轮可完成，但HOME后RESET偶尔同秒返回。随后授权“可以，先修复普通运动的完成确认”。本轮已完成代码修改、五目标编译和离线检查，未烧录、未commit，实机结果待用户复测。START每次串行下发范围/查询/使能导致的一到两秒耗时留待后续，不作为本轮优化项。

修复针对普通位置运动完成确认，保留STOP、堵转回退和CALIBRATION内部动作各自的判稳流程。J8不参与整机完成判定。没有新增上位机指令或回执格式，因此不修改两个串口助手；尤其未修改禁止修改的`串口助手.py`。没有修改EEPROM结构、PID、速度/加速度或堵转参数。

## 2. 已确认原因

1. 主控原`PlanMoveJ`只清空汇总FINISH，没有清各节点的旧FINISH；任意普通回包的`UpdateJointAnglesCallback`会从缓存重新填满七轴完成标志。
2. 原`IsMoving`只看七轴FINISH，没有核验本次目标、新反馈或实际位置误差。HOME/RESET的等待可能提前退出。
3. 电机原普通位置FINISH只判断`softPosition==goalPosition && softVelocity==0`，代表规划完成，不代表编码器实际到位。
4. `0x07`接收后立即回复，而状态在20kHz更新；新目标的第一条回包可能携带旧FINISH。主控每5ms重发目标，所以不能在每次收到同目标时重置判稳。
5. 电机普通0x23未发送样本会合并。新完成查询的回复若走该路径，也可能被普通位置样本覆盖。

这些路径均由当前源码核实；日志与提前完成路径吻合，但没有实机中断时间线，不能断言每次秒回都发生在同一个竞争点。

## 3. 最终完成判据

### 电机本地普通位置 FINISH

同时满足以下条件，才进入独立的实际停稳检查：处于普通位置模式且请求模式一致，编码器有效，未失能/制动/故障/保护锁定，规划位置已到目标且规划速度为零，实际编码器位置在本节点容差内。

| 节点 | 实际位置误差上限 | 内部单位（51200/电机圈） |
|---|---|---:|
| J1～J5 | 约0.1°，减速比50 | 711 |
| J6 | 约0.1°，减速比30 | 426 |
| J7 | 0.1mm，5mm/电机圈 | 1024 |
| J8 | 不参与整机确认，普通位置模式使用细容差 | 51 |

符合到位条件后，连续采集1000个20kHz样本，即50ms：实际位置峰峰值≤8内部单位，估计速度的有符号均值取绝对值≤0.01电机r/s。该窗口独立于STOP和内部保护窗口。任一资格条件失效、位置范围超限或窗口末速度均值超限，撤销完成并清整个计时；不累计间歇条件，不以超时冒充成功。完成后继续检查后续窗口和位置资格条件。

新目标改变时立即清本地完成窗口并撤销旧FINISH；重复发送同一个目标不清窗口。J6按节点ID区分减速比，无需分出另一份35电机固件。该位置容差为本次普通完成的编译常量，不借用用户可配置的回退到位容差，不写EEPROM。

### 主控整机完成

新位置目标发布时，增加目标代次，清七轴旧确认及旧查询编号，各节点先标为RUNNING。主控采用当前50Hz查询节奏逐轴查询，每轴约140ms一轮，不另外增加查询频率。

只有本次目标代次发出的查询、匹配非零nonce的回复才可改变完成标志。电机须证明当前收到的目标与查询中的目标相同、已使能且为有效普通位置控制，再报告实际停稳。主控还独立核验实际位置误差；允许一个内部单位用于浮点目标量化，电机的实际误差约束保持上述表值。

确认/回复最大有效期300ms；重复旧回复不能刷新时效。新匹配回复若目标不就绪、未稳或编码器无效，立即撤销该轴确认。无效编码器反馈不污染已有可用位置缓存。必须J1～J7全部有新鲜完成确认，才能退出普通等待；J8不计入位图。

已在同一目标且保持稳定时，再发送相同目标可以较快完成：仍须新的查询确认，不强制制造运动或延迟。HOME与RESET的J2/J3目标不同，因此它们的连续切换不能利用旧FINISH立即完成。

## 4. CAN格式与发送

复用`(nodeID<<7)|0x23`，DLC=8，不增加独立运动命令或解锁入口：

| 字节 | 扩展完成查询 | 扩展完成回复 |
|---|---|---|
| 0～3 | 期望目标，float，带方向的电机圈数 | 编码器实际位置，float，电机圈数 |
| 4 | 0xA5标记 | 0x80标记，bit1=本目标可用，bit0=实际停稳 |
| 5～7 | 24bit非零查询nonce | 回显该nonce |

旧0x07的即时位置回包及普通0x23回包保留布尔FINISH格式，没有0x80标记，不能代替本次完成证明。普通查询使用清零的局部帧，避免误带扩展标记。目标/回复快照在必要处使用短临界区，跨任务/CAN回调的主控状态使用volatile。

完成查询沿用主控普通查询的有界1ms等待；不使用紧跟0x07后的零等待发送，避免查询饥饿。发送尝试不等于成功确认，只有匹配回复才算证明；查询/回复丢失时继续轮询，旧确认过期后继续等待。

电机带0x80标记的0x23回复进入已有可靠发送队列，使用TXOK才出队、ALST/TERR有界错相重试的规则。合并时区分nonce，不能被无标记的普通位置样本覆盖，也不改写在途帧。保护回复的16次尝试/100ms上限保持不变，未增加第二套重试机制。

## 5. 命令语义、取消与修改文件

- HOME目标为`{0,0,90,0,0,0}`、地轨0；RESET目标为`{0,-75,180,0,0,0}`、地轨0。成功规划后等待七轴新的实际完成确认，才分别输出`Home ok`/`Reset ok`。
- HOME/RESET和等待式SEQ/TRJ目标规划失败时输出`error motion plan failed`，不返回成功；目标含NaN/Inf会拒绝。SEQ/TRJ的MoveL也补齐相同等待，原先该分支规划后直接返回ok。
- STOP、DISABLE、被新系统命令替换或目标代次取消后，旧HOME/RESET/等待式命令不再输出成功。原有STOP/保护锁定和START清队列、保持当前位置的语义不变。
- INT模式原本的即时`ok`仍表示接受/处理新指令，不改为等待到位；其`IsMoving`和七轴显示使用新确认。TUN等非普通点位模式不使用旧点位目标的整机确认门禁。

## 8. 用户烧录后的测试顺序

1. 连接主控USB串口，`!START`至`Started ok`。START耗时本轮未优化，不以它评价完成确认修复。
2. `!HOME`至`Home ok`，检查J2约0°、J3约90°、地轨约0；紧接`!RESET`，必须待J2约-75°、J3约180°、地轨约0并停稳后才收到`Reset ok`。往返至少10轮，重点观察以前秒回的位置。已在同一目标再次发送该命令允许较快完成。
3. 在RESET姿态测试地轨：SEQ模式发送`>0,-75,180,0,0,0,20,10`，检查地轨实际约20mm后才完成；再发送`>0,-75,180,0,0,0,0,10`回0。J8状态不应影响这两条七轴完成。
4. HOME运动中STOP：先`Stopping ok`后`STOP locked`，被取消的HOME不能随后报成功；START后保持停点，不恢复旧HOME目标。另一次HOME运动中DISABLE，等待`Disabled ok`，也不能随后报HOME成功。
5. HOME尚未完成时发送RESET：旧HOME取消，不补发`Home ok`；新RESET只在自己的目标实际完成后报告成功。最后复测原SEQ顺序点位执行，下一条应等前一条新完成确认。
6. 如果显示目标附近但长时间pending，请保留完整串口日志、七轴OLED角度和命令时序，停止该轮测试后定位；不要通过放宽堵转参数、触碰承重关节或超时强行报成功来掩盖完成判据问题。
