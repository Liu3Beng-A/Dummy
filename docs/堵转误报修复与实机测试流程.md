## 2. 已确认问题及修复

用户附件中7次异常均为 `NODE_OFFLINE_OR_RESTART`，没有 `reason=STALL` 的机械检测事件。原主控把保护探针超过1秒未更新与缓存范围无效统一打印为STALL：即使J7没有运动，也可能进入该路径。因此，日志不能证明7次都是机械堵转，更不能仅据此断言节点真实掉线或重启。

| 已确认代码问题 | 本轮处理 |
| --- | --- |
| START范围下发可能消耗接近或超过旧探针1秒预算，使能后立即检查旧时间 | 范围COMMIT全部完成后再次查询八节点，核验新位置/坐标版本/范围，然后执行既有使能保持握手 |
| 查询flags与健康判断读取的EVENT flags不是同一快照 | 新增0x36原子查询回复；健康判断只使用匹配探针的快照 |
| 普通位置回包不计在线，查询入邮箱成功后缺少充分重试 | 分开记录节点通信时间和有效保护快照时间；同编号探针重试，有界超时仍保护 |
| 八节点续约约320ms；入邮箱后丢一帧可能640ms，超过本地500ms租约 | 续约绑定task/version及非零nonce，电机刷新租约后确认；正常按80ms到期调度，待确认20ms重试，轮转避免低ID独占 |
| 校准等待/完成节点也占续约资源 | 校准只向当前J7或J8内部动作节点续约；普通保护中等待授权的节点仍续约 |
| 重复事件产生重复阶段行，校准失败也误打印普通STALL | 重复状态仍确认，但只在事件/阶段/原因变化时打印；通信保护用PROTECT、校准用CAL、机械事件用STALL |

主控通信超时仍为1000ms，电机内部动作租约仍为500ms。没有用无限宽限或假成功掩盖真实断线。STOP优先于内部续约和其他保护发送；回退期间START、STOP、DISABLE的既定语义不变。

两端CAN自动重传仍关闭，本轮通过保护业务的确认和重试处理可重试帧，避免全局重传迟到的普通运动目标。HAL入邮箱成功仍不能证明总线成功；新增ALST/TERR诊断计数用于实机核查。

## 3. 协议与参数决策

必须配套更新主控和全部八节点，包括J8。虽然J8排除普通堵转检测，但START查询和校准续约使用新协议。混用旧固件不在本轮兼容范围。

- CAN StdId仍为 `(nodeID << 7) | cmdCode`；旧0x0A动作数值不改。
- QUERY使用0x34/op=0，回复0x36：`coordinateVersion[0], flags[1], probe u16[2..3], actual motor-r float32[4..7]`，小端，8字节。未确认的有效保护事件另外重发；空闲查询不再额外发送EVENT。
- RENEW使用0x34/op=7，末4字节为非零nonce。有效task/version才刷新租约并回复0x35：`0x40[0], currentVersion[1], task u16[2..3], nonce u32[4..7]`。该确认不代表回退完成或解锁；旧确认、错task/version不会推进动作。
- EEPROM结构版本保持1，已有合法参数继续加载，烧录不会自动覆盖用户设置。需要查询后显式SET；SAVE仍要求真实失能。

普通检测仍要求运动意图成立，且电流命令高、实际速度低、跟随误差大三条件连续成立。任一条件失效即清候选计时；参数/模式切换等复位规则沿既有实现。`focCurrent`是控制器输出命令，不是实测电流。

| 参数 | 本轮新默认值 | 单位及范围 |
| --- | --- | --- |
| CURRENT_A | 初始化时有效电流上限×0.9；2.5A时2.25A | 电流命令A，0.1～有效上限 |
| SPEED_RPS | 0.02，不变 | 电机轴r/s，0.001～0.2 |
| ERROR_R：J1～J5 | 0.06944444，对应关节0.5° | 电机圈，0.0002～1 |
| ERROR_R：J6 | 0.04166667，对应关节0.5° | 同上，减速比30 |

| TRIGGER_MS | 300 | 连续时间ms，20～2000 |
| STARTUP_MS | 200 | 启动豁免ms，0～500 |

电流/速度滤波10/20ms不变；回退5°/5mm、减速箱前电机轴速度3/0.5r/s、加速度上限5r/s²、超时5秒不变。普通回退和保持电流仍受既有电流上限约束。J6按nodeID使用自身减速比，无需拆分35固件。校准接触参数仍独立，未随普通阈值调整。后续显式改变电流上限时，既有阈值约束逻辑仍生效，不能把所有用户配置都称为固定90%。

## 7. 实机测试顺序

### 7.1 先确认失能与实际参数

使用新版 `串口助手_old.py`，COM20为主控USB虚拟串口，115200。发送 `!DISABLE`，等到 `Disabled ok`；pending只表示请求已接收。查询 `#GETI 0` 和 `#STALL_GET 0`，保留完整结果。每项作业完成再发下一项，ALL保护查询以J7最后一项 `DIRECTION_MASK` 回复为结束；`#STALL_GET 8`应为EXCLUDED。

若EEPROM还是旧阈值，在失能确认后逐条设置。下面CURRENT示例只适用于各轴有效上限都已确认为2.5A；上限不同则分别设置各节点的0.9倍，不改变电流上限本身。

```text
#STALL_SET 0 CURRENT_A 2.25
#STALL_SET 0 SPEED_RPS 0.02
#STALL_SET 0 TRIGGER_MS 300
#STALL_SET 0 STARTUP_MS 200
#STALL_SET 1 ERROR_R 0.06944444
#STALL_SET 2 ERROR_R 0.06944444
#STALL_SET 3 ERROR_R 0.06944444
#STALL_SET 4 ERROR_R 0.06944444
#STALL_SET 5 ERROR_R 0.06944444
#STALL_SET 6 ERROR_R 0.04166667
#STALL_SET 7 ERROR_R 0.1
```

**逐条发送、逐条等成功，不要一次粘贴连续发送。** ALL SET须等 `ok STALL_SET [7] ...`；单轴等该轴成功。随后再GET核对。首次可只在RAM测试；确认合适后失能并发送 `#STALL_SAVE 0`，等各轴保存成功。若出现部分应用/失败掩码，先处理该错误，不直接进入运动测试。

同时核对ENABLE、BACK_DEG/BACK_MM、BACK_RPS、BACK_TIMEOUT_MS；应为J1～J6回退5°、J7回退5mm、速度3/0.5电机r/s及5000ms。保存后重启再次GET，验证实际参数确实保留。

### 7.2 静止和启停重复测试

1. `!START`，等待 `Started ok`，保持静止2～3分钟。J7不动也应维持正常，不出现无原因STALL/PROTECT；位置持续刷新。
2. 支撑机械臂，做约10轮START/DISABLE，每次等最终ok再发送下一条。允许短暂pending；不能只有pending而无最终结果。
3. 确认上电坐标和真实姿态一致、运动空间可用，再 `!HOME`，等待 `Home ok`。当前HOME目标是 `{0,0,90,0,0,0}`、地轨0，并不是REST姿态。

### 7.3 重点复现“J7没动也报警”

从已完成HOME的位置做20轮小幅低速往返，每次实际到位再发下一条，J7目标始终0。例如：

```text
>10,0,90,10,10,10,0,10
>0,0,90,0,0,0,0,10
```

末位10是速度档位，对应电机轴最高3r/s；使用前确认这些小幅目标适合实际工作空间。然后保持六轴HOME不变，单测地轨0→10mm→0，仍用低速档位。观察有无新的PROTECT及对应诊断；不要仅凭OLED有角度就认定保护状态回复正常。

### 7.4 STOP与旧目标清除

运动中发送 `!STOP`，应见 `Stopping ok`、随后 `STOP locked`；J1～J7减速后保持固定停点，J8排除普通STOP。减速中发送START应pending，停稳后使能保持当前点，不继续旧目标。另测STOP锁定后DISABLE，八节点全部失能。锁定时点击其他运动命令产生STOP锁定警告属于正常门禁。

### 7.5 真正堵转与自动回退

先选低负载轴、中间行程及低速短距离运动，用受控限力阻挡验证，不用手接近运动夹点。建议先J4，再远离物理端点的J7；承重轴保持可靠支撑。

期望：满足本次设置的三条件连续300ms，电机本地保护并报告STALL；其他J1～J7联动软停；触发轴反向退离，关节最多5°、地轨最多5mm，受实际范围截短。完成依据实际编码器到位和STOP稳定窗，随后锁定保持；不会恢复旧目标。夹爪正常夹持不产生普通全机堵转事件。

分别测回退中提前START和回退后START：提前START应挂起，仅全部回退成功后 `Started ok`，保持新停点；失败则清挂起，不自动使能。解锁后发送新的短距离目标，确认没有残留队列继续冲向旧堵转点。

### 7.6 打断与失败

- 回退中STOP：取消内部回退、软停并保持锁定；需要新的START或DISABLE。
- 回退中DISABLE：立即走八节点失能，不等待回退完成；提前支撑承重关节。
- 受控再次阻碍或回退空间不足：应明确失败原因，例如REBLOCKED、NO_SPACE、RETREAT_TIMEOUT，5秒回退超时不能伪报成功。失败保持保护锁并清提前START。
- 通信故障测试仅在支撑/无负载台架进行：丢失节点通信应报NODE_UNRESPONSIVE；普通位置仍回但有效保护快照丢失应报PROTECTION_STATUS_TIMEOUT。健康同伴软停，不猜测方向回退；恢复后用新START复核。缺节点时DISABLE等待实际确认是正确行为，不应伪报全部失能。

### 7.7 校准只作为共享通信复测

先完成上述堵转测试，再按原方案支撑并失能，执行CALIBRATION观察共享续约。J8先寻端/返回100，J7后寻正端/返回0，全部结束失能保存才校准ok。J7从中心以0.5电机r/s去返约200秒，不能拿普通5秒回退超时判断校准失败。

重点观察J8是否还出现LEASE_TIMEOUT、是否只在阶段变化时打印，以及校准/保存期间START是否busy且不会结束后自动使能。STOP或DISABLE取消不报校准成功，不继续保存未完成流程。本轮没有据此保证其他校准问题已经修复。

## 8. 日志解读与复测反馈

| 回复 | 含义 |
| --- | --- |
| STALL阶段，reason=STALL | 电机机械堵转检测事件，再看回退及终态 |
| PROTECT ... NODE_UNRESPONSIVE | 节点通信超过1秒未到；不等于已证明节点重启 |
| PROTECT ... PROTECTION_STATUS_TIMEOUT | 有效匹配保护快照超过1秒未到，普通位置可能仍正常 |
| PROTECT ... PROFILE_INVALID / COORDINATE_CHANGED | 当前保护范围无效或坐标版本与提交范围不一致 |
| PROTECT ... NO_VALID_ENCODER | 当前快照不具备有效有限编码器反馈 |
| PROTECT ... queued/rx/retry | 查询入邮箱成功数、有效回复数、重试数；queued不代表总线成功 |
| PROTECT CAN alst/terr/full | 仲裁丢失、发送错误、接收FIFO满回调累计计数 |
| STOP锁定警告 | 锁定期间其他运动命令被丢弃，属于正常行为 |

异常保留从连接、参数查询、START到故障后的完整日志，以及轴是否实际运动、堵转/回退/校准阶段。USB ClearCommError只记录前后状态，不能把它直接归为堵转阈值问题。实机通过的最低依据是静止/J7固定/重复启停无误触发，真实堵转会退离并保持，STOP/DISABLE能打断，解锁不恢复旧目标；离线测试不能代替这些结果。

## 9. 第二轮：持续运动仲裁修复与本次复测

### 9.1 用户日志与根因边界

14:40～14:46 HOME/RESET反复触发J2/J3 `PROTECTION_STATUS_TIMEOUT`，其最近通信仅4/10ms，保护探针为1005ms，flags=07。电机仍在回包，缺的是本次有效保护快照，不是电流/速度/误差三条件的机械STALL；不回退符合原通信保护设计。J1 CURRENT=1.8A/上限2A、J2 CURRENT=1.35A/上限1.5A及300/200ms等参数已生效，不能拿统一2.25A覆盖这些不同上限。

电机原`CAN_PollTransmit()`在HAL入邮箱成功就出队，随后ALST/TERR没有保留原回复。主控固定控制周期的查询重试不能保证逃离持续重复的运动仲裁；主控累计ALST支持发送竞争方向，但不能证明每次究竟丢在请求端还是回复端。本轮直接修复已确认的电机回包缺口，不靠提高阈值或放宽保护看门狗。

### 9.2 发送决策

- 保护回复0x0A/0x0B/0x32/0x35/0x36进入独立12槽环形队列（有效容量11），优先于普通反馈。HAL入邮箱只标记在途，TXOK完成回调才移除；错误/普通abort保留帧，按节点与尝试次数做1～4ms退避，再发送。
- 每帧最多16次发送尝试（含首次），或入队后100ms到期，先达到者结束重试。到期在途帧请求有界abort，不伪造成功；主控业务重试仍负责下一次新查询。保存回复、事件和续约仍依靠已有幂等/重发协议，不新增解锁入口。
- 只合并未发送的可替代快照。不同参数/事务/配置操作的0x32回复独立；0x35续约ACK与动作完成上下文不能互相覆盖；在途帧不改写。普通0x23未发送旧样本被最新反馈替代，避免反馈积压挤掉保护回复。
- 电机只保留一个受跟踪的硬件在途发送，等实际complete/error/abort处理后才复用邮箱，避免硬件已经空闲但旧RQCP中断未处理时，把旧回调误认为新保护帧成功。所有回调均短时处理，无阻塞等待、打印或Flash写入。普通反馈仍为尽力发送，不重放运动命令。
- 主控查询时隙及1秒健康预算保持；本地保护租约500ms保持；两端自动重传保持关闭。软件重试发生在电机主循环，独立于主控5ms周期。本轮未修改阈值、回退距离/速度、校准动作或GUI。

### 9.3 新回归证据

实际生产电机CAN队列/结果回调代码，配合硬件邮箱替身及125μs总线时隙模型，覆盖三邮箱、五类保护回复、ALST/TERR、HAL忙、未处理RQCP、到期abort、计时回绕、独立事务/续约ACK、队列满和普通反馈合并。构造每5ms前2ms持续低ID运动帧、每160ms保护查询固定撞相：基线八种nodeID均3秒内0条保护回复；新版各19条，探针最大年龄160ms。仲裁计数仍可能增长，验收条件是有效回复和保护行为，不能要求ALST归零。

模型验证的是该持续碰撞路径，不能代替真实CAN波形和电机负载。若实机仍超时，应保留PROTECT分项日志继续区分请求未达、回复丢失或其它接收问题；不会把本轮通过模型测试写成实机成功。
