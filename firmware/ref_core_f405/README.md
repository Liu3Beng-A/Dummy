> 基于 STM32F4 架构的六自由度 (6-DOF) 伺服机械臂下位机控制核心。
> 结合 FreeRTOS 实时调度与硬件 CAN 总线，实现了高频低延迟的运动学解算与轨迹跟踪，并支持末端执行器（夹爪）的联动控制。

## 核心特性

* **实时运动学引擎**：基于 D-H 矩阵法的内置正/逆向运动学解算 (`DOF6Kinematic`)，直接驱动末端位姿 (XYZ+ABC) 转换。
* **高频低延迟控制环**：主心跳通过 `TIM7` 维持 `5kHz` 定时器硬件中断挂载，结合分频机制 (`100Hz`/`50Hz`)，充分压榨 CPU 资源同时杜绝 CAN 拥堵死锁。
* **多态运动规划**：
  * **顺序/打断模式**：平滑阶跃式点位移动 (`MoveJ`, `MoveL`)。
  * **高频透传伺服模式** (`ServoJ`)：专为外置轨迹规划器(如 ROS/上位机)优化的微秒级时钟插补系统。
  * **粗暴力矩透传控制**：关闭位置环，实现柔顺操作或示教拖拽。
* **硬件级状态监测**：整合 I2C 驱动的 MPU6050 姿态传感器监测基座倾覆；集成 U8g2 库的 128x64 OLED 状态面板；以及基于 PWM 映射的底盘 RGB 灯环互动反馈。
* **断电安全与参数驻留**：内嵌 EEPROM 模拟记录器，能够持久化保留 RGB 偏好设置及各关节物理加速度安全限制参数。

## 系统架构

### 硬件拓扑
* **MCU 主控**：STM32F4 平台
* **通讯协议**：USB CDC (虚拟串口) / UART (预留) / CAN 2.0 (总线)
* **执行单元**：6个闭环步进伺服关节 (`CtrlStepMotor`) + 1个末端开合夹爪系统 (`StepHand`)

### 软件实时任务流 (FreeRTOS)
| 任务名称 (Task) | 优先级 | 挂载周期 | 职能描述 |
| :--- | :---: | :--- | :--- |
| `ControlLoopFixUpdate` | **Realtime** | 5kHz (分频) | 闭环核心、伺服解算、总线数据收发。由 TIM7 强中断唤醒。 |
| `ControlLoopUpdate` | Normal | 异步阻塞 | 命令栈处理工厂，隔离高耗时的 ASCII 字符串模式匹配动作。 |
| `OledTask` | Normal | ~50Hz | I2C 轮询外设、采集机器空间数据、渲染界面UI像素。 |
| `RGBTask` | Normal | ~30Hz | 处理环境氛围灯效渲染与机器状态流转灯语通知。 |

## 编译与部署

### 1. 环境准备
* **CMake** (v3.20+)
* **GNU Arm Embedded Toolchain** (如 `arm-none-eabi-gcc` 10.3+)
* **OpenOCD** 或 **J-Link** / **ST-Link** 烧录工具

### 2. 生成与编译 (命令行)
进入工程根目录执行：
```bash
# 生成 Ninja 或 Make 构建文件 (以您的构建系统为准)
cmake -B build -G "Ninja"

# 执行编译
cmake --build build
```
编译成功后，将在 `build/` 目录下生成 `Core-STM32F4-fw.elf / .hex / .bin` 等文件。

### 3. 烧录
可通过 J-Flash、STM32CubeProgrammer 或 OpenOCD 将 `Core-STM32F4-fw.hex` 写入 MCU 主控。

## 快速开始

1. **硬件上电**：接通系统 12V 主供电及主控逻辑电源，观察主控板 OLED 是否正常亮起并显示 FPS 与当前角度数据。
2. **握手通讯**：通过 Type-C 数据线连接主控与 PC，打开配套的 `串口助手.py` 或任意终端调试工具，波特率设置 `115200`（USB CDC 下波特率通常无关紧要）。
3. **安全使能**：出厂默认设备为上电锁定状态（保护人员安全），必须通过指令主动使能：
   ```text
   发送: !START
   ```
   机械臂底座 RGB 切换至使能工作色，系统正式接管电机偏置锁定。
4. **进行测试运动**：
   ```text
   发送: >0,0,90,0,0,0,30  (Hone位，速度限幅 30)
   ```

## 串行指令集规范 (ASCII)

固件内置了高速轻量的 ASCII 解释器，全部指令必须以纯文本形式发送（无需额外换行符截断处理，依靠特定首字符定界，但推荐附带 `\n` 以便调试）。

### 系统状态控制 (`!`)
| 指令 | 作用 | 示例 |
| :--- | :--- | :--- |
| `!START` | 使能机械臂 (激活电机闭环) | `!START` |
| `!DISABLE` | 卸载机械臂 (下线电机进入示教拖拽) | `!DISABLE` |
| `!STOP` | 紧急制动保护 (清除历史堆栈并原位锁死) | `!STOP` |
| `!HOME` | 进入安全的低位默认归零点 | `!HOME` |
| `!RESET` | 返回休息平躺的收纳姿态 | `!RESET` |

### 夹爪控制器
| 指令 | 作用 | 示例 |
| :--- | :--- | :--- |
| `!HAND_EN` / `!HAND_DIS`| 激活/关闭 夹爪供电使能 | `!HAND_EN` |
| `!HAND_POS <0-100>` | 位置环闭合 (0张开, 100夹紧) | `!HAND_POS 50` |
| `!HAND_I <0-2.0>` | 设定电流(力度)限幅 | `!HAND_I 1.5` |
| `!HAND_O` / `!HAND_C` | 力矩模式下控制持续张开或闭合 | `!HAND_O` |

### 运动规划通道
*注意: 执行空间运动或关节运动前必须处于使能状态。*

* **`>j1,j2,j3,j4,j5,j6[,speed]`** 
  * 描述：关节绝对角度(°)映射移动。
  * 示例：`>45.0,-20.5,10,0,0,0,50` （前六个参数为角度，最后一个可选参数为运行速度 `0-100`）。
* **`@x,y,z,a,b,c[,speed]`**
  * 描述：笛卡尔坐标直线空间插补移动。`x/y/z` 单位为毫米(mm)，`a/b/c` 为欧拉角(°)。
  * 示例：`@200.5,0,150,0,90,0,60`
* **`$c1,c2,c3,c4,c5,c6`**
  * 描述：直接六轴力矩(电流)透传，专供柔顺交互使用。单位(安培 A)。
  * 示例：`$0.5,0.5,0,0,0,0`

### 环境外设配置 (`#`)
| 指令 | 作用 | 示例 |
| :--- | :--- | :--- |
| `#CMDMODE <1-6>` | 切换底层调度工作流（1=串行，3=圆滑连续，6=高频伺服） | `#CMDMODE 1` |
| `#ACC_BASE_J <节点ID> <加速基准>` | 写入底限保护加速度到 EEPROM (1.0~2000.0) | `#ACC_BASE_J 1 150` |
| `#OFFSET_J <节点ID>` | 标定指令：以当前物理位置覆写为零点 | `#OFFSET_J 2` |

## 调试与故障排查

**Q: 启动后 OLED 数据不刷新，系统无响应？**
* **A**: 请检查 I2C 线路。固件主函数中会在开机检查 MPU6050 陀螺仪的通讯回响。若底板 I2C (SDA/SCL) 上拉丢失或接线脱落会导致内部堵塞，请查看底板焊接并复位系统。

**Q: 机械臂处于 `!START` 状态，发送位移指令后完全不动？**
* **A**: 
  1. 确认控制模式。如果意外陷入了 `COMMAND_TORQUE_CONTROL`(力控)，需发送 `#CMDMODE 1` 恢复常规点位控制。
  2. 请检查 CAN 链路终端电阻 (120Ω) 是否齐备。若没有收到 CAN 发出的反馈数据包，主控会判定 “未抵达目标点”，进而引发运动任务列队卡死。

**Q: 机器人在高频上位机随动时有抖动异响？**
* **A**: 需将内部调度模式切入 Servo 伺服模式（发送 `#CMDMODE 6`）。该模式使用 `micros()` 级高精时间分片解算前馈速度，能够有效消除梯形加减速规划器在微小步长指令下产生的阶跃顿挫感。
